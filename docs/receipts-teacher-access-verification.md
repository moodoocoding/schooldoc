# 영수증 일반 교사 접근 검증

## 범위

2026-10-05 사용자 요청으로 관리자 전용 미리보기를 종료한다. 홈 카드 → 로그인 → 개인 장부 → 등록·검토 → 정산 → Excel/PDF 흐름을 모든 로그인 교사에게 연다. 학생용 공개 링크나 익명 AI API를 추가하는 변경이 아니다.

- 프런트엔드는 사용자 ID가 있고 익명 계정이 아닐 때만 장부 화면을 연다. 로그인 확인 중·로그아웃 상태는 입력과 저장소 화면을 열지 않는다.
- 서버는 `auth.getUser`의 검증된 사용자 ID로 인증하고 기존 요청·파일·사용량 제한을 적용한다. 클라이언트 역할·요청 본문의 소유자 ID는 권한 근거가 아니다. 기존 운영 `verify_jwt=true`를 유지한다.
- 장부·초안은 계정별 localStorage, 원본은 계정·장부별 IndexedDB다. 서버 장부 DB나 동기화를 새로 만들지 않으며, 로컬 저장소 분리를 서버 RLS 검증이라고 표현하지 않는다.
- 기존 다른 기능의 서버 소유자 검사·RLS는 변경하지 않는다. 금액 누락과 사진 PDF 분할 등 별도 수정은 이 변경에 섞지 않는다.

인증 대역은 관리자 역할 없는 교사다. 가상 자료만 사용하며 실제 OpenAI를 호출하지 않는다. 홈 클릭·직접 URL·장부 생성·외부 전송 동의·등록/모의 분석·수기 보완·장부 반영·정산·Excel/PDF 다운로드·새로고침·계정 전환·로그아웃·익명 계정 거부·로그인 확인 중 차단을 검증했다. 원본의 다른 계정/장부 키 조회는 실패하고 본인 키는 보존된다. 형식·인증·한도 실패 시 외부 AI를 호출하지 않는 서버 경계는 실제 처리기의 단위 검사다.

## 디자인·React 모의 검토

세 디자인 프로파일을 구현 전에 읽었다. 다음 평가는 AI의 모의 검토이며 실제 전문가·교사 인터뷰나 사용성 시험이 아니다.

| 관점 | 구현 전 판단 | 구현 후 근거·남은 위험 |
| --- | --- | --- |
| 웹디자인 | 수정 필요: 일반 교사에게 완성된 도구가 개발 중으로 보임 | 통과: 홈의 기존 카드 위계·밀도 유지, 관리자 배지 제거. PC/390px 전체 화면에서 빈 장부와 반영 후 정산 상태 확인. 긴 자료의 기존 레이아웃은 회귀 검사 범위로 한정. |
| UX | 수정 필요: 직접 URL도 관리자 제한으로 막히며 로그인해도 해결되지 않음 | 통과: 홈/직접 URL에 동일 기준 적용, 로그아웃은 Google 로그인 안내와 원래 주소 복귀. 등록/정산·수기 복구·계정 전환 유지. 실제 Google 인증·운영 일반 교사 API 성공은 별도 원격 검사가 필요. |
| UI | 수정 필요: 잠긴 기능의 개발 중 표기가 실제 로그인 상태와 불일치 | 통과: 로그인 확인 중·로그아웃·정산 상태를 문구로 구분. axe 위반 0·문서 가로 넘침 1px 이하, 44px 로그인 버튼. 1차 전체 캡처에서 로그인/홈 버튼이 붙어 보여 간격과 줄바꿈을 보완한 2차 코드로 재검증. |

새 관리 화면이나 큰 화면 재설계가 아니라 기존 카드·접근 안내의 제한된 수정이므로 여섯 독립 관점 평가를 형식적으로 만들지 않았다. React 검토에서 파생 접근 조건을 렌더링 시 계산하고 계정 ID로 workspace를 새로 마운트해 이전 계정 초안·진행 요청을 분리한다. AI 분석·PDF/Excel의 지연 로딩과 취소·정리 흐름은 유지한다.

전체 캡처와 내려받은 가상 출력 증거는 로컬 전용 `test-results/receipts-all-teachers-20261005/`에 있다. 브라우저 스킬의 `agent-browser` 실행 도구가 없어 프로젝트 Playwright의 Chrome으로 대체했다.

## 원격 확인과 배포

- 현재 운영 `receipt-analyze`: 버전 1, ACTIVE, JWT 검증 true 확인. 아직 변경 함수를 배포한 것으로 기록하지 않는다.
- 운영 가상 시험 계정 2개 생성/검사/삭제는 자동 안전 검토에서 별도 사용자 승인이 필요하다고 차단됐다. 승인 전에는 실행하지 않는다. 외부 영수증 전송·OpenAI 호출 없는 권한 검사다.
- 계정과 자료를 변경하지 않는 운영 검사에서 인증 헤더 없는 요청·위조 토큰은 각각 401로 거부됐다. 일반 교사 성공 검증을 대신하는 근거는 아니다.
- Vercel 연결에서 프로젝트 목록은 확인했으나 프로젝트 상세 조회는 팀 scope 권한 부족으로 403을 받았다. 이를 배포 실패나 성공으로 단정하지 않는다.
- GitHub·main·함수·프런트엔드 적용 상태는 후속 실제 확인 결과로 갱신한다. DB와 secrets 변경은 해당 없음이다.
