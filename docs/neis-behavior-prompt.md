# 행동특성 작성 프롬프트와 2026 기재요령 반영

## 실제 요청

실행 프롬프트 전문은 [prompts.ts](../supabase/functions/neis-behavior/prompts.ts)의 `behaviorInstruction`이다. 사용자 원문의 역할·목적·입력 우선순위·다양성·문체·분량·최종 점검을 섹션별로 유지한다. 공통 지침은 학급 요청에 한 번만 보내며 학생마다 반복하지 않는다.

[행동특성 전용 작성 지침과 일반 사용자 입력 전문](neis-behavior-request-prompts.md)은 실제 요청 생성 함수로 만든 400자·메모 없는 가상 학생 예시이다. 행동특성 전용 `instructions`와 일반 영역의 `input[0].content[0].text`를 구분한다. '시스템 프롬프트'는 Neis Helper 공통 지침만 뜻한다. 일반 영역은 별도의 장문 지시문이 아니라 학생 특성·메모·분량·중복 비교 자료 JSON이다.

- 최초 요청: 최대 60명의 익명 식별자, 선택한 특성, 교사 메모, 목표 분량을 한 요청에 포함한다.
- 응답: `rows: [{id, text}]`. 학생별 완성된 행이 도착하는 즉시 번호순 표의 해당 칸에 넣는다. 이름·출석번호는 브라우저에 남긴다. 메모에 직접 넣은 개인정보까지 자동 익명화된다는 뜻은 아니다.
- 재작성: 선택한 대상만 요청한다. 나머지 학생의 본문을 중복 비교용 `avoid`로 한 번 보내고 대상 학생의 사실로 사용하지 않게 명시한다.
- 자동 추가 호출은 없다. 교사가 중복 또는 미완료 학생만 묶어서 요청한다. 직접 수정한 문장은 자동 재작성 대상에서 제외하고 명시적으로 선택한 경우만 바꾼다.
- 설정된 기존 NEIS 작성 모델과 사용량 제한을 공유한다. `store:false`를 적용하고 원문·응답을 DB나 로그에 저장하지 않는다. 탭 메모리 보관이며 새로고침하면 초기화된다.

## 검증의 범위

규칙 검사는 ID/누락/중복·형식·금지 표현과 선택 분량을 탐지한다. 생성 응답이 분량 범위를 벗어나면 본문을 보존하되 정상 완료로 처리하지 않는다. 교사는 미완료 학생만 묶어 다시 요청하거나 직접 수정할 수 있다. 직접 수정한 본문에는 생성 목표 분량을 강제하지 않는다. 교사 메모의 사실성이나 문장의 교육적 적절성 전체를 자동 보증하지 않는다. 실제 운영 API 확인과 모의 응답 검사는 별도의 검증 기록에 구분한다.


## 2026-11-14 선택 분량과 지시 충돌 수정

기존 '분량보다 사실 보존 우선' 예외가 짧은 메모를 100자 정도로 요약하도록 만들었다. 사용자 요청에 따라 분량을 생략할 수 있는 예외를 제거했다. 생성은 선택 분량과 사실 보존을 동시에 충족해야 한다.

| 충돌하거나 모호했던 지시 | 수정 기준 |
| --- | --- |
| 400자 작성 / 근거가 적으면 분량 생략 | 본문의 공백·문장부호 포함 360~440자. 매 요청에 실제 선택 분량과 범위를 다시 지정. 100자 결과는 정상 완료로 수용하지 않음 |
| 충분히 작성 / 구체적 사건 창작 금지 | 특성에 내포된 태도·수행 방식·관계 방식·성장과 발달은 충분히 설명. 새로운 사건·직책·횟수·시점·타인의 반응·특정 성과 향상·전후 비교는 추가 금지 |
| 학교생활 전반 종합 / 입력된 영역만 서술 | 모든 영역을 채우는 것이 아니라 입력 영역 내 여러 의미 측면을 연결 |
| 표현 반복 절대 금지 / 공통 교육 용어·명사형 필요 | 같거나 유사한 문장·문장 틀을 금지. 공통 교육 용어·종결어미 자체는 허용. 첫 단어·첫 세 글자는 각 학생 본문의 첫 문장 시작 기준 |
| 긍정적 변화 서술 / 변화 기록이 없음 | 발전이 필요한 행동과 실천 방향·가능성으로 설명. 이미 개선되거나 노력했다는 사실은 만들지 않음 |
| 기호 금지 / JSON 출력 | 금지는 학생 본문의 강조·문단 기호에 적용. 마침표·쉼표와 JSON의 구분 기호는 허용 |

교사 메모는 내용의 우선순위이며 길이의 상한이 아니다. 키워드를 문장으로 치환하는 데 그치지 않고 여러 의미 측면을 설명하되, 수식어나 동의어 반복으로 글자 수만 채우지 않는다. 원문 보관 문서는 변경하지 않는다.

실제 운영 표본에서 지시문만으로는 328~356자의 미달 응답이 남아, 응답 JSON의 `text`에도 선택 분량의 정규식 `pattern`을 적용했다. [OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 문자열 패턴 제약을 사용하며, 서버·클라이언트의 글자 수 검사는 별도로 유지한다. 공식 기재 한도와는 관계없는 제품의 생성 목표 범위이다.

400자는 대략 7~8개의 문장으로 서로 다른 의미 측면을 설명하도록 하고, 학생 본문에 덕목의 사전적 정의나 작성 지침 해설이 들어가지 않도록 했다. 발전이 필요한 특성만 입력한 경우에는 없는 장점을 추가하지 않고 필요한 행동·실천 방향·가능성을 설명한다. 운영 4명 표본에서 376·398·375·428자를 확인했으며, 이는 모든 입력의 교육적 적절성과 사실성을 보장한다는 뜻은 아니다.

## 짧은 교사 메모의 변화 판단

후속 사용자 의견에 따라 '실제 전후 변화가 있을 때만'이라는 과도한 조건을 없앴다. '발표에 자신감이 붙음', '다툼이 줄어듦', '혼자 해보려는 태도가 생김' 등 교사의 짧은 변화 판단도 의미를 풀어 서술할 근거로 인정한다. 전후 사례·날짜·수치·별도 관찰 기록을 요구하지 않는다. '연습 중/노력함'은 진행 중인 행동, '연습 필요'는 필요한 방향으로 구분한다. 변화 언급이 없으면 현재 특성과 발전 가능성을 서술하며, 입력에 없는 변화의 시기·계기·정도·횟수는 만들지 않는다.

## 선택한 특성만으로 성장·발달 서술

최신 사용자 요청에 따라 위 단계의 '현재 특성과 발전 가능성' 제한을 확대했다. 메모가 없어도 교사가 선택한 특성 자체를 판단 자료로 보고, 해당 태도·능력을 익히고 기르며 발달시켜 가는 과정을 자연스럽게 서술한다. 예를 들어 끈기에서 '어려운 과제도 쉽게 단념하지 않고 해결 방법을 찾아가는 힘을 기름.'을 쓸 수 있다. 예문 복제나 모든 문장을 성장 어휘로 채우도록 강제하는 지시는 아니다.

구체적인 사건·변화 이력은 별개다. '학기 초에는 포기했으나 최근에는 혼자 해결함', 특정 사건을 겪은 뒤 태도가 바뀜, 횟수·점수가 늘어남 등은 입력 없이 만들지 않는다. 발전이 필요한 특성을 이미 해결된 장점으로 뒤집지도 않는다. 본문 지침뿐 아니라 요청 말미의 분량 지시에서도 포괄적인 '없는 변화 금지'를 '없는 구체적인 사건·실적·전후 비교 금지'로 맞췄다.

## 사용자 수정본 적용

사용자가 재구성한 전용 지침을 적용하고 승인된 두 부분만 조정했다. 첫째, 문장 수·문장당 길이는 작성 가이드로 두고 본문 전체 글자 수 범위를 우선한다. 최종 점검에서도 7~8문장 고정을 제거했다. 둘째, 마지막 요청 분량은 실제 선택한 200/300/400자와 해당 범위로 동적 생성한다. 나머지 사용자 원문은 그대로 보존했다.

Neis Helper 공통 시스템 프롬프트와 교과 지침은 변경하지 않았다. 기존 지침과 수정본의 실제 OpenAI 비교는 [비교 보고서](../design/feature-reviews/2026-11-14-neis-behavior/prompt-comparison/report.md)에, 원문 대비 변경은 [차이 기록](../design/feature-reviews/2026-11-14-neis-behavior/prompt-comparison/user-guidance-adjustments.diff)에 남긴다.
