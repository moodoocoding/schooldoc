# 학교 문서 작성 지침의 구성

현재 작성 화면의 문서 종류는 운영계획서이며 그 안에 8개 운영 유형이 있다.
공통 원칙을 재사용할 수 있게 분리했지만 결과보고서·회의록·안내문 생성기를 추가한 것은 아니다.

## 참고한 방식과 적용 판단

[EduNote의 문서 생성기](https://github.com/codersongpro/edunote/blob/929b1a51ada6c987951c1456552caccd7eff648e/src/renderer/services/geminiService.ts)는
공통 문체·사실성 원칙과 문서 종류별 구성·분량·어조를 조합한다. 로컬 checkout의 해당 커밋에서
`generateDocument`와 공통 작성 상수를 읽고 구성 방식을 비교했다. 코드·프롬프트 문장은 옮기지 않았다.

- 공통 원칙, 문서 장르, 업무 유형, 사용자 조건의 계층을 분리하는 방식을 참고한다.
- SchoolDoc은 유형별 지침뿐 아니라 응답 형식과 실제 출력 목차도 같은 정의로 연결한다.
- 미입력 날짜·장소·인원을 일반적인 값으로 채우지 않는다. 사실은 확인할 자리로 남기고 실행 방법은 제안한다.
- 모델이 글꼴·HTML·번호를 작성하는 대신, 구조화된 내용을 공통 HWPX 출력 계층으로 조판한다.
- 분량을 지시하는 것에 더해 부족한 본문을 검사하고 제한된 보완 요청을 한다.

## 작성 계층

| 계층 | 구현 | 책임 |
| --- | --- | --- |
| 학교 문서 공통 | `writingRules.ts`의 `schoolDocumentSystemInstructions` | 사실·제안 구분, 자료의 지시문 무시, 출처·개인정보, 자연스러운 한국어 |
| 운영계획서 장르 | `operatingPlanInstructions` | 실행 전 계획, 주체·절차·자료·결과 확인, 보고서·안내장과 구분 |
| 8개 운영 유형 | `authoringProfiles.ts` | 유형별 실제 본문 키·목차·필수 내용 |
| 분량 설계 | `composition.ts` | 요약에서 상세 실행안까지 최소 내용·목표 분량·실행 단계 수 |
| 작업 자료 | `openai.ts` | 이번 공문·조건·답변, 비식별 참고 사례와 가상 작성 예문 |
| 검사와 출력 | 서버 검사, `officialDocument` | 근거·예산·내용량, HWPX 본문 보존·조판·실제 쪽 수 안내 |

유형별 본문 키는 실제 목차로 출력한다. 교원 연수는 연수 내용·실습과 수업 적용을,
학생 자치는 역할별 활동과 인수인계를, 학교 사업은 추진 과제와 성과 확인을 각각 작성한다.
공모전은 배점·제외·동점 처리의 구조화된 검사를 유지한다.

분량이 부족하면 실행 절차·역할·자료·점검 방법을 보완하도록 한 번 더 요청한다.
보완도 사용량에 포함하며, 한도 오류·취소·공급자 실패는 반복 호출하지 않는다.
두 번째 결과도 부족하면 완료로 표시하지 않는다. 기존 저장 원고와 수동 수정은 보존한다.

글자 수는 지면의 근사치다. 표·행 길이·설치 글꼴에 따라 실제 쪽 수는 달라질 수 있다.
빈 페이지나 강제 쪽 나눔으로 분량을 맞추지 않고 실제 차이를 미리보기에서 안내한다.

## 검토 범위

합성 응답으로 8개 유형의 지침·응답 키·실제 목차 대응, 1~5쪽 최소 분량 증가, 부족한 결과의
보완·사용량 차감·재실패·취소를 검사한다. 합성 한국어 원고를 RHWP WASM으로 조판하고
HWPX를 다시 열어 전체 문단 보존을 확인한다. 이는 실제 AI 문장의 교육적 적합성이나
교사가 바로 결재할 수 있는 완성도를 검증한 결과가 아니다.

화면 변경은 분량 설명과 기존 확인 영역의 부족 분량 안내다. 화면 배치는 유지한다.
구현 전 모의 검토에서 웹 관점은 불필요한 새 설정 없이 설명을 고치는 것으로,
UX 관점은 희망 분량과 실제 결과의 차이를 드러내는 것으로,
UI 관점은 색상만이 아닌 문구로 차이를 알리는 것으로 판단했다.
구현 후 전체 데스크톱·모바일·축소 폭 화면과 5쪽 조판 지면을 확인했다.
웹 관점은 목차와 표의 구분·열 배치 유지, UX 관점은 기존 수정·저장 흐름과 입력 보존,
UI 관점은 좁은 폭에서 넘침 없음과 접근성 검사 통과를 근거로 이번 변경을 수용했다.
모바일에서는 지면 글씨가 작으므로 기존 '문서 본문 읽기'를 이용한다. 설치 글꼴에 따른 줄바꿈,
마지막 쪽의 여백과 실제 AI 원고의 의미적 품질은 남은 한계다.
실제 사용자 시험·교사 승인·독립 전문가 검토는 수행하지 않았다.
