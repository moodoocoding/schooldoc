# 운영계획서 작성 구조(v2)

2026-11-14 「운영계획서 v2 리팩토링 실행 지시서」에 따라 다시 설계했다. 범위는 운영계획서이며 다른 공문서에는 적용하지 않았다.

## 책임 나누기

| 누가 | 무엇을 |
| --- | --- |
| AI | 고정 필드에 내용만 쓴다(목적·개요·방침·세부 추진 계획·일정·예산·기대 효과·미정 사항) |
| 코드(구조 검사) | 형식·길이·정수, 항목 앞 기호 떼기, 공문에 없는 근거 ID 지우기 |
| 코드(의미 검사) | 예산 산출·상한, 필수 조건, 일정 순서·요일·마감, 근거 없는 제도·수치·법령, 반복 문장 |
| 렌더러 | 6대 목차 이름·순서·번호, 일정·예산 표, 지정 서식 매핑 |
| 교사 | 확정 필요·제안 사항 결정, 저장 전 고칠 점 수정 |

같은 입력으로 만든 실제 AI 문서의 v1/v2 비교와 교사 블라인드 평가는 하지 않았다.

## 시험(T01~T16)

`tests/unit/schoolPlanV2.test.ts`에 지시서 8장의 16개 시나리오를 가상 데이터로 자동화했다.
AI가 실제로 무엇을 쓰는지는 이 시험으로 알 수 없다. 지시문·스키마가 요구를 전달하는지,
AI가 잘못 썼을 때 검사기가 잡는지, 렌더러·이전 초안 호환이 맞는지를 확인한다.

## 화면 검토 기록(모의 검토)

AI가 `pro/` 프로파일로 수행한 모의 검토이며 실제 전문가·교사 검토나 사용성 시험이 아니다.

- 구현 전 판단
  - 웹: 검토할 점을 저장을 막는 것부터 수준별로 묶고, 새 패널을 늘리지 않는다.
  - UX: 저장이 막히면 무엇을 고쳐야 하는지와 어디서 고치는지를 같은 자리에서 알린다.
  - UI: 수준을 색만이 아니라 제목 글자(`저장 전 고칠 점 n건` 등)로 구분한다.
- 구현 후 확인(근거: `test-results/school-plan/review-issues-desktop.png`, `review-issues-mobile.png`, E2E 접근성 검사)
  - 웹 — 통과: 네 묶음이 지면 위에 차례로 놓이고, 저장 차단 묶음이 빨간 테두리로 맨 위에 있다. 일정표 시기 열과 예산표 비고 열이 좁아 줄바꿈이 많아서 열 너비를 고쳤다.
  - UX — 통과: 차단 사유 아래 수정 버튼과 비활성 HWPX 저장 버튼이 이어진다. 남은 위험은 단가 오류를 고치는 수동 예산 편집기가 없고 AI 예산 수정에 의존한다는 점이다.
  - UI — 통과: 390px에서 가로 넘침이 없고 axe(wcag2a·aa) 위반이 없다. 경고와 확정 필요가 같은 노란색이라 제목 글자로만 구분된다.

## 운영 검수 후 보완(2026-11-14)

운영 사이트에서 가상 공문(공모전, 2쪽)으로 분석·초안·일정 수정·HWPX 생성을 실행한 검수에서 나온 문제를 고쳤다.
검수 원고는 `tests/fixtures/schoolPlanUcc.ts`에 가상 자료로 남겼다.

| 문제 | 고친 곳 |
| --- | --- |
| 제목과 첫 목차가 붙어 보임 | 제목 아래 간격 1,600 → 2,800 HWPUNIT(`rhwpWriter.ts`의 `TITLE_GAP`) |
| 중항목 제목이 쪽 끝에 홀로 남음 | 하위 항목·표가 있는 항목에 '다음 문단과 함께'를 쓰고, rhwp 조판이 이를 따르지 않으므로 홀로 남은 제목 앞에 쪽 나눔을 넣어 미리보기와 한글 결과를 맞춤(`keepHeadingsWithNext`) |
| 표 열 균형(단계 3줄, 담당 '미정' 열이 넓음) | `fitTableColumns`: 내용 길이로 열 너비를 나누고 긴 글 열부터 줄임 |
| 방침·세부 계획의 같은 내용 반복 | 지시문(같은 사실은 한 곳에만) + 글자 쌍 겹침 75% 이상이면 경고(추진 목적↔기대 효과 짝은 제외) |
| 방법 없는 (안) | 지시문 + '사전에 정해 안내'·'안내 후 운영' 등 경고 |
| 총액 한 줄 예산 | 지시문(용도별 산출 (안)) + 확정 필요 |
| 단계마다 같은 시기 | 지시문 + 확정 필요 |
| 수정 후 쪽 수 증가(3쪽에 기대 효과만) | 수정 지시문에 현재 분량 유지. 넘치면 기존처럼 분량 경고 |
| 수정안 비교가 전체 문서를 두 번 보여 줌 | 바뀐 목차만 기존·수정안을 나란히 보이고 빠진 줄(`del`)·새 줄(`ins`)을 표시 |

지시문 변경의 실제 AI 결과는 아래 재검수에서 확인했다.

### 재검수(2026-11-14, 배포 후)

같은 가상 공문으로 운영 사이트에서 다시 실행했다. 2쪽 유지(일정 수정 후에도), 제목 간격, 홀로 남은 중항목 없음, 용도별 예산(시상 물품·편집 앱),
단계별 시기, 방법 없는 (안) 없음, 바뀐 목차만 보이는 수정안 비교를 확인했다. 새로 나온 문제는 다음처럼 고쳤다.

| 문제 | 고친 곳 |
| --- | --- |
| 반복 경고 오탐: 세부 계획의 공모 주제 목록이 추진 목적·기대 효과 문장에 들어 있어 반복으로 판정 | 세 목차 이상에 나오는 글자 쌍은 문서 전체의 주제어로 보고 비교에서 뺀다. 거의 같은 문장(양쪽 모두 75% 이상 겹침)은 주제어를 빼지 않고 판정해 세 목차에 되풀이해도 잡는다 |
| 경고 문구 '추진 목적과(와)' | 받침에 맞춰 '과/와'를 붙임 |
| 양쪽 정렬 줄의 낱말 간격이 크게 벌어짐('…추천작을 / 업무관리시스템으로 제출', #79 배포 후 재검수) | 어절 단위 줄 나눔은 유지하고, 실제 조판에서 빈칸이 보통보다 글자 크기의 25% 이상 넓어진 문단만 한글 기본값인 글자 단위로 나눔(`relieveStretchedLines`). 설정은 HWPX 문단 모양에 남아 한글에서도 같다. 재검수 원고는 `tests/fixtures/schoolPlanUccRecheck.ts` |
| 일정 수정('세 단계로 나눠 주세요')에서 결과 제출이 우수작 선정 행에 합쳐져 시기가 '4. 26.∼5. 7.까지'가 됨(#77 배포 후 재검수) | 지시문(공문 제출·마감은 별도 행, 수정 시 단계 수를 지정받아도 마감 행 유지) + 날짜 하나로 정한 공문 마감만 적은 행이 없으면 검증 경고. 기간으로 정한 신청·제출은 제외 |
| 단계 시작·종료일이 주말(4. 3.(토), 4. 4.(일), 4. 10.(토)) | 지시문(공문이 정하지 않으면 평일) + 공문·입력에 없는 주말 날짜를 검증 경고. '2027. 4. 1. ~ 4. 3.'의 뒤 날짜가 앞 날짜의 연도를 잇도록 날짜 읽기도 고침 |

### 화면 검토 기록(모의 검토)

AI가 `pro/` 프로파일 관점으로 수행한 모의 검토이며 실제 전문가·교사 검토가 아니다.

- 웹(정보 위계·밀도) — 통과: 수정안 비교가 바뀐 목차 하나로 줄어 한 화면에 들어온다(`test-results/school-plan/revision-changes-desktop.png`).
- UX(교사 흐름) — 통과: 무엇이 바뀌었는지 찾지 않고 적용·유지를 고를 수 있다. 남은 위험: 줄 단위 비교라 한 줄 안의 작은 차이는 줄 전체가 바뀐 것으로 보인다.
- UI(접근성·상태) — 통과: 빠진 줄·새 줄을 색만이 아니라 취소선·`del`/`ins` 의미 요소로 구분한다. 비교 묶음에 접근 가능한 이름(`수정안에서 바뀐 목차`)을 붙였다.
