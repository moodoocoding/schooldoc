# 포터블 배포판 개발·인계 계획 (codex)

기준 main: `32abb3af88e9957bfa0aae73b19ee706f8601c4e`. 개발 브랜치: `codex/portable-release`.

이 세션은 구현·로컬 검사·로컬 커밋을 담당한다. 원격 push·PR·후보 게시·다운로드 검증·main 병합·정식 릴리즈는 메인 통합 세션에 인계한다. 로컬 EXE 검사는 게시된 EXE 검증으로 보고하지 않는다.

| 단계 | 완료 기준 | 상태 |
| --- | --- | --- |
| 최신 main·기존 변경 보존 | main fetch, 기존 AGENTS 추가 지침 유지, 다른 checkout 미수정 | 완료 |
| Electron 통합 | 격리된 렌더러, PKCE 로그인, 외부 링크/QR, worker·다운로드·인쇄·저장 | 로컬 구현 완료·실인증 인계 |
| CI 구현 | PR 검사/후보 산출물, main 검증 후 정식 게시, 동일 SHA·체크섬·재실행 처리 | 구현·정적 검사 완료·원격 실행 인계 |
| 로컬 검사 | typecheck/lint/unit/web E2E/build/server 관련 검사 | 완료·보안 패치 후 전체 E2E 282개 재통과 |
| 패키징·로컬 실행 | Windows x64 EXE, 한글/공백 경로, 재시작·저장·대표 사용자 흐름 | clean 코드 커밋의 15항목 통과·최종 증빙은 handoff.json |
| 인계·로컬 커밋 | 재현 명령·산출물·확정 HEAD·미검증 항목 명시 | 구현 커밋 3개와 본 기록·최종 HEAD 산출물로 인계 |
| 후보 게시·다운로드·실인증 | 메인 통합 세션이 수행, 필수 검증이 없으면 병합 보류 | 인계 대상 |
| main 병합·정식 다운로드 | 최신 main 재확인·squash·Actions·최종 EXE 검증 | 인계 대상 |

## 사전 확인

- 기존 Electron 브랜치는 9월 30일 코드다. 기능 코드를 되돌리지 않고 필요한 런타임만 재구성한다.
- 기존 QR 생성에 `window.location.origin`이 남아 있어 EXE 공개 주소가 깨질 수 있다.
- HashRouter에서 `window.location.search`와 pathname 기반 저장 전 이동 확인이 맞지 않는다.
- 프로파일 3개를 읽었다. 초기 AI 모의 판단: 웹디자인은 기존 화면 구조 유지·전체 캡처 필요, UX는 앱/공개 브라우저 주소와 입력 보존 수정 필요, UI는 오류 복구·키보드·PDF/출력 재확인 필요. 실제 전문가 검토가 아니다.
- 외부 공용 개발일지와 `pro/ux-ui-expert.md`는 이 checkout에 없다. 이 문서와 후속 인계 보고서에만 이번 실행을 기록한다.
- 운영 Google 로그인은 계정 접근 및 Supabase loopback redirect 허용 확인이 필요하다. 자동 로컬 모의 인증과 실제 Google 인증을 구분한다.
- 공유 checkout의 미커밋 영수증 변경은 이 작업에 가져오지 않는다. 확정 main의 영수증 출력 기준으로만 패키징하고 차이는 인계한다.

## 작업 기록

- `git fetch origin main feature/portable-app` 완료. Git 작업트리 메타데이터 쓰기는 공유 `.git` 위치로 인해 승격 권한이 필요했고 승인된 명령으로 브랜치 전환했다.
- 원격 게시·운영 DB/Edge 변경 없음.
- DOMPurify만 3.4.13 → 3.4.16으로 고정했다. 다른 기존 패키지 버전은 유지했고 npm 설치 audit는 0건이다.
- 웹 첫 실행의 5개 실패는 가상 연결 설정 누락과 중복 상태 메시지 선택으로 수정했다. 재실행은 282개 통과이며 일반 실행에서 생략하는 HTTP/SQL 5개도 별도 실행에서 통과했다.
- 기존 디자인 증빙 복원은 자동 승인 검토에서 사용자 변경 유실 가능성으로 거부됐다. 해당 파일은 보존하고 커밋에서 제외한다. 최종 EXE는 별도 임시 clean checkout에서 만든다.
- 상세 결과·재현 방법·필수 후속 검증은 [인계 문서](handoff.md)를 따른다.
