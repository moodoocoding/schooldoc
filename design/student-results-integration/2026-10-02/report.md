## 워크플로우와 휴리스틱

1. 교사는 파일을 분석하고 학생 결과·총점을 확인해 안내를 만든다. 다른 앱 화면을 방문했다 돌아와도 현재 탭의 초안·분석 대기·삭제 되돌리기를 복원한다. 초안은 계정별 메모리에만 두며 새로고침·탭 종료 뒤 복원이나 서버 백업으로 안내하지 않는다.
2. PC에서는 학생 비교 표, 모바일에서는 학생 카드로 상태·정정·이의 답변을 처리한다. 화면 폭을 바꿔도 답변 초안·선택을 유지한다. 조회 전용 접속 정보는 기본 확인번호 마스킹과 별도 탭으로 구분한다.
3. 학생은 공용 링크의 이름/확인번호 또는 개인 QR로 자기 결과만 조회한다. 종료·만료·안내 이동 후 늦은 응답을 무시하고 개인 데이터를 지운다. 실패한 이의 제출은 작성 내용을 보존한다.
4. 교사 답변·정정·설정 변경 후 학생은 최신 버전을 읽고 재확인한다. 보호 SQL은 소유자·세션·버전을 잠금 후 다시 확인하며 답변/상태와 재발급/세션 폐기를 함께 처리한다.
5. QR은 PNG로 저장하거나 A4 PDF로 배부한다. 긴 이름/식별값의 높이를 측정해 모든 글자를 유지하면서 페이지당 인원을 줄이고 QR 크기는 유지한다.

휴리스틱 근거: 처리 중 상태·중복 요청 차단(상태 가시성), 조회 종료·초안/되돌리기·재발급 취소(사용자 통제), 기본 마스킹·서버 권한·이전 버전 확인 거절(오류 예방), 명시적 만료/종료 안내와 입력 보존(오류 복구), 상태 검색·카드·PNG 저장(탐색/반복 작업 비용). 학교 현장의 실제 사용자 인터뷰와 사용성 시험을 대신하지 않는다.

1. EXE 로그아웃은 현재 Supabase 기본 전체 세션 로그아웃을 사용한다. 이미 열려 있던 일반 Chrome 교사 화면은 서버에서 로그인을 거절하지만 이전 사용자 표시가 남았다. 새로고침만으로는 복구되지 않았고 정상 로그아웃→기존 계정 재로그인으로 복구됐다. 자동 만료 안내·재로그인 접근 개선은 후속 검토 대상이다. 보안 검증을 우회하거나 로그아웃 범위를 임의로 변경하지 않았다.

3. #52 가정통신문의 실제 서버 발행·보호자 제출과 다른 주요 기능의 실제 후보 EXE 흐름은 이번 검증에서 모두 수행한 것이 아니다. 전체 Chrome 자동 검사 통과와 실제 원격 시험을 구분한다.

## 2026-10-02 마감 시간대·교사 인증 복구 수정 (codex)

사용자의 `코드를 수정해줘` 요청에 따라 앞 절의 두 오류를 기존 별도 브랜치에서 수정했다. 자료 수합은 `487fd7befcbd7a6f28c3cee1251f181854a03a76`, 공통 인증은 `82844abb65d9bde01bed745e901a9ecb520908cd` 커밋으로 나눴다. 검사는 두 수정을 함께 포함한 최종 작업트리를 대상으로 했다. 기록·가상 화면은 별도 문서 커밋으로 정리한다.

### 수정 결과와 호환성

- **자료 수합**: 생성·마감 변경 API 경계에서 브라우저 현지 날짜를 UTC ISO로 변환한다. 유효하지 않은 날짜·지난 마감은 인증·파일 업로드 전에 거절한다. 서버도 생성과 변경에 같은 미래 시각 검증을 적용하고 UTC로 저장한다. 원격 DB 구조·암호화 키·secrets를 바꾸거나 기존 업무의 마감을 일괄 보정하지 않는다.
- 앞 절의 “시간대 있는 값만 서버에서 검증” 제안은 구버전 웹/EXE와의 배포 호환성을 고려해 조정했다. 시간대 없는 기존 요청은 한국 시각 `+09:00`으로 해석하고, 명시된 UTC·offset은 그대로 보존한다. 최신 클라이언트는 한국·미국 시간대 모두 검사했다. 시간대 없는 구버전 요청만으로 다른 지역의 현지 시각을 추론할 수는 없다.
- **공통 인증**: 현재 교사 토큰으로 보낸 같은 Supabase 프로젝트의 업무 API가 401이면 인증 서버에서 그 토큰을 재확인한다. 인증 서버의 401/403 거절이 현재 세션에도 해당할 때 앱의 교사 사용자 상태를 해제하고 기존 Google 로그인 화면에 만료·재로그인 안내를 표시한다. SDK의 저장 세션을 복구 검사에서 임의 삭제하지 않고, 같은 거절 토큰의 초기 인증 이벤트가 사용자 표시를 되살리지 못하게 한다.
- 업무 API의 권한 거절, 익명 공개 요청, 다른 서버, 인증 확인의 네트워크·500·429 오류는 자동 로그인 해제로 처리하지 않는다. 동시 401은 한 번만 확인하며 이전 요청·이전 토큰의 늦은 확인 결과는 새 로그인에 적용하지 않는다. 초기 getSession 결과와 인증 이벤트의 순서 및 언마운트도 보호한다. 쓰기 작업을 자동 재시도하지 않는다.
- Chrome에서 실제 Supabase SDK와 가상 인증 HTTP 응답·Electron OAuth 연결 대역을 사용해 같은 계정 재로그인 후 학생 제목·이름·점수를 탭 메모리에서 복원했다. 학생 자료를 localStorage/IndexedDB에 새로 저장하지 않았다. 일반 브라우저 OAuth의 전체 페이지 이동·새로고침은 기존 안내대로 탭 메모리 초안을 잃을 수 있으므로 같은 탭 대역 검사 결과를 모든 실제 로그인 흐름의 입력 보존으로 확대하지 않는다.
- PR·main 자동 검사에 자료 수합 서버 타입 검사와 새 PostgreSQL 마감 회귀 검사를 추가했다. 기존 릴리즈 게시·검증 안전 조건은 유지했다.
