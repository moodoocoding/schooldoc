## 워크플로우와 휴리스틱

1. 교사는 파일을 분석하고 학생 결과·총점을 확인해 안내를 만든다. 다른 앱 화면을 방문했다 돌아와도 현재 탭의 초안·분석 대기·삭제 되돌리기를 복원한다. 초안은 계정별 메모리에만 두며 새로고침·탭 종료 뒤 복원이나 서버 백업으로 안내하지 않는다.
2. PC에서는 학생 비교 표, 모바일에서는 학생 카드로 상태·정정·이의 답변을 처리한다. 화면 폭을 바꿔도 답변 초안·선택을 유지한다. 조회 전용 접속 정보는 기본 확인번호 마스킹과 별도 탭으로 구분한다.
3. 학생은 공용 링크의 이름/확인번호 또는 개인 QR로 자기 결과만 조회한다. 종료·만료·안내 이동 후 늦은 응답을 무시하고 개인 데이터를 지운다. 실패한 이의 제출은 작성 내용을 보존한다.
4. 교사 답변·정정·설정 변경 후 학생은 최신 버전을 읽고 재확인한다. 보호 SQL은 소유자·세션·버전을 잠금 후 다시 확인하며 답변/상태와 재발급/세션 폐기를 함께 처리한다.
5. QR은 PNG로 저장하거나 A4 PDF로 배부한다. 긴 이름/식별값의 높이를 측정해 모든 글자를 유지하면서 페이지당 인원을 줄이고 QR 크기는 유지한다.

휴리스틱 근거: 처리 중 상태·중복 요청 차단(상태 가시성), 조회 종료·초안/되돌리기·재발급 취소(사용자 통제), 기본 마스킹·서버 권한·이전 버전 확인 거절(오류 예방), 명시적 만료/종료 안내와 입력 보존(오류 복구), 상태 검색·카드·PNG 저장(탐색/반복 작업 비용). 학교 현장의 실제 사용자 인터뷰와 사용성 시험을 대신하지 않는다.

이전 SQL 검사의 ‘플래그 변경은 학생 버전을 유지’ 기대가 최신 main의 재확인 정책과 충돌해 12개 검사 후 실패했다. 기존 main 정책을 되돌리지 않았다. 모든 학생 버전 갱신·오래된 확인 거절·실제 답변 보존을 엄격히 검사하도록 통합하고 같은 설정 재저장의 버전/확인/이력 보존 검사를 추가해 18개를 통과했다. 테스트 삭제나 실패 우회는 하지 않았다.

전체 E2E가 다른 기능의 기존 산출물 55개를 덮어썼다. 복원 명령은 자동 승인 검토에서 기존 작업물 손실 가능성으로 한 번 거절됐다. 작업 전 상태·시험 코드 출력 경로·수정 시각을 확인하고 모든 파일을 ignored 시험 결과 폴더에 백업해 SHA-256 일치를 검사한 뒤 개별 복원을 승인받았다. 내용 해시가 HEAD와 같은 남은 JSON은 인덱스 상태만 갱신했다. 원본 사용자 checkout의 변경 4개는 그대로 유지했다.

## 원격 준비·배포 상태와 재개 지점

- 대상 프로젝트: 기존 연결 `jhystopaacyfvjxhnpyd`. 새 키 생성·secrets 변경·실제 학생 자료 변경은 하지 않았다.
- 원격 이력에서 최신 main의 `202610020200_student_result_settings_versions.sql`이 누락됨을 확인했다. 새 `202610021000_student_result_public_safety.sql`과 함께 dry-run 대상 두 파일만 나온다.
- 과거 학생 safety 번호 `202610010200`은 main의 다른 기능과 중복하므로 재사용하지 않았다. 새 번호의 다른 브랜치/워크트리 충돌을 확인했다.
- 새 migration은 보호 RPC 7개와 service-only grants만 추가하며, 최신 총점/설정 RPC와 단조 updated_at trigger를 덮어쓰지 않는다.
