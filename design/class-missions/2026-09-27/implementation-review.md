# 학급 미션 구현·검토 기록

2026-09-27 · 로컬 구현 및 가상 데이터 검증 · 운영 배포 전

## 구현 범위

- 교사: 최대 12개 학급, 학급당 60명·미션 60건, 붙여넣기/Excel 명단 가져오기, 개인 코드 발급·재발급, 초안·발행·수정·종료·재열기, 대상 스냅샷, 상태 정정·일괄 확인, 미션 복제, Excel 현황, 공통 링크·QR PNG 저장·링크 차단·재발급.
- 학생: 공통 링크와 12자리 개인 코드로 본인 미션만 조회, 완료 표시·교사 확인 전 취소, 저장 오류 재시도, 공용 기기에서 나가기.
- 서버: 교사 인증과 학급 소유자 검사, 공개 토큰·개인 코드 해시·요청 제한, 암호화된 명단/상태/이력, 행 버전 비교로 동시 수정 충돌 감지. 브라우저 역할에는 DB 표의 직접 권한을 부여하지 않는다.
- 홈 도구 카드와 진행 중 업무 목록에 열린 미션을 연결했다. 자료 수합과 구분해 파일·사진 증빙은 포함하지 않았다.

## 세 관점의 모의 검토

`pro/web-designer.md`, `pro/ux-designer.md`, `pro/ui-designer.md`를 구현 전에 읽고, 구현 후 위 전체 캡처와 브라우저 흐름으로 다시 점검했다. 이는 AI의 모의 검토이며 실제 디자이너·교사·학생의 승인이나 사용성 시험이 아니다.

| 관점 | 구현 전 판단·근거 | 구현 후 판단·근거 | 남은 위험 |

| 웹디자인 | **수정 필요.** 미션 목록을 왼쪽 세로 열에 두면 24명 현황 옆으로 큰 빈 공간이 생길 수 있었다. | **통과.** 첫 전체 캡처에서 빈 열을 확인한 뒤 미션 목록을 상단 가로 카드로, 현황을 전체 폭으로 바꿨다. 24명과 60명 캡처에서 두 열 명단과 색·문구가 함께 보이고 390px 및 확대 검사에서 가로 넘침이 없다. | 60명 화면은 세로 길이가 길다. 실제 교사의 빠른 탐색 시간은 측정하지 않았다. |

## 실행한 검사

- `npm run typecheck`, `npm run lint`, `npm test`(53개 파일·438개 테스트), `npm run build` 통과. 린트 경고 6건은 기존 다른 화면에서 발생했다.
- `tests/e2e/class-missions.spec.ts` 4개 통과: 교사·학생·교사 흐름, 두 학생 격리, 공개 링크 끄기, QR PNG·Excel 다운로드, 일괄 확인, 복제, 24명·60명, 보관·파기, 환경 설정의 파기 예정 목록 및 접근성.
- `tests/e2e/app-shell-scroll.spec.ts`의 학급 미션 경로 1개 통과. Playwright는 기존 4173 서버의 다른 데모 설정을 피하려고 별도 4174 포트의 개발 서버에서 실행했다.
- SQL 마이그레이션과 Edge Function은 원격에 적용하지 않았다. 캐시된 Deno로 두 함수의 타입 검사와 모의 HTTP 계약 테스트 6개를 통과했으나 로컬 PostgreSQL이 없어 실제 RLS·DB 트랜잭션의 실행 검사는 하지 못했다. 타입 검사·빌드·데모 E2E를 원격 검증으로 해석하지 않는다.

## 운영 전 남은 일

1. `CLASS_MISSIONS_ENCRYPTION_KEY` 준비 → 마이그레이션 이력 확인·적용 → 두 Edge Function 개별 배포 → 프런트엔드 배포 순으로 운영 연결을 확인한다.
2. 허용된 시험 프로젝트에서 교사 A/B 격리, 학생 코드·공개 토큰 제한, 동시 제출·마감 경계, QR 다운로드와 Excel을 다시 검증한다.
3. 종료 후 90일 보관·교사 확인 파기는 로컬 구현했다. 실제 DB 트랜잭션·RLS·백업 보관 정책은 원격에서 확인해야 한다.

## 후속 구현: 보관·파기

- 종료 시각을 기록하고 90일 경과 전에는 파기 조작을 숨겼다. 다시 열면 보관 기산점을 초기화한다. 기존에 종료 시각이 없는 미션은 자동 파기 대상으로 간주하지 않는다.
- 대상 학생·현재 응답·변경 이력 수를 표시하고, 동의 체크와 `영구 파기` 문구 입력을 거친다. 서버에서도 보드 버전·대상·수량·기간을 다시 확인한다. 마지막 미션 파기 시 명단과 개인 코드를 비우고 공개 링크를 무효화한다.
- 이 기능에는 Storage 파일이 없다. DB 함수에서 암호화 데이터 교체와 개인정보 없는 완료 감사 기록을 한 트랜잭션으로 처리하고, 함수 오류 시 재시도 기록 삽입을 시도한다. DB에 연결할 수 없는 경우에는 재시도 기록도 보장할 수 없으므로 운영 모니터링이 필요하다.
- 종료된 미션을 편집할 때 현재 명단에서 빠진 과거 대상 때문에 서버가 실패할 수 있던 경로를 함께 수정했다.
- 환경 설정의 파기 예정 목록에 종료된 학급 미션을 합쳐 보여 준다. 만료된 항목은 미션 화면으로 이동해 대상·응답·이력 수를 다시 확인한다. 기존 수합 업무의 계정별 보관 개월 설정은 학급 미션의 고정 90일 기한에 영향을 주지 않는다.

### 추가 검증과 원격 한계

- `npm run typecheck`, `npm run lint`(기존 다른 화면의 경고 6건), `npm test`(53개 파일·438개 테스트), `npm run build` 통과. 두 학급 미션 Edge Function 진입점에 `deno check` 통과. `deno test --allow-env --node-modules-dir=manual tests/server/classMissions.test.ts`의 인증·소유자·기간·수량·동시성·공개 조회 모의 HTTP 계약 6개 통과.
- `tests/e2e/class-missions.spec.ts` 4개와 `tests/e2e/app-shell-scroll.spec.ts`의 학급 미션 1개 통과. 가상 명단의 데모 서버 검증이며 원격 Supabase 검증은 아니다.
- Supabase CLI 2.118.0으로 `migration list --linked`를 시도했으나 CLI 액세스 토큰이 없어 `AccessTokenRequiredError`가 발생했다. 따라서 두 마이그레이션·함수·프런트엔드는 원격에 적용하지 않았고, 운영 RLS·실제 파기 트랜잭션도 검증하지 않았다.
