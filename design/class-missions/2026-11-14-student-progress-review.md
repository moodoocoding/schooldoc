# 학급 미션 학생별 현황과 목록 검토

## 구현 전

| 관점 | 판단과 근거 | 확인할 점 |
| --- | --- | --- |
| 웹디자인 | 통계 기간 입력을 공유하고 일별 활동과 학생별 현황을 결과 위에서 전환한다. 관리 목록은 짧은 행과 페이지 단위로 보여준다. | 0명·24명·60명, 누적 미션 60개에서 선택한 미션 상세 위치, 긴 이름·제목과 열 균형 |
| UX | 학생별 완료 건수를 한 표에서 비교하고 학생 이름을 눌러 미션 상태를 확인한다. 관리 목록에는 제목 검색과 상태 필터를 둔다. | 대상이 다른 미션, 과거 종료일, 미션 찾기와 상세 전환, 파기 대상 직접 링크 |

## 1차 검토와 2차 재검증 (codex)

Chrome 데모의 가상 자료를 사용한 AI 모의 검토다. 실제 교사·학생 인터뷰, 스크린리더 음성 출력, 실물 전자칠판은 미검증이다.

| 모의 관점 | 1차 판정과 수정 요구 | 2차 판정과 근거 |
| --- | --- | --- |
| 웹디자인 · 정보 위계 | 수정 필요. 60명 전체가 한 화면에 이어져 원하는 학생까지 훑기 어렵다. 전체 인원과 현재 페이지를 표 위에 둔다. | 통과. 24명과 60명 화면에서 20명씩 보이며 이름·번호 검색은 전체를 대상으로 한다. 21번 학생까지 페이지 이동을 확인했다. |
| 웹디자인 · 화면 밀도 | 수정 필요. 긴 제목이 관리 목록 한 행을 과도하게 차지하고 좁은 통계 표에서 이름 끝이 자주 줄바꿈됐다. | 통과. 관리 목록은 제목을 두 줄까지 보여주고 상세에서 전체 제목을 확인한다. 390px에서는 학생 열을 넓혔고 긴 미션 제목도 펼친 상세 안에서 줄바꿈된다. 데스크톱은 왼쪽 목록과 오른쪽 명단의 길이가 다르다. |
| UX · 학생 사용 흐름 | 통과. 학생별 통계는 교사 화면에 있다. 기존 학생 완료·취소·재표시와 공개 링크를 회귀 검증한다. | 통과. 모바일 Chrome의 기존 QR 접속, 본인 미션, 완료·취소·재표시, 교사 확인 검사를 통과했다. |
| UX · 교실 전자칠판 흐름 | 수정 필요. 학생 이름 가림이 학급 전환으로 해제되고 모바일 상세를 열면 검색 결과까지 수동으로 돌아가야 했다. | 통과. 이름 가림은 교사 화면의 관리·통계에서 공유되며 학급을 바꿔도 유지된다. 모바일 상세에서 `미션 목록으로`를 눌러 검색 결과에 초점을 돌리는 것을 확인했다. |
| UI · 접근성 | 수정 필요. 숫자 검색이 다른 번호에도 부분 일치하고 완료 0건도 녹색으로 표시됐다. | 통과. 번호는 정확히 일치하며 모두 완료한 행만 녹색을 사용한다. 미션 상세 상태는 글자와 색으로 구분한다. 키보드 펼침과 390px axe 위반 0건을 확인했다. |
| UI · 반응형과 상태 | 수정 필요. 빈 학급에서 `미션 0개` 안내가 빈 상태 메시지와 중복됐다. | 통과. 빈 기간은 한 메시지로 표시한다. 1366px·390px·CSS 200%에서 전체 캡처를 확인했고, 설정 제목 3개의 글꼴·크기·굵기가 같았다. |

## 구현과 검증 범위

- 학생별 표는 현재 저장된 미션의 운영 기간과 선택 기간을 비교하고, 보존된 응답 이력을 사용해 종료일(미래 종료일은 오늘) 기준 마지막 상태를 한 번 센다. 확인 대기는 별도이며 해당 없음은 대상 수에서 뺀다. 발행 시각과 미션 일정 변경 이력은 보관하지 않으므로 과거 미션 편성 자체는 복원하지 않는다.
- 관리 목록은 진행 중, 시작 전, 초안, 지난 미션 순으로 정렬한다. 진행 중은 가까운 마감일을 먼저 보여주며 지난 미션은 최근 마감일부터 보여준다. 한 페이지에는 5개를 표시한다. 기존 종료·파기 화면으로 연결되는 직접 링크를 Chrome에서 확인했다.
- `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` 통과. 린트에서 기존 경고 4건, 빌드에서 Excel 모듈 로딩과 큰 번들 경고가 남았다.
- `npm test -- tests/unit/studentMissionProgress.test.ts tests/unit/missionStatistics.test.ts tests/unit/classMissions.test.ts tests/unit/classMissionExcel.test.ts tests/unit/missionSettingsSync.test.ts tests/unit/missionSettingsSyncModes.test.ts tests/unit/scrollContainersAreDeliberate.test.ts` 22건 통과.
- `npm run test:e2e -- tests/e2e/class-mission-statistics.spec.ts tests/e2e/class-missions.spec.ts tests/e2e/class-missions-regressions.spec.ts` 18건 통과. 전체 캡처는 로컬 `test-results/mission-progress-pass1`과 `test-results/mission-progress-final`에 있다.
- `npm run test:e2e -- tests/e2e/app-shell-scroll.spec.ts --grep '학급 미션'` 1건 통과.
- 운영 Supabase는 검사하지 않았고 원격 DB·Edge Functions 변경은 해당 없음. 외부 공용 개발일지가 없어 이 문서에 기록했다.

## UX 검토 반영 전 (codex)

| 관점 | 판정과 근거 | 보완 후 확인 |
| --- | --- | --- |
| 웹디자인 | 수정 필요. 390×844에서 첫 학생 행이 위에서 964px에 있고 검색 결과와 이전 상세가 구별되지 않는다. | 기간과 검색 영역을 줄이고, 선택한 미션이 필터 밖에 있는 경우 상세 위에 안내가 보이는지 확인한다. |
| UX | 수정 필요. 다른 미션을 선택할 때 입력이 사라지고, 브라우저 새로고침 후 적용한 통계 조건이 초기화된다. | 변경한 편집만 이탈 확인, 취소 후 입력 유지, 새로고침과 조회 링크에서 같은 기간·보기를 확인한다. |
| UI | 수정 필요. 이름 가림 상태의 드롭다운 접근성 이름에 학생 이름이 남으며 학생의 완료 취소 후 포커스가 문서 본문으로 떨어진다. | 가림 상태의 DOM과 접근성 이름, Enter로 완료·취소한 뒤 해당 미션 제목 포커스를 확인한다. |

## UX 보완 후 여섯 관점 재검증 (codex)

다음은 Chrome 데모에서 가상 명단으로 진행한 AI 모의 검토다.

| 관점 | 1차 관찰과 보완 | 재검증 결과와 남은 범위 |
| --- | --- | --- |
| 웹디자인 · 정보 위계 | 모바일 통계는 제목·안내 공간을 줄이고 390px에서 날짜 두 칸과 조회를 같은 줄에 배치했다. | 통과. 390×844에서 첫 학생 행이 첫 화면에 들어온다. 320px에서는 일별 통계 조회 버튼을 별도 줄로 표시한다. |
| 웹디자인 · 화면 밀도 | 검색 결과 0건과 이전 상세가 함께 보였다. 상세 위에 현재 필터 범위 밖임을 표시했다. | 통과. 제목·상태 필터에서 안내가 나타나고, 일치하는 항목을 선택하면 사라진다. 24명·60명, 긴 미션 제목, 빈 학급을 확인했다. |
| UX · 학생 사용 흐름 | 완료 표시와 취소 후 동작 버튼이 교체되면서 포커스가 본문으로 떨어졌다. 해당 미션 제목으로 복귀하도록 했다. | 통과. 390px에서 Enter로 완료·취소, Tab으로 같은 미션의 새 동작 버튼에 진입했다. 실물 기기와 스크린리더 음성은 미검증이다. |
| UX · 교사 및 교실 전자칠판 흐름 | 작성 중 이탈하면 입력을 잃었고 새로고침 시 조회 조건이 초기화됐다. 이탈 확인과 URL 복원을 추가했다. | 통과. 미션·학급·설정 전환을 취소하면 입력을 유지하고, 다시 작성을 선택하면 이전 발행 미리보기도 닫힌다. 새로고침 후 학급·적용 기간·학생별 보기를 확인했다. 브라우저의 모든 기록 이동 방식과 실물 전자칠판은 시험하지 않았다. |
| UI · 접근성 | 가림 상태에서 접근성 이름에 실명이 남았다. 번호만 렌더링하고 명단 편집기는 가림을 해제한 뒤 표시한다. | 통과. 상태 정정과 학생 선택에 번호만 보이며 명단 입력이 숨겨진다. 전체 단위 검사에서 발견한 목록의 접근성 이름 중복도 정리했다. |
| UI · 반응형과 상태 | 확인 대기가 완료 수에 포함되지 않는 이유가 표에서 명확하지 않았다. `완료 인정 / 대상`과 확인 대기 설명을 추가했다. | 통과. 데스크톱·390px·CSS 200%의 전체 화면을 확인했다. 390px·일별 통계 데스크톱에서 axe 위반 0건이며, 상태는 글자로도 구분된다. |

- `npm test` 92개 파일, 750건 통과. `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check`도 통과했다. 린트에는 기존 경고 4건, 빌드에는 큰 번들과 Excel 모듈 로딩 경고가 있었다.
- Chrome 데모의 `class-mission-statistics.spec.ts`, `class-missions-regressions.spec.ts`, `class-missions.spec.ts` 20건과 `app-shell-scroll.spec.ts`의 학급 미션 검사 1건을 통과했다. 발행 미리보기 초기화 보완 후 편집 이탈·충돌 복구 2건을 재실행했다.
- 전체 화면 자료는 로컬 `test-results/class-missions-ux-confirmed`에 있다. URL에는 학급 ID와 보기·적용 기간을 포함하며 학생 이름·검색어·개인 코드를 넣지 않는다.
- 운영 Supabase 검증과 배포는 미실행이다.
