# 학급 미션 일별 통계 검토

## 구현 전

| 모의 관점 | 판정과 근거 | 구현 후 확인할 점 |
| --- | --- | --- |
| 웹디자인 | 기존 학급 선택 바로 아래에서 통계로 전환하고, 기간과 일별 표를 한 열에 둔다. 미션별 건수는 날짜를 펼쳐 확인한다. | 전체 화면에서 기간과 결과의 위계, 0건·학급 규모·60명 자료의 열 균형과 긴 미션 제목 줄바꿈 |
| UX | 기본 기간은 오늘까지 7일이며, 시작일·종료일을 입력하고 조회한다. 날짜를 열어 미션별 건수를 확인하고, 다른 학급을 선택해 같은 기간을 비교한다. | 잘못된 날짜 복구, 빈 기간, 탭 복귀와 교사 작성 중 입력, 새로고침 후 최신 기록 |
| UI | 데스크톱과 모바일에 같은 표를 사용한다. 날짜와 건수는 텍스트로 읽을 수 있게 하고 탭과 날짜 펼침에 키보드 조작을 제공한다. | 390px·1366px·200% 확대에서 가로 넘침, 날짜 입력 포커스, 탭 키와 방향키, 색에 의존하지 않는 상태 구분 |

집계는 기존 응답 변경 이력을 한국 시간의 발생일로 묶는다. 학생의 완료 표시·취소, 교사의 확인·기타 상태 정정을 각각 계산하며 같은 학생의 여러 변경은 각각 센다. 현재 상태와 명단만으로 과거 날짜의 상태를 추정하지 않는다.

## 1차 구현 검토와 2차 재검증

아래 평가는 가상 자료를 사용한 AI 모의 검토다. 실제 전문가·교사 인터뷰, 실물 모바일 기기와 전자칠판 사용 시험은 진행하지 않았다.

| 모의 관점 | 1차 판정·근거·수정 요구 | 2차 판정·근거·남은 위험 |
| --- | --- | --- |
| 웹디자인 · 정보 위계 | 수정 필요. 390px에서 합계 카드가 두 줄을 차지해 일별 표가 첫 화면 밖으로 내려갔다. 합계를 한 줄로 묶는다. | 통과. 390×844 전체 화면에서 합계 아래 표 머리글과 첫 날짜를 볼 수 있다. 더 낮은 화면에서는 스크롤해야 한다. |
| 웹디자인 · 화면 밀도 | 수정 필요. 모바일 표에서 네 열 제목이 한 줄에 붙었다. 열 제목을 두 줄로 구분하고 합계 칸은 같은 폭을 사용한다. | 통과. 24명·60명 화면에서 날짜와 건수 열이 정렬되며 0건과 양수는 숫자로 확인된다. 320px에서도 날짜 펼침 버튼이 자기 열 안에 있고 긴 제목이 줄바꿈된다. 실제 학급의 미션 제목 분포는 확인하지 않았다. |
| UX · 학생 사용 흐름 | 통과. 교사 화면에서만 통계 탭이 보이고 기존 학생 QR 흐름을 재사용한다. 추가 수정 요구 없음. | 통과. 기존 Chrome 회귀 검사에서 390px 학생의 QR 접속, 완료 표시·취소·재표시, 교사 확인을 검증했다. 운영 계정과 학생 기기는 미검증이다. |
| UX · 교실 전자칠판 흐름 | 수정 필요. 긴 기간에서 다음 날짜를 보려면 표 맨 아래까지 이동해야 했다. 페이지 버튼을 표 위로 옮기고 통계 새로고침에는 저장 안내를 붙이지 않는다. | 통과. 20일을 두 페이지로 조회하고 이전 날짜의 활동을 펼칠 수 있다. 새로고침으로 추가된 취소가 반영되며 선택 기간은 유지된다. 학생 이름은 통계에 표시하지 않는다. 실제 전자칠판 터치와 교실 뒷자리 가독성은 미검증이다. |
| UI · 접근성 | 수정 필요. 잘못된 기간을 제출하면 두 날짜 모두 오류로 표시되며 포커스가 조회 버튼에 남았다. 수정할 날짜를 식별해 포커스를 보낸다. | 통과. 탭 방향키, Tab으로 기간 입력 진입, Enter로 날짜 펼침, 잘못된 종료일로 포커스 이동을 확인했다. 데스크톱·390px에서 axe 위반 0건이다. 스크린리더 음성 출력은 미검증이다. |
| UI · 반응형과 상태 표현 | 수정 필요. 200%와 빈 학급에서 합계와 상태 안내가 길었다. 합계를 압축하고 날짜 펼침은 밑줄·화살표·접근성 상태를 함께 유지한다. | 통과. Chrome CSS 200% 확대와 320px·390px 전체 화면에서 가로 넘침이 없었다. 0명은 합계 0건과 빈 기간 문구가 표시되고, 잘못된 기간은 이전 결과를 유지한다. 브라우저 메뉴의 실제 확대와 다른 브라우저는 미검증이다. |

## 검사 기록 (codex)

- `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` 통과. 린트는 기존 파일 경고 4건이 있었고 빌드는 Excel 모듈의 동적 로딩과 번들 크기 등의 경고를 남겼다.
- `npm test -- tests/unit/missionStatistics.test.ts tests/unit/classMissions.test.ts tests/unit/classMissionExcel.test.ts tests/unit/missionSettingsSync.test.ts tests/unit/missionSettingsSyncModes.test.ts tests/unit/scrollContainersAreDeliberate.test.ts`에서 20건 통과. 한국 시간 자정, 취소 후 재표시, 종료·초안·삭제된 미션, 잘못된 날짜와 윤일을 포함한다.
- `npm run test:e2e -- tests/e2e/class-mission-statistics.spec.ts tests/e2e/class-missions.spec.ts tests/e2e/class-missions-regressions.spec.ts`에서 기존 15건이 통과했다. 새 테스트의 일부 일치 검색이 `2건`과 `12건`을 함께 찾는 문제를 고친 뒤, `npm run test:e2e -- tests/e2e/class-mission-statistics.spec.ts tests/e2e/app-shell-scroll.spec.ts --grep '기간별 활동|학급 미션'`에서 통계와 스크롤 2건을 통과했다.
- 전체 화면 캡처는 로컬 `test-results/statistics-pass1`과 `test-results/statistics-final`에서 확인했다. 최종 캡처는 24명·60명 데스크톱, 60명 390px·320px·CSS 200%, 빈 학급 390px이다. 기존 E2E의 학생 모바일 화면도 함께 검증했다.
- 변경은 교사용 프런트엔드에 있으며 DB 마이그레이션과 Edge Function 변경은 해당 없음. 원격 Supabase, GitHub 반영, main 병합, 운영 배포는 진행하지 않았다. 이 워크트리에서 외부 공유 개발일지 `../schooldoc-docs/development-history.md`를 찾지 못해 이 문서에 기록했다.
