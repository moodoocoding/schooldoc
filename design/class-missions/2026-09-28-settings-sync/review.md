# 학급 미션 설정 연동 화면 검토

이 기록은 웹·UX·UI 디자이너 프로파일에 따른 AI의 모의 검토다. 실제 교사 인터뷰나 전문가 승인을 뜻하지 않는다.

## 구현 전 판단

| 관점 | 판단 | 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 수정 필요 | 미션 학급과 명단을 모두 비어 있는 화면에서 다시 입력해야 했다. | 설정의 학생을 가져올 때 새 코드가 화면 아래에 묻힐 수 있다. |
| UX | 수정 필요 | 설정에 학급·학생을 등록해도 미션 화면에서 학급 생성과 명단 입력을 반복했다. QR의 재사용 여부도 화면에서 설명하지 않았다. | 자동 변경으로 기존 응답이나 코드를 덮어쓰면 안 된다. |
| UI | 수정 필요 | 새 미션 발행 후 같은 QR을 쓰는지, 이미 열린 학생 화면을 어떻게 갱신하는지 안내가 부족했다. | 자동 발급 코드를 다른 학급 화면에 표시하면 안 된다. |

## 구현 후 판단

| 관점 | 판단 | 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 통과 | [교사 데스크톱](teacher-desktop.png)과 [교사 모바일](teacher-mobile.png) 전체 화면에서 자동 등록 알림, 새 개인 코드, 학급 QR 순으로 읽힌다. 모바일 가로 넘침은 없었다. 기존 24명·60명 전체 화면 E2E도 통과했다. | 학생이 많으면 발급 코드 영역이 길어진다. 교사가 코드 전달을 마치고 닫을 수 있다. |
| UX | 통과 | 설정의 `3학년 2반 담임`과 가상 학생 2명으로 학급·명단을 자동 생성하고, 새 학생 1명만 추가했다. 기존 미션 대상·QR·개인 코드를 유지했다. [학생 모바일](student-mobile.png)에서는 같은 QR로 두 번째 미션을 새로고침 후 확인했다. 마지막 미션 파기 후 중지된 학급에는 명단을 다시 넣지 않는 흐름도 확인했다. | 프로필 학급 표기는 현재 브라우저에만 저장된다. 여러 미션 학급이 있고 프로필 학급이 없으면 자동 배정 대신 안내한다. |
| UI | 통과 | 코드 영역은 경고색 테두리와 학급별 표시로 구분했고, 새 미션의 QR 재사용과 학생 화면의 새로고침을 문구로 알린다. 버튼·입력의 접근 가능한 이름은 E2E에서 확인했다. 기존 24명·60명 화면의 자동 접근성 검사도 통과했다. | 코드 영역을 닫거나 화면을 떠난 뒤에는 코드를 다시 볼 수 없으므로 재발급이 필요하다. |

가상 명단만 사용했다. 데모 브라우저 검증이며 원격 Supabase 검증 결과로 취급하지 않는다.
