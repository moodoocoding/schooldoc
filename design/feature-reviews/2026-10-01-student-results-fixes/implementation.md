# 학생 결과 안내 리뷰 후속 수정 (codex)

기준: ../2026-10-01-student-results/review.md SR1–SR11. 별도 브랜치 codex/fix-student-results-review.
실제 학생 자료 없이 로컬 데모·설치된 Chrome과 서버 모의 요청을 검증한다.

## 구현 전 세 프로파일 판단

- 웹디자인: 모바일 900px 표는 학생 이름과 행동을 분리한다. 학생 카드로 같은 정보를 묶고 PC 표는 학급 비교에 유지한다. 대표 24명·60명, 긴 이름, 빈 상태 전체 화면으로 밀도 검증이 필요하다.
- UX: 조회 종료·만료·뒤로 가기·내용 변경 시 사용자가 현재 상태를 확신할 수 있어야 한다. 종료 후 늦은 응답 차단, 만료 시 비공개 정보 제거와 재조회, 같은 탭의 메모리 초안 복원, 변경 후 재확인을 적용한다. 메모리 보관은 새로고침/탭 종료로 끝남을 명시한다.
- UI: 상태는 색과 문구를 함께 제공하고 QR 저장은 보조 행동으로 분리한다. 대비를 개선하며 PC/390px, 키보드 포커스, 출력 시 긴 이름과 QR 크기를 재검증한다.

세 판단은 pro/web-designer.md, pro/ux-designer.md, pro/ui-designer.md를 읽은 AI의 모의 검토다. 실제 전문가·교사 검토가 아니다.

## 검증 및 1차/2차 검토

구현 완료 후 실제 화면·PDF 근거와 검증 결과를 추가한다. 원격 DB·Edge Functions·프런트엔드 배포는 이 기록만으로 적용되지 않는다.

전체 화면 근거는 evidence/first-pass 및 대표 24명·긴 60명 PC/390px 캡처다. 여섯 항목은 AI의 독립된 검토 기준이며 실제 전문가 여섯 명의 검토가 아니다.

## 2차 검토 결과

- 웹 정보 위계: 통과. PC의 비교 표와 모바일 학생 카드 유지. 실제 전체24명 화면에서 학생·결과·상태·정정/응대 관계 확인.
- 웹 화면 밀도: 통과. 모바일 상태 요약4열·2행으로 첫 화면에 첫 학생 점수 노출. 긴60명은 세로 목록/검색으로 접근하며 가로 넘침0.
- UX 학생 흐름: 로컬 검증 통과. 조회→이의→답변→재확인→완료→재발급 만료 폼 전환 전체 캡처. 원격 환경은 별도 배포·검증 필요.
- UX 교실 배부 흐름: 로컬 검증 통과. 일반17명8/8/1, 긴100자8명4/4, 실제PDF5쪽 전체 렌더에서 이름·식별·QR·쪽번호 잘림/겹침 없음.
- UI 접근성: 자동검사 및 키보드 검증 범위 통과. 대표9화면 axe WCAG2A/AA·2.1AA 위반0, 확인번호 마스킹과 상태 문구 유지. 자동검사는 실제 스크린리더 사용성 시험을 대신하지 않음.
- UI 반응형/상태: 통과. PC1440px·모바일390px와 긴 영문 자료 모두 문서 폭=창 폭, pageerror0. QR A4 미리보기는 의도적 좌우 스크롤이며 이동 안내와 키보드 접근을 제공.

세 프로파일의 구현 후 판단도 위 결과와 같으며, 남은 위험은 실제 학교 IP의 다학급 부하·실제 학교 장비/카메라·원격 Supabase·다중 DB 연결 경합이다. 모의 전문가/가상 담임의 의견이며 실제 인터뷰·승인을 받지 않았다.

## SR2 승인 후 후속 검증 (codex)

제안 수치를 사용자가 직접 승인한 후 동일 브랜치에서 접속 한도를 반영했다. 새 HTTP8개와 SQL2개를 추가해 전체HTTP26·SQL17개를 재검증했고 두 함수 Deno check 및 lint도 통과했다. 이의·세션·소유자 등 이전 회귀도 포함한다. 화면 코드는 이번 후속 작업에서 바꾸지 않아 Chrome/프런트엔드 빌드 재실행은 생략했다. 원격 배포·학교 NAT·다중 DB 연결 부하는 여전히 미검증이며 요청당 제한 RPC3회의 실제 지연도 배포 후 확인 대상이다.
