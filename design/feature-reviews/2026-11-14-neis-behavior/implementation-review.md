# 행동특성 구현 및 모의 디자인 검토

## 구현 전 세 프로파일 검토

- 웹디자인: 전체 학급을 연속된 표로 제시하고 입력/결과의 열 비중을 다르게 한다. 번호·이름은 좁게, 특성과 본문은 넓게 둔다. 기존 화면의 세부 근거 패널은 만들지 않는다.
- UX: 명단 → 특성·메모 입력 → 한 번 작성. 개별 학생 승인·검토 완료 단계는 없다. 완료한 행은 다른 학생이 작성 중이어도 편집할 수 있어야 한다.
- UI: 각 조작 이름에 출석번호와 이름을 넣어 동명이인을 구분한다. native select로 키보드 선택을 지원하며 390px에서는 표의 행을 세로 카드로 배치한다.
- 상세 선행 검토: [ux-ui-review.md](ux-ui-review.md). 보관은 기존 Neis Helper와 동일한 탭 메모리 정책을 사용한다. 영구 저장 성공을 표시하지 않으므로 저장 실패 상태를 가짜로 만들지 않는다. 새로고침 전 안내와 Excel 저장으로 구분한다.

## 1차 구현 후 여섯 독립 모의 관점

실제 전문가나 교사의 인터뷰가 아닌 AI 모의 검토다. 동일한 전체 페이지와 가상 명단을 각 관점에서 따로 판단했다.

| 관점 | 1차 판정과 근거 | 수정 요구 / 2차 적용 |
| --- | --- | --- |
| 웹디자인 정보 위계 | 수정 필요. 특성·메모와 결과 버튼이 동일한 흰색으로 보였다. | 선택된 보기에 파란 테두리·배경·텍스트와 aria-pressed를 함께 적용. |
| 웹디자인 화면 밀도 | 수정 필요. 결과 입력칸이 기본 2줄 높이로 표시되어 400자 본문을 보기 어려웠다. | 결과 textarea를 명시적인 6행으로 설정. 긴 이름은 줄바꿈하고 본문 열의 60% 내외 비중 유지. |
| UX 학생 단위 처리 흐름 | 통과. 24명 요청 1회, 첫 행 도착 즉시 편집, 다른 행 도착 후 편집 유지 확인. | 보존. 중복 재작성은 수정하지 않은 23명만 요청하는 검사 추가. |
| UX 교실·전자칠판 흐름 | 수정 필요. 긴 표의 아래에서 작성·중단 버튼으로 돌아가기 번거롭다. 교사용 개인 기록이므로 실제 수업 중 전자칠판 공개는 검토 대상 사용 방식이 아니다. | 대표 작성/중단 버튼이 있는 도구줄을 고정하고 선택·미완료 수를 표시. 개인정보 외부 전송 안내를 작성 전 표 위로 이동. |
| UI 접근성 | 통과. 입력 이름에 번호·이름 포함, 키보드 native select, 명시적 완료/미작성/직접 수정 상태. | axe와 키보드 검사 유지. 이전 검사에서 1번이 11·21번까지 매칭되던 테스트 선택자를 정확히 고침. |
| UI 반응형·상태 표현 | 수정 필요. 입력 후 잘못된 명단을 바꿀 경로가 없다. | 초기화 대상 수를 알리는 '다른 명단' 확인과 기존 명단 유지 버튼 추가. 중단 시 도착한 내용 보존, 입력 변경 시 재확인 표시. |

## 검사 자료

- 전체 캡처: `test-results/neis-behavior/empty-desktop.png`, `input-24-desktop.png`, `stream-24-desktop.png`, `results-24-desktop.png`, `results-60-mobile.png`, `results-200-percent.png` (가상 학생만 포함, Git 제외).
- 0명·24명·60명, 동명이인·긴 이름, 데스크톱·390px·CSS 200% 확대를 확인한다. 200% CSS 확대 검사는 실제 OS 확대나 모바일 운영 로그인을 대신하지 않는다.
- `tests/e2e/neis-behavior.spec.ts`: 단일 요청, 부분 스트리밍, 편집 보호, 선택 중복 재요청, 중단·재시도, 번호순 Excel 읽기, 입력 변경, 전체 동일 문장 내보내기 차단, axe 검사.
- `tests/unit/neisBehavior.test.ts`: 입력 범위·식별자·익명 전송, 첫 단어/3글자/유사 문장, 명사형, 바이트, 계정 전환 초기화, 인증·한도 실패 시 호출 차단, UTF-8 분할 및 끊긴 SSE 검사.

## 확인 한계

모의 응답의 짧고 기계적인 문장은 전송·표시 테스트용이며 모델의 실제 문장 품질 평가가 아니다. 실시간 운영 확인은 별도 배포 기록에 남긴다. 교사 메모의 사실성·정성적 적절성을 자동 검사로 보증하지 않는다. 포터블은 사용자 지시로 빌드·검사·릴리즈하지 않는다.

## 2차 구현과 운영 점검 후 재검토

- 웹디자인 정보 위계: 통과. 공통 관리자 CSS의 `!important`가 선택 버튼의 Tailwind aria 변형을 덮는 것을 실제 운영 화면에서 발견했다. 선택 상태에 기본 흰색·회색 클래스를 함께 두지 않는 방식으로 수정했다. 실제 계산된 배경색이 입력/결과 전환에 따라 달라지는 E2E 검사를 추가했다.
- 웹디자인 화면 밀도: 통과. 24명 전체 캡처에서 긴 이름 줄바꿈과 본문 열 비중, 6행 결과 칸을 확인했다. 가상 60명과 200% 화면에서도 가로 넘침이 없다.
- UX 처리 흐름: 통과. 단일 요청·먼저 도착한 행 편집·후속 행 수신 시 편집 보존·중단 후 미완료 재요청을 회귀 검사했다. 운영에서는 가상 4명의 실제 생성 완료와 직접 편집 후 Excel 반영을 확인했다.
- UX 긴 명단 흐름: 통과. 대표 작성 버튼 고정과 명단 교체 취소 시 입력 보존을 확인했다. 재사용 명단 가져오기의 설정 저장 안내는 행동특성의 탭 보관 안내로 분리했다. 설정 화면의 기존 저장 안내는 유지한다.
- UI 접근성: 통과. 입력 이름·키보드 선택·선택 상태 aria-pressed와 배경색 구분, axe 위반 0건을 재확인했다.
- UI 반응형/상태: 통과. 390px, 200% 확대, 완료/직접 수정/입력 변경/미완료 상태 검사를 다시 통과했다. 실제 휴대전화 운영 로그인은 검사하지 않았다.

독립 관점은 AI 모의 검토이며 실제 전문가 6명의 승인이 아니다. 최종 배포와 실서비스 확인 범위는 [운영 검증 기록](production-verification.md)을 따른다.
