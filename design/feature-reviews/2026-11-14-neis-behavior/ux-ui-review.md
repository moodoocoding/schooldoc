## 우선 수정할 설계

아래 P1/P2는 설계 보완의 우선순위다. 아직 없는 코드의 실행 버그나 접근성 위반을 확정한 것이 아니다.

### P1-1. 수신 중인 문장과 교사 편집의 충돌 방지

**위치:** 결과 시안의 4번 학생 문장 칸, 상단의 즉시 수정 안내.

수신 중인 칸도 편집 가능한 입력처럼 보인다. 이 상태에서 교사가 문장을 바꾸면 다음 응답으로 덮어쓸지, 수신을 멈출지 정해져 있지 않다. 다른 학생의 생성이 끝날 때까지 전체 화면을 잠그는 방식도 요구와 맞지 않는다.

- 수신 중인 행은 문장을 즉시 표시하되 문장 칸만 읽기 전용으로 둔다. 키보드 포커스를 강제로 옮기지 않는다.
- 해당 학생의 수신·검사가 끝나면 바로 편집과 개별 복사를 허용한다. 다른 학생은 계속 작성한다.
- 생성에 사용 중인 학생의 특성·메모는 요청 당시 값으로 유지하고, 완료 후 수정하면 기존 문장을 보존하면서 `입력 변경됨`을 표시한다.
- 교사가 수정한 문장은 자동 재작성으로 덮어쓰지 않는다. 명시적으로 선택해 재작성한 경우에만 교체하며 이전 문장을 복원할 수 있게 한다.
- 재요청·학급 변경 후 도착한 오래된 응답이 현재 학생 행에 들어가지 않도록 학생 ID·요청 버전·편집 버전을 구분한다.

### P1-2. 중복 확인과 선택 재작성 경로 추가

**위치:** 결과 시안 상단 도구 모음과 학생 행 상태.

현재 시안에는 전체 복사·Excel 저장만 있고, 사용자가 요구한 중복 학생 묶음 재작성 경로가 없다. 중복 이유와 해당 학생을 바로 찾을 수 있어야 한다.

- 기본은 번호순 전체 목록을 유지한다. `표시: 전체 / 중복 있음 / 미완료` 드롭다운을 둔다.
- 행에 `첫 단어 겹침`, `첫 세 글자 겹침`, `문장 겹침`을 표시하고 관련 학생 번호를 확인할 수 있게 한다.
- 중복이 있을 때만 `중복 학생 다시 작성 (N명)`을 표시한다. 해당 학생만 묶어서 요청한다.
- 중복 재작성 중에도 통과한 문장과 수동 편집 내용은 유지한다. 교사 수정 행은 자동 대상에서 제외하고 필요하면 직접 선택한다.
- 필터·재작성으로 학생 번호와 입력 자료의 연결이 달라지면 안 된다. 필터를 해제하면 원래 번호순 위치를 유지한다.

### P1-3. 중단·실패·저장 상태를 구분

**위치:** 결과 시안의 `중단`, `작성 대기`, 하단의 자동 저장 안내.

시안은 정상 수신과 대기 상태만 보여 준다. 중단 후 다시 시작할 때 완료된 학생도 재생성하는지 알 수 없고, 자동 저장 성공을 항상 표시하면 저장 실패를 알아채기 어렵다.

- `중단`은 추가 수신을 멈추고 완료 문장을 보존한다. 수신 도중의 불완전한 문장은 남겨 보되 완료 결과로 내보내지 않는다.
- `미완료 N명 작성`으로 남은 학생만 재요청한다. 개별 실패는 행 옆에서 원인과 다시 시도 동작을 제공한다.
- 저장은 `저장 중… / 저장됨 / 저장 실패 · 다시 시도`로 구분한다. 실제 저장 성공 전에 `저장됨`으로 바꾸지 않는다.
- 저장 위치는 실제 구현과 일치하게 안내한다. 브라우저 저장이면 계정 백업·기기 간 동기화처럼 표현하지 않는다.
- 입력이 전혀 없는 학생은 행에 표시한다. 메모는 선택 입력이며 특성 또는 메모가 있으면 작성 대상으로 삼는다. 작성 가능한 인원과 빠진 인원이 드러나도록 한다.
- 전체 내보내기는 누락을 숨기지 않는다. 일부만 완료된 경우 `완료 N명 내보내기`처럼 범위를 명시한다. 기본 전체 출력은 명단 수·학생 연결·완료 여부를 확인한다.

### P2-1. 특성 선택의 반복 조작과 표시 불일치 완화

**위치:** 입력 시안의 5번 학생 특성 선택창, 입력·결과 시안의 1번 학생 특성.

입력 시안에서 협동 체크와 선택된 칩의 내용이 일치하지 않는다. 1번 학생은 입력 시안의 세 특성 중 두 개만 결과 시안에 보이는데, 축약 표시가 없어 하나가 사라진 것처럼 보인다. 이는 이미지상의 불일치이며 실제 상태 관리 오류를 확인한 것은 아니다.

- 특성 선택과 해제는 같은 값에 즉시 반영한다. 한 항목을 선택할 때마다 창이 닫히지 않게 한다.
- 처음에는 모든 영역을 검색할 수 있게 하고, 영역 드롭다운은 선택적으로 사용한다. 영역 선택을 필수 절차로 만들지 않는다.
- 직접 추가한 특성도 검색·선택·해제 방식이 같아야 한다. 선택한 특성은 줄바꿈하거나 누를 수 있는 `외 N개`로 모두 확인할 수 있게 한다.
- 결과 화면의 특성 요약에서도 숨긴 개수를 보여 준다. 펼치기는 원래 내용을 확인하고 수정하는 용도이며, 별도 검토 완료 단계는 두지 않는다.
- 자주 쓰는 특성을 우선 표시하고 키보드로 선택·닫기·다음 메모 입력을 이어갈 수 있게 한다.
- 여러 학생에게 공통 특성을 추가하는 기능은 보조 선택으로 둔다. 기존 특성·개별 메모를 덮어쓰거나 모든 학생에게 기본 특성을 자동 부여하지 않는다.

### P2-2. 긴 학급 목록과 실시간 문장의 위치 안정성

**위치:** 두 시안의 표 머리글, 결과 수신 중 높이가 바뀌는 문장 칸.

6~8개 행을 본 이미지로 24명·60명·긴 문장의 사용성을 통과시킬 수 없다. 수신마다 행 높이가 변하면 아래에서 편집 중인 위치가 밀릴 수 있다.

- 학생 번호·이름 순서를 고정하고 완료된 학생을 위로 재정렬하지 않는다.
- 표 머리글과 짧은 작업 도구 모음을 스크롤 중에도 찾을 수 있게 하되 포커스된 입력을 가리지 않게 한다. 세로 스크롤은 문서 하나가 맡는다.
- 입력·결과 전환 시 같은 학생 위치를 유지한다. 결과에 필요한 공간을 확보하고 사용자가 보고 있는 행을 새 수신 행으로 강제 이동시키지 않는다.
- 글을 작게 줄여 한 화면에 24명을 욱여넣지 않는다. 전체 학생이 하나의 연속 목록에 존재하는 것을 기준으로 한다.
- 실제 글을 받는 속도로 갱신한다. 별도의 가짜 타이핑 지연을 넣지 않으며, 업데이트 빈도로 입력이 느려지지 않는지 확인한다.

### P2-3. 키보드·작은 조작부·좁은 화면 검증

**위치:** 특성 칩의 삭제 아이콘, 복사 아이콘, 메모 입력, 선택창, 모바일 배치.

이미지로 DOM의 라벨·키보드 조작·CSS 클릭 영역·명도 대비를 확인할 수 없다. 작은 아이콘은 실제 구현에서 클릭 영역을 따로 확보해야 한다.

- 메모와 결과 필드에 학생을 구분할 수 있는 접근 가능한 이름을 연결한다. 예: `3번 학생 C 메모`. 표 제목과 자리 표시자만으로 대체하지 않는다.
- 아이콘 버튼에도 학생과 동작을 식별하는 이름을 둔다. 저장·진행 상황은 포커스 이동 없이 적절한 상태 영역으로 알린다. 모든 글자 수신을 음성으로 반복하지 않는다.
- 선택창은 키보드로 열기·선택·닫기가 가능하고, 닫힌 뒤 원래 버튼으로 포커스가 돌아와야 한다.
- 프로젝트 기준인 44×44 CSS px 목표 클릭 영역, 본문 대비, 선택·오류 상태를 실제 DOM에서 확인한다. 이미지 픽셀을 CSS px 측정치로 쓰지 않는다.
- 좁은 화면에서는 같은 학생 목록 안에서 특성·메모·결과를 세로로 재배치한다. 학생 한 명씩 넘기는 별도 화면은 만들지 않는다.

## 유지할 구조와 수정 후 배치

- 번호순 전체 명단, 선택 입력인 메모, 검색 가능한 복수 특성 선택, 공통 분량, 학급 단위 요청을 유지한다.
- 상단에는 학급·학년도, 학생 수, 공통 분량과 현재 주 동작을 둔다. 이미 명단이 있으면 가져오기는 보조 동작으로 둔다.
- 입력 상태의 표는 `번호·이름 / 특성 / 메모`로 구성한다.
- 작성·결과 상태의 표는 `번호·이름 / 입력 요약 / 문장`으로 구성한다. 결과를 가장 넓게 배치하고 학생별 검토 완료 버튼은 추가하지 않는다.
- 주 동작은 상태에 따라 `학급 전체 작성 → 작성 중·중단 → 미완료 작성 또는 중복 학생 다시 작성`으로 바뀐다. 해당 문제가 없으면 재작성 버튼을 노출하지 않는다.
- 복사·Excel은 보조 동작으로 두며, 완료된 행의 개별 복사는 다른 행의 수신 중에도 사용할 수 있다.
- 문장 상태와 저장 상태는 별개다. 문장은 `대기 / 작성 중 / 완료 / 중복 있음 / 실패 / 입력 변경됨`을 필요한 행에만 간결하게 표시한다.
- 학급 변경이나 명단 재가져오기는 기존 입력을 조용히 초기화하지 않는다. 기존 작업을 보존하고 다른 학급 작업과 구분한다.

| `streaming progress layout stability --domain ux` | Streaming, Progress Indicators가 관련 있음 | 실시간 표시와 완료 수. 단계 표시 예시를 추가 단계 도입 근거로 사용하지 않음 |

| `controlled table input rendering --stack react` | 폼 제어·라벨은 현재 스택에 해당. ref 변경 등 무관한 결과는 제외 | 입력값과 수신값을 분리하고 행 단위 입력 비용을 점검하는 구현 기준 |

`quick-reference.md`를 함께 읽었다. `pro-rules.md`의 주 범위는 네이티브 모바일이므로 pt·dp를 데스크톱 웹 CSS px 기준으로 그대로 옮기지 않았다. 검색 결과는 권고로 취급하고 기존 제품 스타일과 사용자의 드롭다운·전체 학급·단계 축소 요구를 우선했다. 코드 실행이 없으므로 React 상태·ARIA 역할 구현의 통과 여부는 판정하지 않았다.

## 구현 후 검증할 과제

1. 0명·24명·60명, 동명이인, 긴 이름, 특성 여러 개, 여러 줄 메모의 배치를 확인한다.
2. 마우스 없이 특성 검색·복수 선택·해제·직접 추가·메모 입력·복사를 수행한다.
3. 1번 문장을 편집하는 동안 2~24번을 수신해 교사 수정·포커스·스크롤 위치가 유지되는지 확인한다.
4. 생성 중단·연결 끊김·단일 행 실패 후 완료 문장과 미완료 행이 구분되고 미완료 학생만 재요청되는지 확인한다.
5. 중복 필터와 재작성 전후에 원래 번호·학생 ID·특성·메모의 연결 및 교사 수정 내용이 유지되는지 확인한다.
6. 저장 실패·다음 접속·학급 변경·명단 교체에서 실제 저장 정책대로 입력과 문장이 보존되는지 확인한다.
7. 1366px 데스크톱·390px 모바일·200% 확대에서 전체 화면을 확인한다. 문서 하나의 세로 스크롤과 선택창의 포커스 가림을 검사한다.
8. 실제 문자열과 상태를 대상으로 접근성 자동 검사 및 키보드 검사를 하고, 정상 결과의 전체 복사·Excel 행 수·번호·내용을 대조한다.

이번 실행: 이미지 전체의 정적 확인, 관련 소스·설정 확인, 스킬 검색, 검토 문서와 경로·diff 확인. 행동특성 실행 화면이 없고 이번에 제품 코드를 수정하지 않았으므로 타입·단위·E2E·빌드·실제 AI 생성은 실행하지 않았다. 실제 접근성·반응형·저장·생성 품질은 미검증이다. 커밋·push·병합·배포를 수행하지 않았다.
