# 1인 1역 워크플로우 후속 구현·모의 디자인 검토 (codex)

이 문서는 [교사·학생 업무 검토](review.md)의 W1~W6를 코드에 반영한 기록이다. 세 프로파일과 여섯 관점은 AI의 **모의 검토 기준**이며, 실제 웹디자이너·UX/UI 전문가·교사·학생에게 인터뷰나 승인을 받은 것이 아니다.

## 실제 흐름을 기준으로 바꾼 내용

| 흐름 | 수정 내용 | 보존 조건 |
| --- | --- | --- |
| 최초 준비·학기 중 변경 | 내부 메뉴를 실천 현황·배정 관리·역할 관리·운영 설정으로 묶었다. 배정 관리에서 현재 배정 변경과 다음 기간 준비를 구분한다. | 기존 개별 URL은 유지한다. 현재 변경은 적용일 전날로 기존 기간을 닫고 다음 기간에 기존 배정을 가져온다. 변경이 없으면 새 기간을 만들지 않는다. |
| 기간 관리 | 별도 `codex/fix/classroom-role-period-settings` 워크트리의 과거 날짜 수정, 지난·현재·예정 기간 선택, 기록 없는 기간 삭제, 서비스 전용 원자적 저장 규칙을 가져왔다. | 기록된 날짜를 기간 밖으로 빼거나 기록 있는 기간을 삭제하지 않는다. 겹침과 동시 저장 충돌을 막는다. |
| 매일 실천 | 학생 상세에 역할의 할 일을 입력 버튼보다 먼저 표시한다. 교사가 정정한 당일 기록은 학생이 덮어쓰지 못하게 한다. | 교사가 `미기록`으로 되돌리면 다시 학생 입력이 가능하다. 학생별 확인 정보는 해당 학생 선택 시에만 내려준다. |
| 이력·정정 | 지난 기록의 학생·날짜 상세에서 바로 정정한다. 공유 링크·교실 표시·게시판 안내문은 주간 표의 보조 영역으로 묶었다. | 이전 학생·날짜 맥락을 유지하고 기록 출처를 표시한다. QR 표시 시 이미지 저장은 계속 제공한다. |
| 많은 인원 | 학생 화면은 이름·번호 검색, 교실 표시는 25명씩 페이지 전환을 제공한다. | 전자칠판은 읽기 전용이고 공개 이름 마스킹을 유지한다. |
| 미저장 상태 | 역할·운영 설정·배정 편집의 링크 이탈과 새로고침을 경고한다. | 취소하면 입력값을 보존하며, 저장 뒤에는 경고를 치운다. |

## 구현 전 세 프로파일 판단

- 웹디자인: **수정 필요**. 여섯 동등 메뉴와 상단 공유 블록이 일상 확인보다 먼저 보였고, 한 학급·60명 교실 표시의 화면 밀도를 구분할 필요가 있었다.
- UX: **수정 필요**. 전입생 반영, 현재 역할 일부 변경, 지난 기록 정정이 연결된 한 업무로 끝나지 않았다.
- UI: **수정 필요**. 교사 정정 뒤 학생에게 입력 가능한 것처럼 보였고, 저장하지 않은 설정을 화면 이동 중 잃을 수 있었다.

## 1차 구현 뒤 여섯 독립 모의 관점과 2차 조정

| 모의 관점 | 1차 판정·화면/과제 근거 | 수정 요구와 2차 반영 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 · 정보 위계 | **조건부 통과**. 네 주요 메뉴와 배정 관리의 현재·다음 선택은 분명하지만, 공유 도구가 일상 조회 앞에 남아 있었다. | 주간 표·학생별·지난 기록을 먼저 놓고 공유 액션을 접었다. | 실제 교사가 접힌 공유 영역을 찾는지는 미검증. |
| 웹디자인 · 화면 밀도 | **수정 필요**. 60명을 한 화면에 표시하면 교실에서 글자가 작거나 아래 행이 화면 밖으로 밀린다. | 25명씩 페이지 전환하고 1366×900 전체 화면에서 첫 25명을 확인했다. | 실물 전자칠판의 거리·해상도는 미검증. |
| UX · 학생 사용 흐름 | **수정 필요**. 학생이 할 일을 보기 전에 했어요/못했어요만 골랐고 많은 명단에서 자기 이름을 찾기 어려웠다. | 역할 설명을 먼저 표시하고 이름·번호 검색을 추가했다. 숫자만 입력하면 해당 번호와 정확히 일치시켰다. | 저학년 읽기와 타인 이름 선택 위험은 실제 학생 시험 필요. |
| UX · 교실 전자칠판 흐름 | **조건부 통과**. 읽기 전용·이름 마스킹은 유지되지만 25명 초과 시 전환 조작이 필요하다. | 현재 쪽/전체 쪽·인원과 이전/다음 버튼을 표시했다. | 자동 순환은 교실 사용성이 확인되기 전까지 추가하지 않음. |
| UI · 접근성 | **조건부 통과**. 검색 입력에 이름, 기간 입력에 레이블, 기록 정정에 날짜별 이름이 있다. 미저장 링크 이탈 확인도 동작한다. | 저장 후 남던 미저장 경고를 제거하고, 변경 없는 기간 분리를 차단했다. | 실물 스크린리더·전체 키보드 탐색은 별도 검증 필요. |
| UI · 반응형/상태 표현 | **조건부 통과**. 390px 학생 검색, 1366px 전자칠판, 기간 설정 전체 화면에서 가로 잘림을 확인하지 못했다. 교사 확정은 학생 화면에서 텍스트로 설명된다. | 교사 확정 날짜의 학생 버튼을 숨기고 서버에서도 재제출을 거절한다. | 운영 DB 마이그레이션 전에는 원격 경로에서 보호되지 않음. |

2차 조정에는 숫자 정확 검색, 저장 후 미저장 경고 해제, 배정 변경 없는 분리 방지, 공통 이탈 확인, 새 관리 화면의 스크롤 경로 추가가 포함된다. 가상 데이터의 모바일/데스크톱 전체 화면과 기존 보고서의 28개 캡처를 함께 검토했다. 자동 브라우저 검사는 실제 모바일 기기나 원격 Supabase 검증을 뜻하지 않는다.

## 검증·적용 범위

- `npm test`: 57개 파일·465개 단위 테스트 통과. `npm run typecheck`, `npm run build`, `git diff --check` 통과. `npm run lint`는 통과하되 변경 범위 밖의 기존 경고 7개가 남았다.
- Chrome E2E에서 1인 1역·운영 설정·앱 껍데기 57개 시나리오가 통과했다. 가상 학생 60명 전자칠판·검색, 현재 배정에서 1명 역할 변경, 교사 정정의 학생 재입력 차단, 과거 기간 수정·삭제를 포함한다.
- `tests/server/classroomRoles.test.ts`, `tests/server/classroomRolesSql.test.ts`는 Deno 전용이다. 이 환경에 Deno 실행 파일이 없어 실행하지 못했다. SQL은 로컬 DB에서 검증됐다고 주장하지 않는다.
- 새 마이그레이션은 `202609280200_classroom_role_period_edits.sql`, `202610010001_classroom_role_teacher_record_priority.sql`이다. 2026-10-01 운영 DB 이력에서 전자는 이미 적용된 상태였고, 후자만 dry-run 목록을 확인한 뒤 적용했다. 적용 후 두 번호가 모두 원격 이력에 기록된 것을 확인했다. `classroom-roles-admin`, `classroom-roles-public` 함수도 이름을 지정해 각각 배포했다. 웹 프런트엔드와 운영 화면 검증 결과는 별도로 확인한다.
- 원본 기간 수정 워크트리는 다른 작업 소유라 앱의 보관·종료 기능이 거절됐다. 수정 파일은 이 브랜치로 옮겼고 원본 워크트리는 손상 없이 남아 있다.
