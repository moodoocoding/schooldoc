# 1인 1역 여섯 기능의 교사·학생 워크플로우 재검토 (codex)

## 결론

첫 배정과 오늘 실천 입력은 완료할 수 있다. 그러나 학기 중 전입·일부 역할 변경·과거 기록 정정을 이어서 수행하면 현재 구조의 한계가 드러난다. 여섯 기능 자체는 필요하지만, 모두 독립된 진입 메뉴일 필요는 없다. 특히 배정과 역할 교체, 오늘 실천판과 실천 기록은 같은 업무 안에서 연결하는 것이 적절하다.

이번에는 운영 설정을 포함한 여섯 기능을 네 가지 연속 업무로 재검토했다. 아래 표에서 완료, 막힘, 미검증을 구분한다. 모든 예외 상황이나 운영 서버까지 검증했다는 뜻은 아니다. 제품 코드는 수정하지 않았고, 개선안은 아직 구현하지 않았다.

## 검토 범위와 방법

- 검토일: 2026-10-01, Asia/Seoul. 기준 코드는 `main`의 `024b2ec`다.
- 실제 설치된 Google Chrome에서 교사와 학생 화면을 조작했다. 소스는 관찰 원인과 화면 연결을 확인하는 보조 근거로 사용했다.
- 독립 로컬 데모 `http://127.0.0.1:4188`에서 수행했다. Supabase 연결 변수를 비우고 데모 모드를 사용했으며, 운영 계정·원격 DB·실제 학생 자료는 변경하지 않았다. 포트 설정 파일도 수정하지 않았다.
- 교사·교실 표시: 1366×900 CSS viewport. 학생·일부 교사 화면: 390×844 CSS viewport. 실물 휴대전화나 전자칠판 시험은 아니다.
- 가상 학생 24명으로 시작했다. 1번·3번은 같은 이름 `가상하늘`, 24번은 `가상긴이름학생테스트`다. 전입생 25번을 추가했고, 별도 미확정 초안에서 60명·정원 부족·학생 검색을 확인했다.
- 기본 역할 목록은 18개다. 실제 사용자 학급의 역할 개수를 추측하지 않았다. 첫 기간에는 12개 역할에 24명, 다음 기간에는 13개 역할에 25명을 배정했다.
- `pro/web-designer.md`, `pro/ux-designer.md`, `pro/ui-designer.md`를 읽었다. 아래 세 프로파일 및 여섯 관점 평가는 AI의 모의 검토다. 실제 전문가 6명, 담임, 학생의 인터뷰·승인·사용성 시험은 아니다.
- 전체 화면 캡처 28개를 남겼다. 좁은 영역의 기능 확인만으로 화면 밀도·반응형 검토를 대신하지 않았다.

최초 검토는 운영 설정의 기간 변경과 학기 중 변경을 충분히 다루지 못했다. [이전 보고서](../2026-10-01-classroom-roles/review.md)는 부분 검토 이력으로 보존하고, 전체 업무 구조 판단은 이 문서를 기준으로 한다.

## 우선 개선해야 할 문제

이 문서의 P1은 필요한 업무를 화면에서 완료할 수 없는 문제, P2는 반복 불편·상태 혼동·기록 정책 위험이다. 서버 장애나 개인정보 유출이 재현됐다는 의미가 아니다.

### W1 · P1 · 현재 배정의 중간 변경 경로가 없다

교사가 역할 목록에서 이름을 바꾸고 공통 명단에 25번 전입생을 추가해도 현재 실천판은 24명·이전 역할명을 유지한다. 저장된 기간의 스냅샷을 보존하는 동작 자체는 타당하지만, 교사에게 필요한 다음 행동이 제공되지 않는다. 실천판의 `역할 설정`을 누르면 현재 배정 수정이 아니라 다음 11월 배정 준비 화면으로 간다.

- 근거: [역할 설정 이동](evidence/12-role-settings-opens-new-period.jpg), [공통 명단 25명](evidence/16-new-student-common-roster.jpg), [다음 기간 25명](evidence/17-rotation-roster-next-day.jpg). `RoleAssignmentPage.tsx`는 기존 기간의 배정을 직접 수정하는 대신 새 기간과 빈 배정을 준비한다.
- 영향: 한 학생의 전입이나 두 학생의 역할 교환에도 현재 기간 종료일 변경과 다음 기간 전원 배정을 해야 한다. 학생 추가와 역할 변경을 저장했으니 현재 학급에 적용됐다고 오해하기 쉽다.
- 수정 요구: `현재 배정 변경`과 `다음 기간 준비`를 명확히 구분한다. 기존 기록을 덮어쓰지 않고 적용일을 정해 변경 이력을 남기는 구조를 검토한다. 새 기간 분리 방식을 유지한다면 기존 배정을 가져와 바뀐 학생만 수정할 수 있게 한다.
- 재검증: 전입·전출·한 역할 교환·역할 이름 변경 각각에서 이전 날짜의 역할과 기록을 보존하고, 적용일 이후만 변경되어야 한다. 기간 중간 변경 정책은 구현 전에 확정해야 한다.

### W2 · P1 · 운영 기간 수정·삭제 요청이 현재 main에 반영되지 않았다

확정된 현재 기간은 시작일이 비활성화돼 있고, 종료일의 최솟값은 오늘이다. 기간 삭제 버튼도 없다. 확정 전 과거 시작일 입력과 확정 후 기간 수정은 서로 다른 기능이다.

- 근거: [운영 설정 전체](evidence/13-start-date-disabled-no-delete.jpg). 종료일을 10/31에서 10/1로 단축한 뒤 저장·새로고침해 유지되는 것은 별도로 확인했다.
- 별도 작업 확인: `codex/fix/classroom-role-period-settings` 브랜치의 다른 워크트리에 과거 기간 선택·날짜 수정·기록 없는 기간 삭제 작업 파일이 있다. UI/API diff에는 기록 날짜를 기간 밖으로 밀어내지 않는 제한이 있다. 해당 작업은 이번 기준 main에 병합되지 않았다. 서버·마이그레이션까지 이번 검토에서 재검증한 것은 아니다.
- 수정 요구: 동일 기능을 새로 중복 구현하지 말고 기존 작업부터 검토·통합한다. 기간 선택을 배정 관리와 연결하고, 수정 가능 범위·기록 존재 시 삭제 제한·실패 후 입력 유지·삭제 확인을 명확히 한다.
- 재검증: 과거·현재·미래 기간, 기록 없는 기간, 기록 있는 기간, 겹치는 날짜를 각각 확인한다. 삭제는 테스트용 자료와 승인된 환경에서 수행한다.

### W3 · P1 · 과거 기록의 정정 링크가 오늘 화면으로 이동한다

9월 학생 상세에서 `실천판에서 기록 정정`을 누르면 학생 선택과 9월 날짜를 잃고 오늘의 실천판으로 이동한다. 학생을 다시 찾더라도 그 화면에서 정정할 수 있는 날짜는 오늘이다.

- 근거: [9월 상세](evidence/20-past-record-detail.jpg) → [오늘 전체 실천판](evidence/21-history-context-lost.jpg). `RoleHistoryPage`의 링크는 `/board`만 전달하고, 연결된 `RolePracticeBoardPage`는 오늘 기록을 정정한다.
- 코드 구분: `RoleRecordPages.tsx`에 날짜를 선택하는 이전 `RolePracticePage` 구현은 남아 있지만 현재 workspace 라우팅에 연결되지 않았다. 그 구현이 존재한다는 이유로 현재 사용자에게 과거 정정이 제공된다고 볼 수 없다.
- 수정 요구: 학생·날짜·기간을 유지한 정정 대화상자를 기록 상세에서 연다. 별도 페이지가 필요하면 같은 맥락을 URL로 전달하고 돌아왔을 때 조회 조건을 보존한다.
- 재검증: 과거 미기록·했어요·못했어요·해당 없음 각각의 정정, 집계 갱신, 출처 표시, 뒤로가기 상태를 확인한다.

### W4 · P2 · 학생에게 할 일이 표시되지 않는다

역할 `수업 자료 나눔이`에 `수업 전 학습지를 친구들에게 나눠 주세요.`를 저장했지만 학생 상세에는 역할명·주간 실적·했어요/못했어요만 보인다.

- 근거: [학생 상세](evidence/09-student-task-description-missing.jpg). 공개 상세 화면에서 역할 설명을 렌더링하지 않는다.
- 수정 요구: 역할명 바로 아래 실제 할 일을 표시하고, 오늘 입력을 다음에 배치한다. 주간 실적은 낮은 위계로 둔다. 설명이 없는 역할에 불필요한 긴 안내를 추가하지 않는다.
- 재검증: 처음 맡은 역할, 긴 설명, 모바일에서 할 일을 읽은 뒤 기록할 수 있어야 한다.

### W5 · P2 · 학생이 교사 면제 처리를 덮어쓸 수 있다

교사가 5번을 `해당 없음`으로 정정하면 학생에게도 해당 없음이 표시된다. 그러나 했어요/못했어요는 활성화돼 있고, 학생이 했어요를 누르면 교사의 면제 대신 학생 자기보고가 반영되며 집계 분모도 다시 늘어난다.

- 근거: [교사 정정](evidence/10-teacher-exempt.jpg), [학생 재입력 후](evidence/11-student-overrides-exempt.jpg). 같은 날짜·학생 기록을 교체하는 데모 동작과 일치한다. 운영 서버에서 실행한 결과는 아니다.
- 수정 요구: 교사 정정의 최종성부터 정한다. 면제는 학생 재입력을 막거나, 자기보고와 교사 판정을 분리해 집계 기준을 명확히 한다. 학생의 정상적인 자기보고 수정까지 일괄 금지하지 않는다.
- 재검증: 학생→교사, 교사→학생, 동시 입력, 면제 취소에서 최종 표시·집계·출처가 일치해야 한다. 정책 변경 시 공개 서버 검증도 맞춰야 한다.

### W6 · P2 · 저장하지 않은 설정 변경을 잃는다

운영 설정의 제목을 임시 값으로 바꾸고 저장 없이 홈으로 이동한 뒤 돌아오면 경고 없이 이전 값으로 돌아온다. 이전 부분 검토에서는 역할 목록 변경에서도 같은 문제를 재현했다. 반면 배정 초안에는 이탈 확인 코드가 있어 화면마다 보호 수준이 다르다.

- 수정 요구: 설정·역할 편집의 저장 상태를 표시하고 미저장 이탈 보호를 맞춘다. 긴 역할 목록은 하단 저장 버튼만 찾게 하지 않는다.
- 재검증: 내부 링크·뒤로가기·새로고침에서 저장/폐기 선택을 확인한다. 배정 초안의 실제 이탈 확인은 브라우저 제어 중단으로 최종 취소·복귀 결과까지 검증하지 못했다.

### W7 · P2 · 교사용 보기와 학생용 화면의 용어·진입이 겹친다

교사 실천판의 `학생 화면`은 교사용 학생 카드 모드이고, 외부 학생용 공용 화면과 다르다. `전체 보기`는 주간 표 모드이며 교실 전자칠판 표시가 아니다. 공용 링크·QR 영역이 실천판 상단을 차지해 반복 조회 때 표의 첫 화면 높이도 줄어든다.

- 근거: [교사 표](evidence/22-class-display-fit.jpg), [교사 카드 전체](evidence/27-teacher-cards-desktop.jpg). 파일명 `22-class-display-fit.jpg`와 달리 이 캡처는 교사 표 화면이다.
- 수정 요구: 교사용 전환은 `주간 표 / 학생별`로, 외부 액션은 `학생용 링크 / 교실 표시 / 게시판 안내문`으로 구분한다. 공유 도구는 찾기 쉬운 버튼으로 열고 일상 기록보다 위계를 낮춘다. QR 이미지 저장 기능은 유지한다.

### W8 · P2 · 교실 표시와 큰 명단은 별도 밀도 기준이 필요하다

24명 교실 표시는 1366×900에서 다섯 열이며 마지막 행이 첫 화면 아래에 있다. 문서 높이는 약 986 CSS px이다. 전체 화면 버튼의 실물 전자칠판 결과는 시험하지 않았으므로 모든 교실에서 잘린다고 단정하지 않는다. 학생 공용 명단에서는 학생 찾기 검색을 찾을 수 없었다.

- 근거: [교실 표시 viewport](evidence/23-class-display-viewport.jpg), [교실 표시 전체](evidence/24-class-display-full.jpg), [학생 모바일 명단](evidence/08-student-mobile-list.jpg).
- 경계 시험: 60명 모바일 배정 초안은 정원 36명 대비 24자리 부족을 표시하고 확인을 막는다. 학생 검색은 제공된다. 정원을 늘린 뒤 60번을 검색·배정할 수 있었다. 가로 넘침은 없었지만 긴 세로 화면이 된다. [60명 초안](evidence/25-sixty-student-draft-mobile.jpg), [정원 복구·검색](evidence/26-capacity-recovery-and-search-mobile.jpg).
- 수정 요구: 교실 표시는 학생 수와 화면 크기에 맞춘 가독성 있는 밀도 또는 페이지 전환을 제공한다. 학생 화면은 번호·이름 탐색을 보조한다. 배정 화면의 기존 검색을 재사용할 수 있다.
- 한계: 60명 기간 전체 확정과 공개·교실 화면 60명 표시는 실행하지 않았다. 작은 글자로 억지로 한 화면에 넣는 방식은 권하지 않는다.

| --- | --- | --- | --- |
| 학생 역할 배정 | 명단·기간·정원 확인과 배정 확정 | 필요 | 배정 관리의 최초·현재 배정 |
| 역할 교체 | 이전 역할 참조, 다음 기간 준비 | 기능은 필요하나 배정과 같은 화면을 반복함 | 배정 관리의 `다음 기간 준비` 액션 |
| 운영 설정 | 실천 요일·제외일·공용 화면·입력 중지 | 필요. 기간 관리는 배정 업무와 가까워야 함 | 운영 설정, 기간 편집은 배정 관리와 연결 |

├─ 실천 현황   [오늘·주간] [기록]

자동 역할 교환을 강제하거나 현재 기록을 덮어쓰자는 제안은 아니다. 교사는 기존 배정을 유지하거나 바꿀 수 있어야 하고, 학생에게 적용되는 날짜가 분명해야 한다.

## 검증 결과와 한계

- `npm test -- tests/unit/classroomRoles.test.ts tests/unit/classroomRolesPeriodEditing.test.ts`: 2개 파일, 20개 테스트 통과. 규칙 단위 테스트 통과는 위 워크플로우 문제 해결이나 운영 화면 검증을 뜻하지 않는다.
- Chrome 교사·학생 탭의 로컬 출처 콘솔 기록에서 오류는 보이지 않았다. 의도적으로 Supabase를 비운 데모 환경의 미설정 경고는 있었다. 콘솔 수집 구간 밖까지 오류가 없다고 단정하지 않는다.
- 새 자동 E2E, typecheck, lint, build는 실행하지 않았다. 이번 변경은 보고서·증거 파일뿐이며 제품 소스를 수정하지 않았다. Chrome 실제 조작과 자동 E2E를 혼동하지 않는다.
- 모든 사용자는 같은 Chrome 프로필·로컬 origin의 데모 저장소를 사용했다. 다른 기기 간 동기화, 실제 Google 로그인, 원격 RLS·권한·공개 서버 검증이 아니다.
- 배정 초안의 내부 링크 이탈 확인 중 브라우저 제어가 멈춰 해당 시험 탭을 닫고 새 탭에서 검토를 이어갔다. 확인창 취소·저장 유지의 최종 결과는 미검증이다. 제어 중단 자체를 제품 결함으로 집계하지 않았다.
- 운영 기간 삭제는 화면 경로가 없어 수행하지 못했다. 공용 링크 재발급, 영구 삭제, 실제 날짜 전환, 실물 모바일·전자칠판, 200% 확대, 스크린리더, 오프라인·서버 실패·동시 입력도 미검증이다.
- 이전 부분 검토의 안내문·QR PNG 저장 근거는 이전 보고서에 있다. 이번 재검토에서 해당 다운로드를 새로 실행한 것은 아니다.

## 다음 개발 순서와 완료 기준

1. 기존 기간 수정 브랜치와 main 차이를 먼저 검토한다. 기록 보호·삭제 정책·마이그레이션 호환성을 확인해 중복 개발 없이 통합할 범위를 정한다.
2. 배정 관리에서 현재 변경과 다음 기간 준비를 구분한다. 이전 배정을 가져와 전입생·일부 역할만 바꾸고, 적용일 이전 기록이 보존되는지 검증한다.
3. 기록 상세 안에서 학생·날짜를 유지한 과거 정정을 제공한다. 교사 정정과 학생 자기보고의 우선순위를 확정하고 화면·데모·서버를 일치시킨다.
4. 학생 할 일 표시, 미저장 보호, 보기 명칭, 명단 탐색을 개선한다. 네 메뉴 구조는 기능을 보존하는 시안으로 먼저 확인한다.
5. 대표 24·25명과 큰 명단, 긴 이름·동명이인, 미기록·완료·면제·제외일, 현재·미래·과거 기간을 Chrome에서 재시뮬레이션한다. 전체 화면을 여섯 모의 관점으로 평가하고 2차 수정까지 검증한다.
6. 코드 변경 범위에 맞는 타입·lint·단위·E2E를 실행한다. 원격 시험 자료·환경을 확인한 후 실제 서버 경로를 별도로 검증하고, 데모 통과와 운영 통과를 분리해 보고한다.

기능별 버튼을 눌렀다는 이유로 완료 판정하지 않는다. 새 학급 준비, 일상 입력, 학기 중 변경, 과거 정정, 다음 기간 전환 각각의 목표를 끝까지 수행하고 저장·조회·이전 기록 보존까지 확인해야 한다.

현재 main 기준 독립 로컬 데모에서 가상 24명 학급을 준비하고 전입생을 포함한 25명 다음 기간까지 확정했다. 운영 설정의 실제 수정 범위, 현재/미래 배정 적용 범위, 과거 정정 경로, 교사 면제 재입력, 입력 중지·재개, 60명 미확정 초안의 정원 회복을 확인했다. 증거 28개와 메뉴 구조·휴리스틱·여섯 모의 관점 평가를 작성했다. 단위 테스트 20개 통과. 코드·원격 DB·Git 커밋·push·병합·배포는 하지 않았다.

공유 개발일지는 저장소 밖 `schooldoc-docs/development-history.md`에 있다. 이번 작업의 쓰기 허용 경로 밖이므로 그 파일은 수정하지 않았으며, 이 절에 검토 기록을 남겼다.
