# 1인 1역 실제 Chrome 워크플로우·휴리스틱 검토 (codex)

> 범위 정정: 이 문서는 최초 부분 검토다. 운영 설정의 기간 수정·삭제, 학기 중 명단·배정 변경을 충분히 다루지 못했으며 여섯 기능 전체의 완료 보고가 아니다. 이후 [연속 업무 재검토](../2026-10-01-classroom-roles-workflow/review.md)에서 해당 범위와 과거 정정 경로를 추가 확인했다. 아래 내용은 당시 관찰 이력으로 보존한다.

## 결론

24명 가상 학급으로 교사의 최초 배정 → 학생의 실천 기록·수정 → 교사 정정 → 월별 조회 → 다음 달 역할 교체를 실제 Google Chrome에서 수행했다. 기본 흐름은 완료할 수 있었지만, 역할 이해·정정의 의미·학생 재탐색·변경 유실에서 개선이 필요하다. 기능 테스트 통과를 사용성 합격으로 보지 않는다.

이번 작업은 **검토만** 수행했다. 제품 코드 수정, Git 커밋·push·main 병합, Supabase 변경, 운영 배포는 하지 않았다. 개선안은 미구현이다.

## 1. 범위와 근거

- 날짜: 2026-10-01, Asia/Seoul. 기준: `main`의 `024b2ec`.
- 실제 설치된 Google Chrome을 제어했다. 화면 캡처와 접근성/DOM 상태로 결과를 확인했고 소스는 관찰 원인의 보조 근거로 사용했다.
- 서버: `http://127.0.0.1:4187`. Supabase URL·anon key를 비워 두고 `VITE_CLASSROOM_ROLES_DEMO_MODE=true`로 실행한 독립 로컬 데모다. 실제 계정·학생 자료·원격 DB는 변경하지 않았다.
- 교사: 1366×900 CSS viewport. 학생과 교사 모바일: 390×844 CSS viewport. 휴대전화 화면은 Chrome의 viewport 재현이며 실물 Android/iPhone 시험이 아니다. 캡처의 픽셀 크기와 CSS viewport는 다를 수 있다.
- 가상 학생 24명: 1번·3번은 같은 이름 `가상하늘`, 24번은 `가상긴이름학생테스트`. 기본 역할 목록은 **18개**, 정원 각 2명이다. 최초 배정과 다음 달 배정은 각 12개 역할에 2명씩 배정했다. 사용자의 실제 학급 역할 수를 가정하지 않았다.
- 빈 상태, 미기록, 했어요, 못했어요, 교사 해당 없음, 공통 실천 제외일, 미래 배정, 동명이인, 긴 이름을 확인했다.
- 참고 프로파일: `pro/web-designer.md`, `pro/ux-designer.md`, `pro/ui-designer.md`를 읽고 검토했다. 아래 평가는 AI의 모의 관점이며 실제 전문가·교사·학생 인터뷰나 사용성 시험이 아니다.

Chrome 자동화 CLI가 연결 후 일부 명령에서 응답하지 않아 연결된 Chrome 탭 제어로 전환했다. 잘못된 선택자·날짜 입력·다운로드 이벤트 대기 실패를 제품 결함으로 집계하지 않았다. QR 저장은 이벤트 대기가 끝났다는 추정 대신 실제 생성된 PNG로 확인했다.

## 3. 개선 항목

우선순위는 이번 검토의 제안이다. P1은 기록·업무 신뢰를 크게 훼손하거나 완료를 막는 문제, P2는 반복적인 불편·판단 혼동, P3는 경미한 표현 개선으로 정의한다. 이번에는 P1 장애를 확정하지 않았으며 P2 개선 6건을 확인했다.

### F1 · P2 · 학생에게 실제 ‘할 일’이 보이지 않는다

- 재현: 교사 역할 목록에는 `책 깔끔이`의 할 일 `학급 문고의 책을 정리해요.`가 있다. 학생이 해당 역할을 열면 역할명·주간 실적·했어요/못했어요만 보인다.
- 영향: 역할을 처음 맡은 학생은 무엇을 한 뒤 기록해야 하는지 교사에게 다시 물어야 한다. 기록 화면이 행동 안내보다 자기보고를 앞세운다.
- 근거: [학생 상세](evidence/student-task-detail-viewport.jpg). `PublicClassroomRolesPage.tsx`는 상세에서 `student.role.description`을 표시하지 않는다. 공통 공개 projection은 이미 description을 제공하므로 데이터 부족은 아니다.
- 개선 요구: 역할명 아래 할 일을 표시하고 그 아래 오늘 입력을 둔다. 설명이 비어 있을 때 장황한 대체 안내를 만들지는 않는다. 주간 실적은 행동 안내보다 낮은 위계에 둔다.
- 휴리스틱: 현실과의 일치, 기억보다 인식, 도움·안내.
- 재검증 기준: 새 역할을 맡은 학생이 별도 교사 설명 없이 할 일을 읽고 기록할 수 있어야 한다. 긴 설명·작은 모바일에서도 행동 버튼을 찾을 수 있어야 한다.

### F2 · P2 · 교사 정정과 학생 자기보고의 우선순위가 불분명하다

- 재현: 교사가 2번 학생을 `해당 없음`으로 바꾼다. 학생 화면에서는 `오늘 해당 없음`이지만 했어요/못했어요 버튼이 활성화된다. 했어요를 누르면 1/1일로 바뀌고 교사 정정 대신 학생 자기보고가 남는다.
- 영향: 결석·면제 처리라고 이해한 교사와 계속 자기보고할 수 있다고 이해한 학생이 서로 결과를 덮어쓸 수 있다. 교사 화면의 ‘실천일 아님’과 학생 화면의 입력 가능 상태도 다르게 느껴진다.
- 근거: [교사 정정](evidence/teacher-exemption-desktop.jpg) → [학생에게 보인 해당 없음](evidence/student-teacher-exemption.jpg) → [학생 재입력 후](evidence/student-overwrote-exemption.jpg).
- 원인 보조 근거: 데모 `writeRoleRecord`는 같은 기간·학생·날짜 기록을 교체한다. 서버 경로와 저장소의 `write_classroom_role_record` SQL도 같은 키에서 status/source를 갱신하며 기존 교사 source를 잠그는 조건이 없다. **운영 DB에서 이 시나리오를 실행한 것은 아니다.**
- 개선 요구: 교사 정정이 최종값인지, 학생 자기보고와 별도 값인지 먼저 결정한다. 면제 잠금 또는 자기보고/교사 판정 분리 중 정책을 선택하고 화면·서버·데모를 맞춘다. 학생의 정상적인 자기보고 재수정까지 일괄 금지하지 않는다.
- 휴리스틱: 시스템 상태 가시성, 일관성, 오류 예방.
- 재검증 기준: 면제·했어요·못했어요 각각에서 교사/학생 수정 순서와 최종 표시·집계·출처를 확인한다.

### F3 · P2 · 역할 수정 중 이탈하면 변경이 경고 없이 사라진다

- 재현: 역할 1 이름을 `가상 수정 중 칠판 도우미`로 바꾼 뒤 저장하지 않고 홈으로 이동한다. 경고 없이 이동하며 다시 열면 `칠판 도우미`다.
- 영향: 역할 이름·설명을 여러 개 편집하는 교사가 저장을 잊으면 작업을 다시 해야 한다. 저장 버튼은 긴 역할 목록의 마지막에 있다.
- 근거: [이탈 전](evidence/role-unsaved-before.jpg), [복귀 후](evidence/role-unsaved-after.jpg). 현재 페이지 상태만 보관하고 이탈 확인이나 초안 복구가 없다.
- 개선 요구: 저장되지 않은 변경 표시와 안전한 이탈 확인/초안 복구를 제공한다. 저장 위치를 쉽게 찾도록 하되 새 플로팅 메뉴를 무조건 추가하지 않는다.
- 휴리스틱: 사용자 통제·자유, 오류 예방, 오류 복구.
- 재검증 기준: 내부 링크 이동·뒤로가기·새로고침에서 변경 보호를 확인하고, 저장한 경우 불필요한 경고가 없어야 한다.

### F4 · P2 · 기록 상세에서 정정으로 이동할 때 학생 맥락을 잃는다

- 재현: 실천 기록에서 3번의 상세를 연 뒤 `실천판에서 기록 정정 →`을 누르면 학생 선택이 없는 전체 실천판으로 이동한다.
- 영향: 방금 확인한 학생을 다시 찾아 눌러야 한다. 월별 기록과 정정 업무가 하나의 흐름으로 연결되지 않는다.
- 근거: [상세](evidence/student-record-detail.jpg), [이동 후 전체 실천판](evidence/record-correction-context-lost.jpg). `RoleRecordPages.tsx`의 링크는 `/tools/classroom-roles/board`만 전달한다.
- 개선 요구: 선택 학생과 정정할 날짜를 유지한 화면으로 연결하고 돌아왔을 때 조회 월·학생을 복원한다. 과거 날짜 정정은 별도 정정 화면/기존 기능과 연결하고 오늘 정정으로 조용히 바꾸지 않는다.
- 휴리스틱: 기억보다 인식, 효율성, 사용자 통제.
- 재검증 기준: 동명이인·교체 전후·과거 월에서도 원래 학생·날짜를 유지해야 한다. 과거 날짜는 이번 Chrome 시나리오에서 직접 정정하지 않았다.

### F5 · P2 · 학생 찾기와 교사 모바일 현황에 반복 탐색 부담이 있다

- 학생 재현: 390×844 화면에서 24명은 두 열이다. 첫 카드는 y=96, 24번 카드는 y=1636이며 전체 문서 높이는 1784 CSS px다. 이름/번호 검색 입력은 없다. 역할명이 가장 크고 이름은 작아서 자기 이름을 찾을 때 보조 정보처럼 보인다.
- 교사 재현: 모바일 전체 실천판은 공유 주소·QR 블록 다음에 24명의 주간 카드가 세로로 이어지며 전체 높이 4031 CSS px다. 이미 QR을 배포한 교사도 현황을 보려면 공유 영역을 지난다.
- 영향: 뒤쪽 번호 학생은 기록 전에 스크롤을 반복한다. 교사는 특정 학생/미기록 학생을 확인하는 작업이 명단 크기에 비례해 길어진다. 처음 기록한 이름을 개인 기기에 기억할지는 공용 기기와 구분해야 한다.
- 근거: [학생 전체](evidence/student-entry-mobile.jpg), [교사 모바일 전체](evidence/teacher-board-mobile.jpg).
- 개선 요구: 학생 입력 모드에서는 이름·번호 탐색을 우선하고 가벼운 검색/번호 찾기를 검토한다. 교사 현황에는 학생 찾기·미기록 등 목적별 필터를 두고 공유 영역은 접거나 별도 동작으로 분리한다. 전자칠판의 역할 우선 위계는 별도로 유지할 수 있다.
- 휴리스틱: 효율성, 기억보다 인식, 미니멀 디자인.
- 재검증 기준: 24명·60명, 동명이인·긴 이름, 개인/공용 기기에서 비교한다. **60명은 이번에 실제 실행하지 않았다.**

### F6 · P2 · 전자칠판에서 전체 학생의 첫 화면 가시성이 부족하다

- 재현: 1366×900, 학생 24명, display 모드의 5열 카드에서 문서 높이 986 CSS px, 마지막 카드 하단 y=966이다. 첫 화면에 마지막 줄 전체가 들어오지 않는다.
- 영향: 교사가 학급 전체 역할을 한 번에 보여 주는 상황에서 스크롤이 필요하다. 일반 모바일 입력 화면의 카드 크기와 교실 표시의 밀도 목표가 다르다.
- 근거: [전자칠판 전체](evidence/electronic-board-desktop.jpg). 이 캡처에는 로컬 데모 안내도 포함되어 있다. 실제 전자칠판 하드웨어/전체 화면 모드에서의 높이는 별도 검증이 필요하다.
- 개선 요구: 표시 전용 화면은 인원·열·높이에 따른 밀도 선택이나 페이지 분할을 제공한다. 교사용 화면에서 표시 모드 진입도 쉽게 찾게 한다. 글자를 무조건 작게 하거나 고정 높이+중첩 스크롤로 해결하지 않는다.
- 휴리스틱: 사용 맥락과의 일치, 효율성, 상태 가시성.
- 재검증 기준: 24/30/60명, 1366×768·1920×1080, 실제 교실 화면에서 읽기 거리와 전체 가시성을 비교한다.

## 4. 잘 작동한 사용자 경험

- 번호 중복·미배정·정원 초과를 확정 전에 막고, 입력을 유지해서 복구할 수 있다.
- 배정 확정 전 학생과 기간을 전체 확인할 수 있다. 역할 이동도 바로 실행하지 않고 확인한다.
- 동명이인을 번호로 구분한다. 긴 이름은 확인한 화면에서 줄바꿈되어 잘리지 않았다.
- 학생 상세에서 Escape로 닫은 뒤 해당 카드로 포커스가 돌아온다. 상태는 O/X/—/·와 설명으로 구분하며 색만 사용하지 않는다.
- 학생 기록 저장 후 상태 메시지와 이번 주 집계가 바뀐다. 공통 제외일에는 입력을 제공하지 않는다.
- 역할 교체에서 명단을 재입력할 필요가 없고 이전 역할을 참조할 수 있다. 미래 배정이 현재 역할과 기록을 바꾸지 않는다.
- 학생 공용 명단에서 오늘 상태는 기본 비공개이고, 표시 모드는 이름을 마스킹한다. 이는 본인 인증이 아니며 설정에도 공용 링크의 다른 학생 선택 가능성을 안내한다.
- 게시판 안내문은 20칸·기간·학생·QR을 한 정보 구조로 제공한다. 화면 미리보기와 실제 PNG 저장은 확인했다. 인쇄된 PDF와 실물 QR 스캔은 미확인이다.

## 7. 검증과 한계

- 실행: `npm test -- tests/unit/classroomRoles.test.ts tests/unit/classroomRolesPeriodEditing.test.ts` → **2개 파일, 20개 검사 통과**. Chrome의 실제 사용자 흐름 관찰과 별개인 기존 규칙 검사다.
- 확인한 앱 출처의 콘솔에서는 의도적으로 연결을 끈 Supabase 안내 경고가 있었고 앱 오류는 발견하지 않았다. 브라우저 확장의 외부 통신 오류는 제품 오류에서 제외했다.
- QR 저장은 다운로드 이벤트 감지가 시간 초과됐으나 같은 시각 생성된 파일의 1024×1024 PNG를 확인했다. [파일 근거](evidence/qr-downloaded.png). 따라서 다운로드 결함으로 분류하지 않았다.
- 날짜/month 입력을 자동화로 바꾸려는 일부 시도는 실제 값이 바뀌지 않아 성공·제품 실패 어느 쪽으로도 판정하지 않았다. 현재 main의 시작일 잠금·지난 날짜 제한·기간 삭제 부재는 [운영 설정](evidence/operation-settings.jpg)에서 관찰했다. 별도 기간 수정 작업과 중복 여부를 먼저 확인해야 한다.
- 미실행: 원격 Supabase Auth/RLS/RPC 실제 저장, 네트워크 장애·동시 교사 쓰기, 학교 공유 IP 부하, 전체 Playwright E2E, 실물 모바일/전자칠판, 스크린리더·axe·실제 200% 확대, 60명 명단, 실제 PDF 인쇄/QR 스캔, 실제 사용자 사용성 시험.
- 제품 코드·의존성·빌드 설정을 바꾸지 않아 typecheck/lint/build 전체 재실행은 하지 않았다. 포트 설정 파일을 수정하지 않았다.
- 외부 공용 개발일지는 현재 checkout의 `docs` 링크로 연결되어 있지 않고 쓰기 허용 범위 밖이다. 다른 기능 일지를 덮어쓰거나 과거 이력을 만들지 않고 이 검토 문서에 완료 내용과 남은 검증을 기록했다.

## 8. 다음 개발 제안

1. F2의 교사 정정 정책을 결정하고 클라이언트·서버·데모의 의미를 맞춘다.
2. F1 할 일 표시, F3 변경 보호, F4 학생·날짜 맥락 유지부터 수정한다.
3. F5 입력/현황의 학생 탐색과 F6 표시 모드 밀도를 목적별로 개선한다.
4. 24명·60명, 동명이인·긴 이름, 미완료/완료/면제 상태의 전체 화면을 다시 평가한다. 관련 회귀 검사와 원격 계약 검증은 별도 범위를 확인한 뒤 실행한다.

그 뒤 기존 기능별 검토 순서인 학생 결과 안내 → 가정통신문 수합 → 등록부 서명 → 자료 수합 → 특별실 예약으로 이어간다. 이번 검토를 해당 기능들의 완료로 간주하지 않는다.
