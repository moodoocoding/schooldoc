# 가정통신문 수합 교사·보호자 워크플로우 검토 (codex)

## 결론

가상 PDF로 원본 업로드 → 필드 추가 → 수신자·공유 설정 → 보호자 모바일 응답 → 교사 결과 확인·PDF 내려받기를 연결했다. 기본 기능과 ‘아니오’ 응답의 단일 선택 규칙은 동작한다. 그러나 **처음 쓰는 교사가 필드를 추가만 하고 원본 칸에 배치하지 않아도 수합을 만들 수 있다.** 이 경우 보호자는 제출 전 요약에서 ‘아니오’를 확인하지만, 실제 결과 PDF에는 원본 ‘아니오’ 칸이 비어 있고 엉뚱한 위치에 체크가 찍힌다. 이는 답변 계산 오류가 아니라 발행 전 배치 검수의 부재다.

이번 요청은 검토다. 제품 코드·서버·DB·운영 데이터·Git 배포는 바꾸지 않았다. 아래 개선 요구는 구현 완료가 아니다.

## 우선 수정할 사항

### C1 · P1: 필드가 원본과 어긋나도 발행된다

필드 추가는 원본 빈칸을 찾는 동작이 아니다. `ConsentFieldEditor.tsx:96-124`는 겹치지 않는 임의 위치를 찾아 놓고, `:92`의 완료 조건은 필드 개수와 필드끼리의 배치 오류만 본다. 이번 재현에서는 체크 두 개와 성명 입력이 원본의 실제 ‘예/아니오’·보호자 성명 칸이 아니라 문서 상단에 놓였지만 단계 3·4를 거쳐 발행했다. [보호자 제출 전 요약](evidence/08-parent-review-mobile.png)은 ‘아니오’라고 정확히 적지만 [결과 PDF](evidence/11-submitted-response.png)의 원본 ‘아니오’ 네모는 비어 있다. 가상 보호자 성명은 학생 이름 행을 덮는다.

필드는 교사가 직접 배치해야 한다는 현재 의도와 결과 PDF 합성 로직을 구분해야 한다. 엔진이 ‘아니오’를 ‘예’로 바꾼 것은 아니다. 문제는 원본 문서와 무관한 초기 위치가 유효 배치처럼 취급되는 것이다.

개선 요구: 필드 추가 직후에는 ‘배치 필요’ 상태를 두고, 원본을 클릭해 위치를 정하거나 이동했음을 확인할 때까지 발행을 막는다. 특히 예/아니오 묶음은 두 칸을 각각 원본 위치에 놓도록 유도한다. 마지막 단계에서 실제 보호자 입력 화면과 결과 PDF에 가까운 1쪽 미리보기를 보여 주고, 교사가 ‘원본의 각 입력칸과 위치를 확인함’을 명시적으로 확인하게 한다. 자동 OCR이 원본 칸을 완벽히 찾는다고 약속해서는 안 된다.

### C2 · P1: 데스크톱 기본 PDF 축척이 정밀 배치에 너무 작다

1440×900 캡처에서 편집 문서는 너비 약 360px이고, 2.4% 체크박스는 화면상 약 9px이다. 오른쪽 설정 패널은 넓지만 가운데 원본은 작은 종이처럼 남아 있어 교사가 실제 네모에 맞춰 끌기 어렵다. `ConsentFieldEditor.tsx:338`의 기본 폭 계산이 뷰포트 높이에 묶여 최소 360px을 택하기 때문이다. [전체 화면](evidence/02-field-editor.png).

개선 요구: 데스크톱 기본값을 작업 영역 너비에 맞춰 더 크게 표시하고, 큰 문서는 문서 스크롤로 이동한다. 축소/확대와 ‘쪽 맞춤’이 실제 화면상의 읽을 수 있는 폭을 가리키도록 한다. 설정 패널과 종이의 열 균형을 다시 확인한다.

### C3 · P2: 편집기의 PDF 표시 완료와 다음 단계가 연결되지 않는다

최초 자동화 캡처 시 편집 원본이 아직 회전 표시 중이어도 `필드 배치 완료`가 활성화돼 있었다. 코드에서 `ConsentPdfPage`의 준비·오류 상태를 편집기 완료 조건에 전달하지 않으며, `canContinue`는 필드 개수·겹침만 확인한다. 따라서 원본을 육안으로 확인하지 못한 상태에서 발행까지 갈 수 있다. 공개 응답 화면은 반대로 모든 페이지가 준비되기 전 입력·제출을 막는다.

개선 요구: 교사 편집 단계도 모든 페이지가 표시되기 전 진행을 막고, 페이지 오류 시 재시도와 행동 가능한 안내를 제공한다. 단순 분석 완료와 시각 확인 완료를 구분한다. 실제 영구 렌더 실패로 발행되는 사례는 이번 검토에서 재현하지 않았다.

### C4 · P2: 모바일 원본 본문이 너무 작다

390px 전체 화면에서는 A4 한 쪽을 가로폭에 맞춘 결과 본문과 원본 체크 문구가 매우 작다. 현재 화면에는 앱 내부 확대·원래 크기 보기 조작이 없다. 보호자는 아래 큰 예/아니오 선택지를 누를 수 있지만, 상단 원본 내용을 제대로 읽어 동의 여부를 판단하기 어렵다. [보호자 모바일 전체 화면](evidence/07-parent-no-mobile.png). 브라우저 손가락 확대의 실제 기기 동작은 미검증이다.

개선 요구: 원본 확대·이동을 명시적으로 제공하고, 질문으로 이동해도 원본의 주변 문맥과 입력값을 유지한다. 특히 긴 실제 가정통신문·2쪽 이상·저학년 보호자 기기에서 읽기→응답→다시 읽기 흐름을 실기기로 시험한다.

## 유지할 점과 기능 중복 판단

- ‘명단으로 받기’와 ‘명단 없이 받기’는 제출 현황을 개인별로 추적할지의 선택이므로 둘 다 필요하다. 수신자 단계는 불필요한 중복 단계가 아니다.
- 응답자 화면은 모든 PDF 쪽이 준비돼야 입력·제출할 수 있고, 오류 시 페이지 재시도 안내가 있다. ‘예/아니오’는 필수 응답이지 반드시 ‘예’에 동의하라는 뜻이 아니며, ‘아니오’만으로 제출할 수 있다.
- 보호자는 이전 질문으로 돌아가 값을 수정할 수 있고 제출 전 요약을 볼 수 있다. 완료 화면과 교사 받은 응답·xlsx·개별/전체 PDF·QR 이미지 저장 경로도 있다.
- 다만 ‘원본 업로드 → 필드 배치 → 수신자 → 공유’ 네 단계의 존재보다, **배치 정확도에 대한 검수 연결이 없는 것**이 핵심이다. 단계를 무조건 합치거나 삭제하기 전에 C1을 해결해야 한다.

## 후속 수정 및 재검토 · 2026-10-01 (codex)

위의 발견 사항을 바탕으로 **제품 코드를 수정했다.** 앞 절의 “이번 요청은 검토”와 검증 수치는 최초 검토 당시의 기록이며, 아래는 후속 요청에 따른 별도 작업 결과다. 실제 교사·보호자·전문가에게 시험이나 승인을 받은 것은 아니다.

### 구현

- 새로 추가하거나 복제한 응답 필드는 `배치 필요` 상태로 시작한다. 교사가 원본 PDF를 클릭하거나 필드를 이동·위치 입력해야 상태가 해제된다. 미배치 필드가 있으면 다음 단계와 발행을 막는다. 기존 저장 필드는 이미 배치된 것으로 간주해 기존 수합의 의미를 유지한다.
- 교사 편집기에서 원본 PDF의 **모든 쪽**이 렌더링돼야 다음 단계로 진행한다. 표시가 실패한 쪽은 재시도할 수 있고, 내부 오류 문자열 대신 일반 안내를 보여 준다. 렌더링 전에는 필드 추가도 막는다.
- 데스크톱 편집기의 기본 문서 폭을 약 794px까지 넓혀 원본 칸과 필드를 나란히 비교하기 쉽게 했다. 텍스트·날짜 필드 기본 높이를 4%로 낮췄으며, 세부 크기는 설정에서 조절할 수 있다.
- 최종 확인 단계에 **원본 PDF와 회색 응답 위치를 겹쳐 보여 주는 미리보기**를 추가했다. 교사가 위치 확인 항목을 체크해야 수합을 만든다. 저장할 때 편집기 내부의 임시 배치 상태는 제거한다.
- 보호자 모바일 원본에 100·150·200% 확대와 손가락·키보드 가로 이동을 제공했다. 질문 간 이동이나 확대 변경 시 이미 입력한 응답을 유지한다. 앱 전체의 세로 스크롤은 문서가 맡고, 확대된 PDF의 가로 이동만 내부에서 처리한다.

## 최신 `main` 통합 및 재확인 · 2026-10-02 (codex)

위 수정은 영수증 브랜치의 미커밋 작업에서 최신 `main`으로 옮겼다. 충돌한 교사 편집기는 `main`의 좌측 도구·우측 원본 구성을 유지하면서 원본 렌더 완료, 새 필드의 배치 대기, 클릭 배치와 완료 차단을 결합했다. 수합 생성은 `main`의 준비 상태 저장 → 명단·비밀번호 원자적 완료 흐름을 유지하고, 최종 발행 필드에서만 임시 배치 속성을 제거한다. 기존 응답을 받은 필드의 의미는 바꾸지 않았다.

1차 통합 화면을 전체 캡처로 보니 390px 보호자 화면은 실제 200% 확대됐지만 600px에서는 원본 안쪽의 최대 너비 때문에 표시 배율보다 작게 보였다. 2차 수정에서 안쪽 최대 너비를 제거하고, 600px에서도 실제 원본 폭이 화면 폭의 1.9배 이상인지 확인했다. 가상 A4 원본의 체크칸과 성명칸 위치에 필드를 배치하는 좌표 검사도 추가했다. 아래 판단은 세 디자인 프로파일을 적용한 **AI 모의 검토**이며 실제 전문가·교사·보호자 검증은 아니다.
