## 실제 운영 확인

평가계획은 사용자가 앞서 제시한 2026학년도 5학년 2학기 PDF(65쪽)를 사용했다. 학생 성적은 직접 만든 3명·2평가의 가상 XLSX이며 실제 학생 정보는 사용하지 않았다. 기존 로그인 세션으로 운영 Supabase와 OpenAI를 호출했고 데모나 API 응답 대체를 사용하지 않았다.

1. PDF 업로드 → 실제 AI 분석 → 10개 교과 목록을 확인했다. 수학의 두 평가를 원문과 대조했다.
2. 두 수학 평가의 내용·성취기준·세 수준 기준이 원문과 일치했다. 최종 화면은 실제 요약 표가 있는 PDF 3쪽을 가리켰다. 중복 표가 있는 24·26쪽 안내도 확인했다.
3. XLSX 시트·두 번째 행 머리글을 선택했다. 3명과 두 평가 열을 누락 없이 읽었고 두 동명이인을 번호로 구분했다.
4. 다른 성적 열에 이미 쓴 평가를 중복 연결하면 진행 버튼이 비활성화됐다. 올바른 두 평가로 다시 연결했다.
5. 2번 학생의 빈 성적은 `확인 필요`로 남았고 진행을 막았다. 가상 시험 자료의 의도된 성적(△)으로 정정한 뒤 진행했다. 자동으로 채우지 않았다.
6. 3명의 서로 다른 수준에 대해 실제 평어 생성·학생별 근거 표시·검토 완료 흐름을 확인했다. 일부 재생성도 실제 서버로 수행했다.
7. 최종 배포에서 처음부터 다시 실행해 `수학_교과평어.xlsx`를 내려받았다. 파일을 다시 읽어 3개 학생 행, 번호 순서, 동명이인, 정정 성적, 7개 열, 평가 근거를 대조했다. 글자 수는 111·104·58자, 바이트는 273·237·144로 코드 계산과 일치했다. 목표 200자에 맞추려고 근거 없는 내용을 덧붙이지 않아 짧은 결과 안내가 표시됐다.
8. 비로그인 HTTP 요청은 운영 게이트웨이에서 401로 차단됐다. 일반 교사·익명 계정 거절과 제한 초과·검사 실패 경로는 단위 검사로 검증했으며 실제 계정을 만들어 시험하지 않았다.

## 실제 시험에서 발견해 수정한 사항

- **잘못된 PDF 쪽 번호**: 최초 AI가 수학 평가를 6·7쪽으로 연결했다. 코드로 PDF 본문을 대조하도록 바꾸고 확인 불가·반복 표 안내 및 쪽 드롭다운을 추가했다. 원본 65쪽 재분석 후 두 항목 모두 3쪽 표시를 확인했다.
- **근거 없는 수준 추정**: 최초 하 수준 평어에 원문에 없는 `어려움이 있으나`가 들어갔고, 상 수준에는 성취기준의 넓은 목표인 `자료 수집`을 추가한 사례가 있었다. 모델 입력에서 등급 및 넓은 성취기준 본문을 빼고 선택된 수행 기준 중심으로 생성하게 했다. 근거 없는 어려움·도움·노력·태도 표현을 추가 검사하며 온점도 정규화한다. 보완 서버의 재생성 및 최종 전체 실행에서 위 표현이 사라진 것을 확인했다. 패턴 검사는 모든 의미상 오류를 막는 보증이 아니다.
- **재배포 전부터 열어 둔 화면의 Excel 모듈 실패**: 검증 도중 재배포 후 기존 탭이 없어진 예전 동적 모듈 주소를 요청했다. 이 기능의 Excel 작성 모듈을 화면과 함께 로딩하게 바꿨다. 최종 배포의 새 탭에서 저장·파일 재읽기를 확인했다. 이미 열려 있던 이전 배포의 탭까지 소급 수정한 것은 아니다.

## 남은 범위

- 관리자 미리보기 권한 유지. 다른 세 기록 기능은 개발 예정이다.
- 실제 학생 자료, 다양한 학교의 병합 머리글·다른 성적 단계, 스캔 성적표의 운영 AI 인식, 실제 휴대폰 운영 로그인, 60명 실제 AI 일괄 생성은 미검증이다. 60명 표시와 모바일 흐름은 모의 E2E로만 확인했다.
- AI 평어는 초안이다. 원본 대조와 교사 검토가 필요하며 사실성·완전성을 보증하지 않는다. 초안은 현재 탭 메모리이고 새로고침·종료로 초기화된다.
- 비용의 청구 금액·공급자 보관 정책·대규모 부하를 측정하지 않았다. 실제 학생 원본·서버 비밀값은 저장소나 기록에 포함하지 않았다.
- 외부 작업일지는 체크아웃에 없어 이 문서와 DEVELOPMENT.md에 결과를 남겼다.

## 후속 Git 저장 범위

같은 날 사용자의 Git/GitHub 푸시 요청으로 `codex/neis-helper` 브랜치를 만들고 기능 코드를 `77c4ba3`에 커밋했다. 검토·비교·배포 기록은 별도 문서 커밋으로 보존한다. 운영에 함께 배포되어 있던 다른 워크트리의 학교 문서 변경은 이 기능 브랜치에 섞지 않았다. main 병합과 재배포는 이번 푸시에 포함하지 않는다.
