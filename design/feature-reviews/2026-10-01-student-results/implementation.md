## 1차 구현과 2차 모의 검토

총점 열을 독립 점수와 구분하고 원본 총점과 과목 합계가 다르면 가져오기 경고를 표시했다. 교사는 기존 링크를 유지하면서 제목·안내·배점·점수·피드백을 정정하고 이력을 확인할 수 있다. 정정과 설정 저장은 소유자 확인 후 암호화한 이력과 함께 원자적으로 반영되며, 변경된 확인 완료 학생만 재확인 대상으로 바꾼다. 학생 화면에는 원래 안내, 본인의 이의와 답변, 최신 결과 확인, 조회 종료를 연결했다. QR PDF 캡처는 각 쪽을 복제 문서의 원점으로 옮기도록 수정했다.

| 독립 관점 | 1차 구현 판정·근거 | 2차 수정 요구와 결과 |
| --- | --- | --- |
| 웹디자인·정보 위계 | 총점 92/100과 세부 점수 92/100의 의미가 일치함 | 재확인 안내가 점수 정정에도 '답변'만 언급하므로 '수정된 결과나 답변'으로 고침 |
| 웹디자인·화면 밀도 | 데스크톱 전체 화면의 현황 표와 카드가 분리되어 읽힘 | 1024px 부근에서 7열 카드가 빽빽해 4열, 넓은 화면에서 7열로 조정 |
| UX·학생 흐름 | 이의 초안 보호, 답변 확인, 최신 결과 갱신, 종료가 이어짐 | 갱신 시 만료·종료를 감지하면 이전 개인정보를 화면과 메모리에서 지움. 교사 정정 뒤 오래된 화면의 확인 요청은 거부하고 최신 결과 확인을 안내 |
| UX·교실 배부 흐름 | 17명 3쪽 PDF의 제목·카드·QR이 전부 나타남 | 긴 제목·실제 기기 QR 스캔은 운영 확인 대상으로 남김 |
| UI·접근성 | 방향키 탭, 정정 대화상자 포커스, 오류 안내가 동작함 | 저장 중 상태 변화가 대화상자의 첫 입력으로 포커스를 되돌리지 않도록 보강 |
| UI·반응형/상태 | 390px 학생·교사 전체 화면에서 가로 넘침이 없고 이의 상태가 구분됨 | 파일 적용 뒤에도 '다른 파일 선택'을 남기고 교체 범위를 설명함 |

## 재검증

- `npm run typecheck`: 통과.
- `npm run lint`: 종료 코드 0. 기존의 다른 기능·공통 컴포넌트 경고 7건은 남음.
- `npm test`: 57파일 466검사 통과.
- `PLAYWRIGHT_TEST_PORT=4188 npm run test:e2e -- tests/e2e/student-results.spec.ts`: 12검사 통과. 가상 성적 파일, 총점, 이의 초안 보호, 교사 정정·학생 갱신, 17명 QR PDF를 포함한다.
- `npm run build`: 통과. 기존 단일 번들 크기 경고는 남음.
- 연결된 Chrome에서 교사 현황 1512px·390px 전체 화면, 학생 결과 390px 전체 화면을 직접 확인했다. 학생 페이지의 문서 너비와 뷰포트가 모두 390px이었다. 앱 자체의 콘솔 오류는 보지 못했으며 Chrome 확장 프로그램의 네트워크 차단 오류는 별개였다.
- 실제 내려받은 17명 QR PDF 3쪽을 PNG로 렌더해 각 쪽의 제목·카드·QR·아래쪽 잘림을 시각 확인했다. 실제 출력 용지·운영 링크 QR 스캔은 확인하지 않았다.

운영 Supabase 마이그레이션·함수·프런트엔드 원격 적용과 실제 권한·암호화 통합 검증은 로컬 데모 성공과 별개다. 원격 적용 여부는 배포 결과로 따로 기록해야 한다.
