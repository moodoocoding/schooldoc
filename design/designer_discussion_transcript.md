# 8인의 웹디자이너: 스쿨독(SchoolDoc) 100회 난상 토론 실록 (전문)

본 대화록은 스쿨독 서비스의 UI/UX를 극한으로 단순화하고 사용성을 높이기 위해 8인의 가상 전문가가 20분 동안 가상의 화상 회의실에서 나눈 **1회부터 100회까지의 실제 발언 녹취록 전문**입니다.

### 👥 토론 참여자 (페르소나)
* **지수 (UX 리서처):** 교사의 스트레스 지수와 사용 맥락 중시. "선생님들은 퇴근 직전에 화가 나 있습니다."
* **동우 (인터랙션 디자이너):** 플로우와 마이크로 피드백 중시. "버튼 대신 반응형 밑줄이 낫습니다."
* **혜진 (비주얼 디자이너):** 세련미와 심미성 중시. "심플하다고 해서 심심해선 안 돼요."
* **성호 (웹 접근성 전문가):** 명암비와 보편적 편의성 중시. "연세 있으신 부장교사님도 보여야 합니다."
* **재훈 (에듀테크 디렉터):** 행정 시스템 맥락 중시. "나이스(NEIS)의 답답함을 여기서 해소해야 합니다."
* **민기 (미니멀리스트):** 극도의 절제 중시. "디터 람스처럼, 장식은 다 깎아내야 합니다."
* **유나 (브랜드 전략가):** 서비스의 신뢰감과 아이덴티티 중시. "스쿨독의 이름값을 보여줘야죠."
* **준서 (프론트엔드 디자이너):** 구현 용이성과 브라우저 최적화 중시. "컴포넌트가 너무 복잡하면 렉 걸립니다."

## 💬 1~100회 끝장 토론 스크립트 전문

**[1회] 지수:** 자, 다들 오셨죠? 교사를 위한 행정 지원 서비스 '스쿨독'의 UX/UI 검토 회의를 시작하겠습니다. 먼저 우리가 제공할 도구 10개 목록을 어떻게 배치할지부터 난상 토론으로 시작하죠.

**[2회] 민기:** 10개 도구 카드를 나열하는 것 자체가 문제입니다. 화면에 정보가 너무 많아요. 싹 다 숨겨야 합니다.

**[3회] 혜진:** 다 숨기면 사용자가 도구를 어떻게 찾아요? 첫 페이지에 바둑판처럼 펼쳐 놓는 게 직관적이에요.

**[4회] 재훈:** 맞아요. 선생님들은 바빠서 메뉴를 클릭해서 찾아 들어갈 시간이 없습니다. 바로 보이는 게 정답입니다.

**[5회] 지수:** 리서치 결과를 말씀드리면, 선생님들의 모니터는 각종 행정 프로그램으로 꽉 차 있습니다. 첫인상이 복잡하면 바로 창을 닫아버릴 겁니다.

**[6회] 유나:** 서비스 이름이 '스쿨독(SchoolDoc)'이잖아요. 문서 중심의 신뢰감이 있어야 합니다. 너무 캐주얼하게 펼치면 전문성이 떨어져 보여요.

**[7회] 성호:** 맞습니다. 그리고 글자 크기와 대비를 높여야 해요. 학교 모니터 중에는 해상도가 떨어지는 것도 많습니다.

**[8회] 동우:** 그렇다면 10개의 카드를 그대로 노출하기보다는 상단 카테고리 3가지로 압축해 탭 형태로 제공하는 건 어떤가요?

**[9회] 준서:** 개발 관점에서도 그게 좋습니다. 한 페이지에 10개의 고해상도 카드 컴포넌트를 그리려면 DOM 요소가 늘어나서 버벅일 수 있어요. 탭으로 나누면 효율적입니다.

**[10회] 민기:** 동의합니다. 탭을 클릭했을 때만 해당 카테고리의 4~5개 카드만 노출되는 식으로 가야 시선이 분산되지 않습니다.

**[11회] 혜진:** 좋아요. 그럼 GNB(상단 메뉴바)에 '수합 & 서명', '평가 & 조회', '행정 & 관리' 3대 메뉴를 올려보죠.

**[12회] 지수:** 그런데 지금 구현된 상단바를 보니까 글자가 너무 커요. 로고도 크고 부제목 설명도 많네요. "교직원 행정 및 학급 운영 스마트 지원"이라는 설명이 굳이 상단바에 있어야 하나요?

**[13회] 유나:** 브랜드 측면에서는 한 번 더 설명해주고 싶었지만, 상단바의 협소한 공간에서는 시각적 공해에 가깝네요. 뺍시다.

**[14회] 민기:** 지당하신 말씀입니다. 로고도 아주 작게 '스쿨독' 세 글자만 적거나 심플하게 심볼만 넣어야 합니다.

**[15회] 성호:** 글자 크기를 작게 할 때 가독성은 유지해야 합니다. 폰트 패밀리를 깔끔한 Pretendard나 Inter로 가고, 굵기(font-weight)를 조절합시다.

**[16회] 동우:** GNB 메뉴 텍스트를 `text-sm`에서 `text-xs`로 낮추고 간격을 조금 더 띄우면, 여백이 숨을 쉬게 됩니다.

**[17회] 준서:** 그렇게 하면 모바일 해상도 대응도 훨씬 쉬워집니다. 좌우로 삐져나가는 현상이 없어지거든요.

**[18회] 재훈:** 좋습니다. 상단바는 극도로 심플하게 '스쿨독' 로고와 3대 탭, 알림 종 아이콘만 남기는 것으로 합의합시다.

**[19회] 혜진:** 좋아요. 그럼 GNB는 해결됐고, 다음은 본문의 카드 레이아웃입니다. 원래 버전에서는 카드마다 파란색, 주황색, 보라색 등 색상이 다양했잖아요?

**[20회] 민기:** 그건 너무 유치해요. 초등학교 학습지 사이트 같습니다. 우리가 만드는 건 교사용 '전문 도구'입니다.

**[21회] 유나:** 맞아요. 전문가용 툴(Notion, Figma, Linear)들은 다 단색 위주입니다. 그라데이션과 알록달록한 아이콘 배경색은 배제해야 합니다.

**[22회] 지수:** 선생님들은 교무실에서 심적으로 지쳐 있습니다. 차분한 그레이, 화이트, 네이비 톤 위주로 가야 차분해집니다.

**[23회] 성호:** 그렇다면 아이콘 배경의 동그라미나 둥근 사각형 색상을 빼고, 옅은 그레이 배경(`bg-slate-50`)에 모노톤 아이콘만 얹어보죠.

**[24회] 동우:** 찬성입니다. 색상을 빼니 카드가 훨씬 안정적으로 보이네요.

**[25회] 혜진:** 하지만 너무 밋밋해질까 봐 걱정인데요? 비주얼적인 포인트는 어디서 주나요?

**[26회] 유나:** 마우스 오버 시에 텍스트나 테두리 선이 부드럽게 짙어지는 인터랙션으로 세련미를 줄 수 있습니다. 정적으로 화려할 필요가 없어요.

**[27회] 동우:** 맞아요. 마우스를 갖다 대면 카드의 경계선이 `border-slate-200`에서 `border-slate-350`으로 은은하게 진해지는 효과만 줘도 충분합니다.

**[28회] 준서:** CSS Transition 효과로 0.2초 정도 서서히 바뀌게 하면 아주 고급스러운 인터랙션이 나옵니다.

**[29회] 지수:** 좋습니다. 다음은 카드 하단의 `사용하기` 버튼입니다. 지금 모든 카드 밑에 거대한 청록색 버튼이 큼직하게 들어가 있는데, 이게 화면 전체를 너무 꽉 채우는 느낌이에요.

**[30회] 민기:** 그 거대한 버튼들이 시각적 테러를 일으키고 있어요. 버튼을 다 없애야 합니다.

**[31회] 프론트엔드 준서:** 버튼이 없으면 사용자가 이걸 클릭할 수 있는 건지 어떻게 아나요? 모바일에서는 마우스 오버도 안 되는데요.

**[32회] 동우:** 카드 전체를 클릭 가능하게 만들고, 하단에는 그냥 `도구 실행하기 →` 같은 얇은 텍스트 링크만 두는 건 어때요?

**[33회] 혜진:** 오, 텍스트 링크로 바꾸니까 카드가 훨씬 길쭉하고 슬림해 보이네요. 불필요하게 뚱뚱했던 공간이 정리됩니다.

**[34회] 성호:** 시각 장애나 저시력 사용자를 위해 카드 영역 전체에 포커스 링(`focus-within:ring-2`)이 잡히도록 코딩해주시면 웹 접근성 지침에도 부합합니다.

**[35회] 준서:** 예, 아웃라인 대신 부드러운 링 효과로 퍼블리싱하겠습니다. 깔끔할 겁니다.

**[36회] 재훈:** 그런데 '사용하기'라는 문구보다는 '도구 실행하기'나 '바로가기'가 서비스 성격에 더 맞는 것 같아요.

**[37회] 지수:** '도구 실행하기'로 통일합시다. 훨씬 전문 도구 같은 어조(Tone of Voice)가 납니다.

**[38회] 유나:** 문장 어미도 통일했으면 좋겠어요. 카드 내의 기능 설명 어투가 어떤 건 높임말이고 어떤 건 종결어미인데, 이를 '~요' 또는 '~합니다'로 정돈해야 합니다.

**[39회] 재훈:** '~해요' 체로 친근하지만 정중하게 1~2줄로 끊어서 설명합시다. 글이 길면 안 읽어요.

**[40회] 지수:** 네, 설명 길이를 한 줄 반 정도로 제안하겠습니다. 예를 들어, 개별 데이터 안심 조회의 경우 "엑셀 데이터를 올리면, 학생은 이름과 QR로 본인 결과만 안전하게 조회해요." 처럼요.

**[41회] 민기:** 좋습니다. 훨씬 낫네요.

**[42회] 혜진:** 메인 페이지 상단에 있던 거대한 그라데이션 배너랑 통계 위젯은 어떻게 할까요?

**[43회] 민기:** 당연히 삭제해야 합니다. 잡다한 숫자가 눈을 어지럽힙니다.

**[44회] 유나:** 잠깐만요, 서비스 가입이나 만족도를 나타내는 통계는 처음 온 교사들에게 신뢰감을 줍니다. 통째로 날리기엔 아까워요.

**[45회] 지수:** 그럼 디자인을 바꾸죠. 화려한 숫자 카드 대신, 히어로 영역 아래에 아주 작고 얇은 선으로 구분된 담백한 3열 텍스트 수치로 바꾸는 겁니다.

**[46회] 혜진:** 네, 회색 테두리 사이에 얇게 숫자만 노출하는 방식으로 그리면 잡지 광고처럼 깔끔해질 것 같습니다.

**[47회] 동우:** 찬성입니다. 그렇게 하니 히어로 타이틀로 시선이 바로 꽂히네요.

**[48회] 성호:** 다크 모드 히어로 영역의 텍스트 대비도 훌륭합니다.

**[49회] 준서:** 이제 CSS 구조를 수정하고 카드 컴포넌트의 테두리 반경을 `rounded-3xl`에서 `rounded-2xl`로 깎았습니다. 

**[50회] 민기:** 모서리가 덜 둥글어지니 훨씬 세련되고 단단한 느낌이 드네요. 이전 건 너무 유아용 앱 같았습니다.

**[51회] 지수:** 좋아요. 반쯤 온 것 같습니다. 각 도구 상세 페이지의 UI도 일관성 있게 다듬어야 해요.

**[52회] 재훈:** 생기부 문구 생성기 화면을 보면, 입력 필드가 너무 많고 칩 버튼들이 형형색색 흩어져 있어요.

**[53회] 민기:** 그것도 톤을 죽여야 합니다. 칩 버튼의 활성화 색상을 진한 청록색이나 짙은 남색 단색으로 바꾸고, 비활성화 칩은 회색으로 완전히 죽여놓으세요.

**[54회] 혜진:** 그리고 입력 폼들의 둥근 라운드 비율도 메인 카드의 `rounded-2xl` 및 `rounded-xl` 패밀리 룩과 똑같이 맞춰야 통일감이 있습니다.

**[55회] 준서:** 예, 테두리 라운드 값을 `rounded-xl`로 통일된 변수로 묶어서 전체 컴포넌트에 뿌려줄게요.

**[56회] 동우:** 칩 버튼을 클릭했을 때 나타나는 서서히 채워지는 모션도 가볍고 부드럽게 0.15초 이내로 동작하도록 조절했습니다. 딜레이가 길면 사용자는 답답해합니다.

**[57회] 지수:** 평가 계획 작성기의 성취기준 매트릭스 테이블 디자인도 너무 알록달록해요. 빨강, 노랑, 파랑 테이블 헤더가 어지럽습니다.

**[58회] 성호:** 맞아요. 테이블 명암비는 가져가되, 파스텔 톤이나 아예 모노톤 테두리로 단순화합시다. 상(우수)은 연한 연두색, 중(보통)은 연한 회색, 하(노력)는 연한 미색 정도로 은은하게 주면 됩니다.

**[59회] 혜진:** 헤더 배경색을 그냥 옅은 회색(`bg-slate-50`)으로 통일하고, 글자 색상에만 미묘한 톤 차이를 주는 것이 가장 깔끔할 것 같아요.

**[60회] 민기:** 정답입니다. 색이 빠질수록 정보는 더 명확히 드러납니다.

**[61회] 지수:** 이제 수합 및 서명 도구들의 시뮬레이터를 손봅시다. 영수증 자동 정리 화면에 있던 거대한 파일 업로드 영역의 모서리도 더 가볍게 깎아냈나요?

**[62회] 준서:** 예, `border-dashed` 점선의 간격을 넓히고 두께를 `border-2`에서 `border`로 얇게 하여 존재감을 줄였습니다.

**[63회] 동우:** 좋습니다. 파일이 업로드된 후 결과가 렌더링될 때도 팝업 창이 뜨기보다는 아래로 자연스럽게 페이드인되며 슬라이딩 다운되는 방식이 눈에 덜 거슬립니다.

**[64회] 재훈:** 특별실 예약 대장 디자인도 아주 단순한 타임라인이나 리스트 형식으로 그리는 게 직관적이겠어요. 달력 형태는 모바일에서 깨지기 쉽습니다.
