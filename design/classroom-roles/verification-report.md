# 1인 1역 검증 보고서

## 확인한 흐름

교사 설정의 명단 → 역할 2단계 배정 → 학급 공용 학생 화면 → 오늘 실천 저장/재제출 → 교사 정정 → 선택한 월의 학생별 누가 기록.

## 로컬 검사 결과 (2026-09-27)

| 검사 | 결과 | 범위 |
| --- | --- | --- |
| `npm run typecheck` | 통과 | 프런트엔드 + 공유 도메인 |
| `npm run lint` | 통과 | 신규 코드 경고 없음. 기존 코드 경고 6건 유지 |
| `npm test` | 48파일 / 392검사 통과 | 현재 작업 폴더의 기존 미커밋 영수증 검사 포함 |
| 관련 Playwright E2E | 22검사 통과 | 1인 1역 7개, 셸 스크롤 15개 |
| `npm run build` | 통과 | 기존 큰 청크 경고 있음 |
| Deno 함수 타입 검사 | 통과 | 신규 admin/public 서버 함수 |
| 서버 HTTP 계약 검사 | 10검사 통과 | 가상 fetch, 실제 네트워크 사용 안 함 |
| PostgreSQL SQL 검사 | 1검사 / 8단계 통과 | PGlite 메모리 DB, 신규 마이그레이션·RLS·RPC |
| 브라우저 시각 검사 | 통과 | 홈의 6개 기능, 데스크톱/모바일 캡처 확인 |

서버 HTTP 검사는 인증 필수·소유자 필터·공개 토큰·공개 응답 최소화·날짜/상태 위조 거부·공유 중지·요청 제한 실패·동시 변경 충돌·월간 1,050행 조회·암호화 키 누락을 검사했다.

SQL 검사는 실제 PostgreSQL 문법으로 마이그레이션 적용, 교사별 읽기 격리, 브라우저 직접 쓰기/RPC 거부, 익명 접근 거부, 중복 제출 갱신, 버전 충돌, 다른 교사 기록 차단, 한 건 초기화를 검사했다. 운영 Supabase 검증으로 간주하지 않는다.

## 수정하고 재검증한 문제

1. 공유 입력 검증의 TypeScript narrowing 오류 → 타입이 확정된 지역 변수 및 명시적 종료 함수 사용.
2. 월간 기록이 기본 1,000행 제한에 잘릴 가능성 → 500행 페이지 조회, 1,050행 회귀 테스트.
3. 공개 객체 펼치기로 향후 추가 필드가 노출될 가능성 → 공개 필드 명시적 선택.
4. 입력 라벨을 정확히 찾지 못한 브라우저 검사 실패 → 고유 id/htmlFor와 명시적 선택상자 이름, 22검사 재통과.
5. 기존 QR 테스트의 Windows 경로 구분자 불일치 → 플랫폼별 `join()` 경로, 기존 기능 변경 없음.

## 배포 전 미확인 사항

- GitHub 로그인과 기존 운영 Git 연동 배포 이력은 확인했다.
- Supabase CLI는 로그인되지 않아 원격 프로젝트 이력·신규 키·마이그레이션·서버 함수 배포를 아직 확인하지 못했다.
- 연결된 Vercel 계정은 이 저장소의 기존 팀에 접근 권한이 없다. 프런트엔드 배포는 기존 GitHub 연동 경로를 사용하되 결과를 확인해야 한다.
- 아직 main 통합, 운영 학생 제출/교사 확인, 다른 기기 간 동기화 성공으로 보고하지 않는다.
- 외부 개발 일지와 `pro/ux-ui-expert.md`는 이 checkout에 없어 사용하지 않았다. 계획·모의 검토·검증 내역은 이 폴더에 기록했다.
