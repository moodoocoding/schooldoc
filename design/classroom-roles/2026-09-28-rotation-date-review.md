# 역할 교체 날짜 선택 검토 (codex)

AI 내부 웹·UX·UI 디자인 프로파일에 따른 모의 검토다. 실제 교사·디자이너 인터뷰나 승인 결과가 아니다.

## 구현 전

| 관점 | 판정·근거 | 수정 방향 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자이너 | 수정 필요. 교체 화면의 첫 카드가 명단이어서 교체 시점을 한눈에 알 수 없다. | 날짜 입력을 명단 앞의 독립된 카드로 배치하고 모바일·데스크톱 전체 화면에서 위계를 확인한다. | 작은 화면에서는 세로 길이가 늘어날 수 있다. |
| UX 디자이너 | 수정 필요. 날짜 입력은 역할 배정 단계의 `기간 변경` 뒤에 있고, 운영 중인 기간과 겹치면 마지막 확인에서야 오류가 난다. | 진입 즉시 시작·종료일을 선택하고, 겹치지 않는 시작일과 운영 중 교체 경로를 앞에서 안내한다. | 기존 기간 종료일은 운영 설정에서 별도로 줄여야 한다. |
| UI 디자이너 | 수정 필요. 날짜 입력이 숨겨져 키보드·터치 사용자가 발견하기 어렵다. | 날짜 필드를 항상 표시하고 레이블·최소 날짜·빈 값 오류를 확인한다. | 모바일 날짜 선택기의 모양은 OS별로 다르다. |

## 구현 후

| 관점 | 판정·근거 | 남은 위험 |
| --- | --- | --- |
| 웹디자이너 | 통과. 데스크톱·모바일 전체 화면에서 `교체 기간` 카드가 명단 앞에 놓인다. 200% 확대에서 명단은 1열로 바뀐다. | 실제 태블릿·OS별 날짜 선택기 모양은 확인하지 않았다. |
| UX 디자이너 | 조건부 통과. 첫 화면에서 날짜를 정하고 2단계로 값을 유지한다. 기존 배정을 오늘 종료한 뒤 내일부터 교체를 시작할 수 있다. | 오늘 날짜의 역할을 즉시 덮어쓸 수는 없다. 운영 설정에서 종료일을 먼저 바꾸는 왕복이 필요하다. |
| UI 디자이너 | 통과. 날짜 필드는 항상 보이고 레이블로 접근 가능하다. 빈 시작일은 첫 단계에서 필드 가까이에 오류를 표시한다. | 실제 키보드 날짜 선택기와 고대비 모드는 현장 검증이 남았다. |

화면 증거는 `tests/e2e/classroom-roles.spec.ts`의 데스크톱·모바일·200% 확대 전체 페이지 캡처다. 가상 학생 데이터와 데모 모드로 검사했으며 실제 교사 승인이나 원격 Supabase 검증으로 간주하지 않는다.
