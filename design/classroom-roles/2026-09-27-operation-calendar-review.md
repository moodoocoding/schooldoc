# 운영 기간·제외일 화면 모의 검토

이 문서는 `pro/web-designer.md`, `pro/ux-designer.md`, `pro/ui-designer.md`를 기준으로 한 AI 모의 검토다. 실제 디자이너나 교사의 인터뷰·승인 결과가 아니다.

## 구현 전

| 관점 | 판단 | 근거 | 남은 위험과 조치 |
| --- | --- | --- | --- |
| 웹디자인 | 수정 필요 | 운영 설정에는 기간이 보이지 않고, 실천 제외일은 날짜 형식 안내와 긴 텍스트 상자로 표시된다. 날짜 작업의 시각적 우선순위가 없다. | 기간·실천일을 먼저 배치하고, 달력과 선택 상태를 데스크톱·모바일 전체 화면에서 확인한다. |
| UX | 수정 필요 | 확정한 배정의 종료일을 바꾸려면 현재 화면에서 방법을 찾을 수 없다. 제외일마다 날짜를 정확히 입력해야 한다. | 진행 중·예정 기간만 안전하게 수정하고, 날짜 클릭·재클릭으로 제외일을 변경한다. 저장 실패 시 입력을 유지한다. |
| UI | 수정 필요 | 제외일 텍스트 상자는 선택·해제 상태를 보여주지 않으며, 날짜 형식 오류는 저장 이후에야 드러난다. | 44px 높이의 달력 버튼, 접근 가능한 날짜 이름·선택 상태·키보드 포커스를 제공한다. |

## 구현 후

전체 페이지 캡처: [진행 중인 기간·제외일 선택 PC](verification/operation-settings-desktop.png), [배정 전·제외일 선택 모바일](verification/operation-settings-mobile.png). 모두 가상 자료를 사용한 개발 데모다.

| 관점 | 판단 | 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 통과 | 1366px 화면에서 기간 → 실천 요일·달력 → 학생 공용 설정 순으로 읽히고, 달력의 월 이동과 날짜 격자 폭을 맞췄다. 390px 화면은 한 열이며 가로 넘침이 없다. | 실제 교사의 시선 흐름과 선호는 확인하지 못했다. |
| UX | 통과 | 진행 중인 기간은 종료일, 예정된 기간은 시작·종료일을 저장하고 재접속해 확인했다. 배정 전에는 배정 화면으로 이동할 수 있다. 제외일은 월 이동·선택·해제 후 저장된다. 지난 날짜와 학생·역할 스냅샷은 변경되지 않는다. | 제외일 변경은 과거 집계에도 반영될 수 있으므로 저장 전 문구로 기록 유지 사실을 안내한다. 실제 교사 사용성 시험은 하지 않았다. |
| UI | 통과 | 날짜 버튼은 높이 44px 이상, `aria-pressed`와 날짜별 접근 가능한 이름을 갖고, Space 키로 선택된다. 달력 영역 axe 검사에서 위반이 없었고, 390px·195px 문서 가로 넘침도 없었다. | 200% 확대 수준의 매우 좁은 폭에서는 달력 안에서 가로 이동이 필요하다. |

React 구성 점검: 날짜 선택은 컴포넌트 안의 단일 월 상태와 부모의 제외일 배열로 나눴다. 비동기 저장은 기존 `save` 경로를 그대로 사용하며, 서버와 브라우저가 같은 기간 변경 검증을 사용한다.

검증: `npm run typecheck`, `npm run lint`(기존 다른 파일의 경고 6건), `npm test`(427개), 관련 Playwright 38개, `npm run build`, 두 Edge Function의 Deno 타입 검사와 가상 요청·응답 테스트 11개 통과. 운영 Supabase와 실제 교사 계정 흐름은 별도 확인이 필요하다.

배포 확인: 연결된 운영 프로젝트의 마이그레이션 이력이 일치했고, `classroom-roles-admin` 함수만 배포해 ACTIVE 버전 2를 확인했다. 배포된 함수는 무인증 요청에 HTTP 401을 반환했다. 운영 교사 계정으로 기간·제외일 저장까지 시험하지는 않았다.
