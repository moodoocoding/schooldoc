# 학생 명단 다열 배치 모의 검토

`pro/web-designer.md`, `pro/ux-designer.md`, `pro/ui-designer.md`를 기준으로 한 AI 모의 검토다. 실제 전문가·교사 인터뷰나 사용성 시험은 아니다.

## 구현 전

| 관점 | 판단 | 근거 | 조치 |
| --- | --- | --- | --- |
| 웹디자인 | 수정 필요 | 23명 명단이 넓은 PC 화면에서도 번호·이름 한 줄씩 23행을 차지하고, 오른쪽 대부분이 비어 있다. | PC 4열·모바일 2열로 번호순 배치하고 전체 화면에서 열 균형을 확인한다. |
| UX | 수정 필요 | 다음 단계로 이동하려면 명단 아래까지 스크롤해야 한다. | 행 수를 줄이되 모바일의 짧은 미리보기와 전체 보기·접기 동작은 유지한다. |
| UI | 수정 필요 | 한 열 표의 헤더와 넓은 빈 셀이 공간을 차지한다. | 번호·이름을 한 항목으로 묶은 접근 가능한 목록을 쓰고 긴 이름·200% 확대에서 잘림을 확인한다. |

## 구현 후

| 관점 | 판단 | 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 개선 확인 | [PC 전체 화면](verification/roster-grid-desktop.png)에서 23명이 4열 6행에 번호순으로 놓이고, 오른쪽 빈 공간이 명단에 활용된다. [모바일 전체 화면](verification/roster-grid-mobile.png)은 2열 12행으로 균형이 맞는다. | 실제 교사의 화면 밀도 선호는 확인하지 않았다. |
| UX | 개선 확인 | 인원수와 무관하게 PC는 4열, 일반 모바일은 2열이다. 모바일 미리보기는 6명(3행)으로 짧게 유지하고 전체 보기·접기를 제공한다. 목록과 다음 단계가 한 문서 스크롤 안에 있다. | 360px 미만 또는 200% 확대처럼 화면이 아주 좁을 때는 읽기 편하도록 1열로 바뀐다. |
| UI | 개선 확인 | 번호와 이름을 하나의 목록 항목으로 묶고, DOM·키보드 읽기 순서를 왼쪽에서 오른쪽으로 번호순 유지한다. 0·1·23·60명, 긴 이름, 195px 폭에서 가로 잘림이 없음을 확인했다. | 실제 교사 인터뷰·승인·사용성 시험은 진행하지 않았다. |

전체 화면 캡처는 가상 학생 명단의 개발용 데모 화면이다. `npm run typecheck`, `npm run build`, `npm test`(427개), 관련 Playwright 검사(38개)와 명단 가져오기 검사(5개)가 통과했다. `npm run lint`는 통과했으며 기존의 다른 파일에서 경고 6개가 남아 있다.
