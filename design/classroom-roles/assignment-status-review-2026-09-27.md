# 학생 배정 상태 시각 검토 (codex)

2026-09-27. `pro/`의 웹·UX·UI 디자이너 프로파일을 적용한 AI 내부 검토다. 실제 디자이너나 교사의 검토가 아니다. 화면과 테스트에는 가상 학생만 사용한다.

## 구현 전

| 관점 | 판단과 근거 | 변경 방향 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자이너 | 수정 필요. 정원이 찬 역할에서 체크된 학생만 파란색이고, 미배정·다른 역할 배정 학생은 모두 흐린 회색으로 보인다. | 현재 역할·미배정·다른 역할의 배경·테두리·문구를 각각 구분한다. | 색만으로 구분되면 고대비 환경에서 의미가 사라질 수 있다. |
| UX 디자이너 | 수정 필요. 19명이 미배정이어도 선택 역할이 꽉 차면 모든 체크하지 않은 카드가 비활성으로 흐려진다. 다음에 배정할 학생을 찾기 어렵다. | 비활성 여부와 배정 상태를 별도로 표시하고, 정원 완료 후 다음 행동을 안내한다. | 실제 교사가 상태를 얼마나 빨리 훑는지는 별도 사용성 검토가 필요하다. |
| UI 디자이너 | 수정 필요. `opacity-60`이 카드 전체에 적용돼 학생 이름과 기존 역할까지 흐려진다. | 카드 전체 투명도를 없애고 상태 텍스트를 표시한다. 체크박스의 실제 비활성·키보드 동작은 유지한다. | 모든 상태의 대비와 확대 화면을 확인해야 한다. |

## 구현 후

| 관점 | 판단과 근거 | 남은 위험 |
| --- | --- | --- |
| 웹디자이너 | 상태 구분은 통과. 23명 중 현재 역할 2명, 다른 역할 2명, 미배정 19명의 전체 화면 캡처에서 파랑·회색·옅은 호박색 카드가 구분된다. 선택 역할 배경도 파란색으로 바뀐다. | 19개 미배정 카드가 한꺼번에 강조돼 화면이 다소 노랗다. 좌우 패널의 하단 높이 차이와 전체 타이포그래피 위계는 이번 변경으로 해결되지 않았다. |
| UX 디자이너 | 상태 구분은 통과. 각 카드에 `이 역할 담당`·`배정됨 · 역할명`·`미배정`을 적어 색을 읽지 않아도 다음 배정 대상을 찾을 수 있다. 정원 완료 문구는 다른 역할을 고르는 다음 행동도 안내한다. 기존 역할 이동·검색·취소 E2E가 통과했다. | 실제 교사가 반복 배정을 완료하는 시간과 선호하는 상태 색은 아직 측정하지 않았다. |
| UI 디자이너 | 상태 구분은 통과. 카드 전체의 `opacity-60`을 제거해 정원이 찬 상태에서도 이름과 기존 역할이 보인다. 체크박스의 `disabled`는 유지했고 상태 문구를 `aria-describedby`로 연결했다. 대상 영역의 axe 검사에서 위반이 없었다. | 200% 텍스트 확대·320px에서는 한 열로 바뀌어 가로 잘림은 없지만 세로 스크롤이 길다. 고대비 모드·실제 모바일 기기 검증은 남았다. |

가상 학생 23명·기본 역할 18개, 긴 가상 이름 1개로 1366px 데스크톱·768px 태블릿·390px 및 320px 모바일 폭을 확인했다. 320px에서 기본 글자 크기를 두 배로 하는 검사에서 처음에는 2열 카드 안의 글자가 과하게 줄바꿈되어 수정이 필요했다. 카드의 최소 너비를 `rem` 기반으로 바꿔 이 경우 한 열이 되도록 수정했다. 최종 코드에서 `npm run typecheck`, `npm run lint`(기존 경고 6건), `npm run build`, Playwright 관련 전체 검사 15건이 통과했다. 데스크톱·모바일·큰 글자 전체 화면 캡처를 남겼다. 이는 실제 브라우저 확대나 실기기 테스트를 완전히 대체하지 않는다.
