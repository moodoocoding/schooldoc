# 1인 1역 개발 계획

## 범위와 화면 구조

전용 브랜치: `codex/classroom-roles`. 기존 영수증·README 변경은 보존하고 이번 커밋에 포함하지 않는다.

- 홈: 오늘의 짧은 현황 → 아래 3열×2행 기능 타일(모바일 1열).
- 매일 쓰는 기능: 오늘의 실천판, 실천 기록, 학생 역할 배정.
- 운영 기능: 역할 목록, 역할 교체, 운영 설정.
- 공유/전자칠판 보기는 실천판 안의 동작이다. 별도 기능 타일로 중복하지 않는다.
- 배정은 정확히 2단계: 설정의 학생 명단 자동 불러오기 → 학생별 역할 배정. 미배정 학생 수와 남은 역할 자리 수를 표시한다.
- 모든 학생이 같은 링크에서 이름을 선택하고 했어요/못했어요를 제출한다. 개별 QR·개별 인증은 사용하지 않는다. 학생 자기보고이며 본인 인증 기록이 아님을 안내한다.
- 누가 기록은 선택한 월의 학생 타일 → 날짜별 상세로 접근한다. 미기록, 못했어요, 해당 없음은 서로 다른 상태다.
- 배정 기간은 기본 월 단위, 직접 기간 설정 가능. 역할별 실천 요일과 학급 제외일을 지원한다. 교체 이후에도 과거 명단·역할 스냅샷은 보존한다.

## 구현 순서

1. 공통 도메인·입력 검증·암호화 저장·소유자 격리·공개 토큰 API.
2. 교사 6개 화면, 설정 학생 명단, 공용 학생 화면, 개발용 데모.
3. 2차 모의 검토(화면·동선) 후 수정.
4. 타입 검사, 린트, 전체 단위 테스트, 관련 E2E, 빌드, 서버 권한·날짜·중복 기록 검사.
5. 3차 모의 검토(예외·버그)와 코드 리뷰, 발견 사항 수정 및 재검증.
6. 배포 사전 점검: 기존 인증·프로젝트 확인 → 신규 암호화 키(기존 키 유지) → 신규 마이그레이션 → 신규 서버 함수 → 프런트엔드.
7. 명시적으로 이번 파일만 커밋·푸시, PR 검토 후 main 통합. 운영 주소에서 실제 동작 확인, 4차 모의 검토(운영 인수).

## 안전성과 검증 기준

- 실명은 서버 암호화 저장, 교사 소유자 검사와 RLS를 적용한다. 개발 데모만 로컬 저장한다.
- 공개 API는 활성 기간의 필요 정보만 제공한다. 과거 기록·교사 전용 정보는 제공하지 않는다.
- 한국 시간 오늘만 학생 제출 가능. 교사는 기간 내 과거 정정 가능. 동일 날짜·학생의 재제출은 한 기록을 갱신한다.
- 교사 설정 저장은 버전 충돌을 감지한다. 다른 탭 변경을 조용히 덮어쓰지 않는다.
- 공개 링크는 비밀번호 없는 학급 공용 링크임을 안내하고 끄기·재발급을 제공한다.
- 테스트는 가상 자료만 사용한다. 원격 자격 증명이나 배포 대상이 확인되지 않으면 배포 성공으로 보고하지 않는다.
- 실행 결과와 미확인 사항은 별도 검증 보고서에 기록한다. 데모 E2E와 운영 검증을 구분한다.
