# 1인 1역 UX·UI 간소화 수정 계획서 (codex)

작성일: 2026-09-27 · 상태: P1 구현·검증 진행, P2 후속 과제

## 1. 핵심 제안

**학생 역할 배정 2단계를 ‘설명이 많은 설정 화면’에서 ‘역할을 고르고 이름을 누르는 작업 화면’으로 바꾼다.**

역할별 다중 선택과 기존 2단계 흐름은 유지한다. 문장을 짧게 고치는 데 그치지 않고, 화면의 우선순위를 다음처럼 바꾼다.

1. 가장 크게: 선택한 역할과 학생 이름.
2. 가까이, 짧게: 배정 인원·정원과 미배정 인원.
3. 필요할 때: 기간 편집, 역할 설명, 일괄 작업.
4. 실행 직전에: 역할 이동과 최종 확정의 주의사항.

글자를 줄이거나 모두 아이콘으로 바꾸는 방식은 사용하지 않는다. 자주 쓰는 선택 행동에 추가 클릭을 넣지 않는 것이 우선이다.

## 2. 현재 화면 진단

검토 근거는 현재 main의 구현(`3618570`), 관련 E2E, 직전 검증에서 저장한 30명 명단의 데스크톱·모바일 캡처다. 이번에 운영 데이터를 수정하거나 실제 교사 사용 시간을 측정하지는 않았다. 저장된 캡처는 선택 영역을 잘라 찍은 이미지이므로 페이지 전체의 첫 화면 노출 높이는 새 시안에서 별도로 측정해야 한다.

| 현재 문제 | 사용자에게 생기는 부담 | 수정 방향 |
| --- | --- | --- |
| 페이지 제목·단계·설정 제목·선택 안내·하위 번호가 중첩됨 | 어디부터 해야 하는지 다시 읽게 됨 | 페이지 제목, 짧은 단계 표시, 작업 영역만 남김 |
| 미배정 인원·총 남은 자리·자리 남은 역할 수를 함께 표시 | 학생 수와 역할 수, 자리 수를 계속 구분해야 함 | 평상시에는 미배정 인원만, 전체 자리 부족은 예외 안내 |
| 미배정 학생 이름을 상단 문장과 선택 칸에서 중복 표시 | 긴 이름 목록이 실제 선택 영역을 아래로 밀어냄 | 상단 이름 나열 삭제, 학생 선택 영역에서 확인 |
| 역할마다 배정/정원·남은 자리·안내문·담당자 명단 표시 | 역할 카드가 커지고 역할 탐색이 느려짐 | 역할 이름과 `배정/정원` 중심의 간결한 목록 |
| 체크 표시 옆에 ‘선택됨’, 모든 빈 항목에 ‘미배정’ 반복 | 상태를 읽는 글자가 학생 이름과 경쟁함 | 체크박스로 선택 표시, 예외 상태에만 짧은 배지 |
| 날짜 입력·정원 입력·설명·보조 버튼이 항상 펼쳐짐 | 학생을 고르는 작업보다 설정이 먼저 보임 | 값은 보이되 편집기는 요청할 때 표시 |
| ‘미배정 N명 모두 선택’이 정원보다 인원이 많아 대부분 비활성화됨 | 자주 쓸 수 없는 큰 버튼이 주목을 차지함 | 보조 작업 메뉴로 이동, 적용 범위를 명확히 표시 |
| 모바일에서 전체 역할 목록 다음에 학생 목록 배치 | 역할과 학생 사이를 길게 왕복함 | 모바일 역할 선택기를 압축해 학생 영역 위에 배치 |

원인은 정보의 총량뿐 아니라 **우선순위 없이 동시에 보여 주는 방식**이다. 앞선 ‘검사 통과’는 기능·접근성 회귀 확인이며, 정보량이 적절하거나 실제 교사의 작업이 빠르다는 증거는 아니다.

## 3. 권장 화면 구조 — 배정 2단계

### 데스크톱

```text
← 1인 1역                 학생 역할 배정
① 명단 확인   ② 역할 배정

배정 기간  10.1–10.31  [변경]

역할       배정/정원        칠판 도우미   1/2명  [정원 변경]
──────────────────        학생 찾기 [이름·번호          ]
● 칠판 도우미    1/2       ☑ 1 가상하늘  ☐ 2 가상바다  ☐ 3 가상새봄
  책 깔끔이      2/2       ☐ 4 가상푸름  ☐ 5 가상나래  ☐ 6 가상마루
  학습 나눔이    0/2       …
  전등 지킴이    0/1
  …                       [역할 설명]  [추가 작업]
  [+ 역할 추가]

──────────────────────────────────────────────────────
[이전]         미배정 10명                     [배정 확인]
```

개념 구조도이며 픽셀 단위 시안은 아니다. 예시 이름·기간·인원은 가상이다.

- 공통 머리말의 홍보 문구와 기본 학급명 반복을 상세 화면에서 줄인다. 실제로 구분에 필요한 학급명은 짧게 유지한다.
- 왼쪽은 폭 약 240~280px의 목록, 오른쪽은 학생 선택에 나머지 공간을 사용한다. 큰 역할 카드·겹겹의 테두리·중첩 흰 패널을 줄인다.
- 역할 목록에는 `역할명 + 배정/정원`만 기본 표시한다. 담당 학생 전체 이름은 선택 영역의 체크 상태와 최종 확인에서 보여 준다.
- 현재 역할의 인원은 선택 작업과 바로 붙어 있어야 하므로 오른쪽에도 유지한다. 의미 있는 맥락 반복과 불필요한 설명 반복을 구분한다.
- 학생은 번호순의 작은 선택 타일로 표시한다. 데스크톱 4~5열을 목표로 하되 이름 길이·확대율에 따라 열 수를 줄인다. 학생 수에 맞춰 글자를 축소하지 않는다.
- 선택 영역이 가용 높이 안에 들어올 때만 데스크톱에서 따라오는 배치를 검토한다. 긴 내용이나 확대 상태에서는 일반 문서 흐름으로 돌아간다. 목록별 내부 세로 스크롤은 만들지 않는다.
- 하단에는 미배정 인원과 주 행동 하나를 둔다. 고정 노출을 사용하더라도 마지막 학생·오류·키보드 포커스를 가리지 않게 공간을 확보한다.

### 모바일

전체 역할 목록을 학생 목록 위에 펼치지 않는다.

```text
학생 역할 배정                 2/2
10.1–10.31 [기간 변경]

[칠판 도우미 · 1/2명          ▾]  ← 역할 변경
[정원 변경]      학생 찾기 [      ]

☑ 1 가상하늘       ☐ 2 가상바다
☐ 3 가상새봄       ☐ 4 가상푸름
…

미배정 10명              [배정 확인]
```

- 역할 선택 버튼을 누르면 역할 이름·배정 인원이 있는 선택 대화상자를 연다. 선택 후 닫고 학생 선택 영역으로 복귀한다.
- 학생별 드롭다운으로 돌아가는 것이 아니다. **역할은 한 번 선택하고 학생 여러 명은 계속 탭한다.**
- 360~390px에서는 학생 2열을 기본으로 한다. 작은 터치 영역으로 억지로 3열을 만들지 않는다.
- 역할이 가득 차도 자동으로 다음 역할로 이동하지 않는다. 연속 탭이 다른 역할에 적용되는 실수를 막는다.
- 긴 역할 선택 대화상자만 의도적인 내부 스크롤을 허용한다. 닫기·Esc·포커스 복귀를 제공한다.

## 4. 무엇을 남기고, 어디로 옮길 것인가

| 정보/기능 | 기본 화면 | 필요할 때 |
| --- | --- | --- |
| 배정 기간 | `10.1–10.31 · 변경` | 변경 시 시작일·종료일 입력과 겹침 오류 |
| 역할별 인원 | `1/2` | 선택한 역할에서 정원 변경. 남은 자리가 명확해야 할 때 `1명 더 선택 가능` 표시 |
| 전체 미배정 | 하단 `미배정 10명` | 누르면 첫 미배정 학생으로 이동·강조. 검색 중이면 검색을 해제했다고 안내 |
| 전체 자리 부족 | 정상일 때 숨김 | 실제 부족할 때만 `역할 자리가 2개 부족합니다`와 정원 변경 동선 |
| 역할 설명 | `역할 설명` 보조 버튼 | 눌렀을 때 선택한 역할의 설명만 펼침 |
| 학생 상태 | 번호·이름·체크 표시 | 다른 역할에 속한 학생에게만 해당 역할명 배지 |
| 이전 역할 | 일반 배정에서 없음 | 역할 교체 화면에서 `이전 역할 보기`를 켠 경우만 표시 |
| 역할 추가 | 역할 목록 끝 `+ 역할 추가` | 작은 입력 영역. 다른 페이지로 이동하지 않고 현재 배정 유지 |
| 전체 선택/해제 | `추가 작업` 안으로 이동 | 미배정 모두 선택·현재 역할 선택 해제. 대상 인원과 범위를 표시 |
| 확정 주의사항 | 장문 확인 체크박스 제거 | `배정 확인`을 누른 최종 확인 창에서 표시 |

`추가 작업`의 ‘미배정 모두 선택’은 검색 결과가 아니라 **학급 전체 미배정 학생** 대상임을 메뉴에 명시한다. 전원이 남은 정원 안에 들어갈 때만 허용하며 임의로 일부만 채우지 않는다. 일괄 해제는 대상 수를 확인하고 취소할 수 있게 한다.

## 5. 조작과 문구 규칙

### 자주 하는 작업

- 미배정 학생 선택·해제: 현재처럼 한 번 클릭. 별도 ‘적용’ 버튼을 추가하지 않는다.
- 이름 순서는 선택할 때마다 바꾸지 않는다. 선택된 학생을 갑자기 위로 옮기거나 목록에서 없애지 않는다.
- 검색은 선택 상태와 무관하다. 검색어를 지워도 체크를 유지하며 역할을 바꾸면 검색을 초기화한다.
- 정원 변경은 현재 위치에서 처리한다. 인원보다 작은 정원·0·60 초과·소수 입력은 설명과 함께 거부하고 기존 유효 값을 유지한다.

### 예외와 오류

- 다른 역할 학생을 누르면 그때만 `책 깔끔이 → 칠판 도우미로 옮길까요?`와 `[취소] [옮기기]`를 표시한다. 일상적인 미배정 학생 선택에는 확인을 요구하지 않는다.
- 정원에 도달하면 추가 선택은 막되 기존 선택은 해제할 수 있다. `정원 완료 · 정원 변경`처럼 짧게 안내한다. 사유 없이 학생 전체를 회색 처리하지 않는다.
- 저장 중에는 배정·기간·명단 변경과 중복 제출을 잠근다. 실패 시 선택을 유지하고 다시 시도할 수 있게 한다.
- 짧은 문구로 바꾸더라도 오류 원인과 복구 방법을 함께 제공한다. 필요한 오류를 ‘문제가 발생했습니다’로 축약하지 않는다.

### 최종 확인

하단 버튼은 `배정 확인`으로 바꾸고, 누르면 기간과 `역할 → 담당 학생` 요약을 보여 준다. 기존 2단계를 늘리지 않고 2단계 안에서 마지막 확인만 제공한다.

- 미배정이 있으면 진행 불가 사유를 하단에 보여 주고 해당 학생으로 이동할 수 있게 한다.
- 확인 창에 `확정 후 이 배정은 직접 수정할 수 없습니다.`를 명시한다. 미래 시작일이면 학생 화면 적용일도 표시한다.
- `[돌아가기] [확정하기]`로 마무리한다. 별도 동의 체크박스까지 중복 요구하지 않는다.
- 명단·기간·정원·배정이 바뀌면 확인 내용도 다시 계산한다. 과거 확정 스냅샷을 수정하지 않는다.
- 선택 중에는 ‘자동 저장’이라고 안내하지 않는다. 현재처럼 확정 전 서버 저장은 하지 않으며, 이탈 경고로 미저장 초안 손실을 예방한다.

### 문구 예시

| 현재 | 수정안 |
| --- | --- |
| 역할을 고르고 학생을 여러 명 선택하세요 | 긴 제목 삭제. 필요 시 안내 한 줄: `역할을 고른 뒤 학생을 선택하세요.` |
| 배정 1/2명 · 남은 1자리 | `1/2` — 목록 상단에 `배정/정원` 표기 |
| 담당 학생을 선택하세요 — 역할마다 반복 | 삭제 |
| 1번 가상하늘 / 선택됨 | `☑ 1 가상하늘` |
| 학생 이름 또는 번호 검색 | 보이는 라벨 `학생 찾기`, 입력 예시 `이름·번호` |
| 미배정 학생 10명 + 미배정 이름 나열 | `미배정 10명` |
| 기간과 역할을 확인했습니다… | 최종 확인 창의 짧은 주의문으로 이동 |

## 6. 다른 화면에 적용할 범위

배정 2단계를 먼저 개선하고, 효과를 확인한 뒤 다른 화면에 같은 원칙을 적용한다. 기능과 데이터 의미는 유지한다.

| 화면 | 남길 것 | 간소화할 것 |
| --- | --- | --- |
| 1인 1역 홈 | 위쪽 오늘 현황 + 아래쪽 6개 기능, 현재 메뉴 순서 | 반복되는 기능 분류·홍보 문구. 설명은 버튼 제목만으로 불명확한 메뉴에 한 줄만 |
| 배정 1단계 | 총인원·번호/이름 명단·수정·다음 | 가져오기 안내 한 줄로 통합. 입력 형식·최대 인원은 편집 중에 표시. 수정 저장 시점은 적용 행동 옆에 짧게 유지 |
| 역할 교체 | 이전 배정과 새 기간, 같은 역할별 선택 방식 | 이전 기간 설명 축약, 학생마다 이전 역할을 항상 반복하지 않음 |
| 역할 목록 | 역할명·정원·수정 동선 | 모든 역할의 설명 입력칸을 동시에 펼치지 않고 선택한 역할만 편집. ‘다음 배정부터 적용’ 안내는 유지 |
| 운영 설정 | 실천 요일·공개 상태·이름 공개의 의미 | 예외일 입력·링크 재발급 같은 보조 작업을 분리. 본인 인증 없음·이름 가리기 적용 범위는 관련 설정 옆에 짧게 유지 |
| 오늘의 실천판 | 학생 상태·기록 정정·학생 화면 공유 | ‘하나의 화면, 두 가지 사용 방식’ 장문을 명확한 행동 버튼으로 전환. 공유 주소는 복사 동작 중심으로 정리 |
| 실천 기록 | 선택한 월·학생별 기록·상세 진입 | ‘누르면 볼 수 있다’는 반복 안내 축소. 미기록/미실천/해당 없음의 구분은 유지 |

학생 공용 화면은 이번 우선 수정 대상이 아니다. 개인정보·공개 범위·링크 폐기 관련 경고와 QR 이미지 저장 기능은 간소화 명목으로 제거하지 않는다.

아래는 실제 인터뷰 결과가 아니라 설계 가설과 반대 의견을 점검한 모의 검토다.

| 관점 | 우려 | 계획에 반영 |
| --- | --- | --- |
| 김서연·5학년 | 설명을 접어도 처음 쓰는 사람이 선택 방법을 알아야 함 | 보이는 체크박스와 필요 시 한 줄 안내. 튜토리얼 강제 없음 |
| 박준호·5학년 | 다른 역할 학생을 실수로 빼오면 안 됨 | 현재 역할 배지 + 이동할 때만 짧은 확인 |

| 정민재·6학년 | 텍스트를 없애다 누가 빠졌는지 모르게 될 수 있음 | 미배정 인원과 해당 학생으로 이동하는 기능 유지 |

## 8. 구현 순서와 완료 기준

### P1 — 배정 화면 집중 개선

1. 현재 기준 화면을 30명·18역할, 60명·다수 역할 조건으로 전체 화면 캡처한다.
2. 제목/설명/통계 중복을 제거하고 기간 표시·역할 목록·학생 선택 영역을 재배치한다.
3. 정원·설명·보조 작업의 펼침 동작, 모바일 역할 선택기, 마지막 확인 창을 구현한다.
4. 기존 배정 로직과 접근성을 회귀 검사한다. 목표를 만족한 뒤 다음 범위로 진행한다.

### P2 — 주변 화면 정돈

홈·명단 확인·교체의 반복 문구부터 정리한다. 역할 목록의 편집 방식과 운영 설정 재배치는 별도 변경으로 나눠 검증한다. 사용 빈도 근거 없이 모든 보조 기능을 한 메뉴에 몰아넣지 않는다.

### 측정 가능한 인수 기준

아래는 제안 목표이며 아직 달성 결과가 아니다.

- 1366×768, 기본 글자 크기에서 2단계 진입 즉시 첫 역할과 첫 학생 행이 보인다. 학생 선택 전에 페이지를 내리지 않는다.
- 390×844 모바일에서도 초기 학생 선택 영역이 첫 화면에 보인다. 전체 역할 목록이 앞을 차지하지 않는다.
- 평상시 작업 영역의 조작 설명은 최대 한 문장으로 제한한다. 사용자 이름·역할명·필수 라벨·오류·확정 경고는 이 제한에서 제외한다.
- 같은 30명·18역할·미배정 상태에서 고정 안내 문구의 글자 수를 기존 대비 50% 이상 줄이는 것을 목표로 한다. 숨긴 기능을 찾는 시간이 늘면 수치 달성보다 발견성을 우선한다.
- 역할 선택 뒤 학생 N명을 배정하는 데 N번의 선택으로 충분하다. 드래그·학생별 드롭다운·매번 적용 버튼을 요구하지 않는다.
- 선택 후 타일 위치가 바뀌지 않고, 정원 도달로 자동 역할 전환이 일어나지 않는다.
- 200% 확대·긴 이름·동명이인·0/30/60명·빈 역할·정원 부족에서도 가로 잘림과 하단 버튼 겹침이 없다. 문서가 세로 스크롤을 맡는다.
- 클릭 영역은 제품 목표로 최소 44×44 CSS px를 확보한다. 색상만으로 상태를 구분하지 않고 번호·이름·체크 상태를 보조기술에도 제공한다.
- 검색·이전 단계·취소·기간 변경·서버 오류에서도 배정 초안을 잃지 않는다. 과거 기록·최종 저장 형식·공개 권한은 동일하다.

실사용 평가가 가능하면 5·6학년 담임에게 같은 배정 과제를 기존/새 화면 순서를 바꾸어 수행하도록 요청한다. 완료 시간, 불필요한 스크롤 왕복, 정원·이동 오류, 추가 도움 요청을 비교한다. 가상 페르소나 의견이나 자동 테스트를 실제 사용성 개선의 증거로 대체하지 않는다.

### 구현 시 확인할 파일과 검사

- `src/features/classroomRoles/RoleAssignmentPage.tsx`: 기간·요약·확정 흐름.
- `src/features/classroomRoles/RoleStudentPicker.tsx`: 역할 목록·학생 선택·모바일 구조.
- `src/features/classroomRoles/ClassroomRolesWorkspace.tsx`: 상세 화면 머리말 간소화.
- `roleAssignmentDraft.ts`의 단일 학생→역할 매핑과 서버 검증은 재사용한다. DB 변경은 계획하지 않는다.
- 타입 검사·린트·관련 단위 검사와 `classroom-roles.spec.ts`, `class-roster-import.spec.ts`, `app-shell-scroll.spec.ts`를 실행한다. 확정 창·이동 확인·검색·키보드 포커스 검사를 추가한다.
- 새 대화상자의 포커스 가두기/복귀, Esc, 보이는 라벨, 오류 읽기, axe 검사를 수행한다. 보조 설명을 숨겨도 입력 라벨은 숨기지 않는다.
- 배포가 승인된 구현 단계에서 가상 자료로 운영 UI→저장→학생 제출→교사 확인을 다시 검증한다.

## 9. 판단 근거와 이번 작업의 한계

- 핵심 작업은 바로 보이고 드물게 쓰는 기능은 요청 시 보이게 하는 원칙을 적용했다. 역할 선택을 학생 선택과 다른 페이지로 나누지는 않는다. [Nielsen Norman Group: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)
- 설명을 줄이되 입력에 필요한 라벨·단서는 유지한다. 과도한 설명도 과소한 설명만큼 입력을 방해할 수 있다는 지침을 참고했다. [W3C: Labels or Instructions](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)
- 대부분의 사용자가 필요한 정보는 접힌 영역에 숨기지 않는다. 정원·미배정·오류·확정 결과를 남긴 이유다. [GOV.UK Design System: Details](https://design-system.service.gov.uk/components/details/)

구체적인 레이아웃·문구·수치 목표는 위 원칙과 현재 구현을 바탕으로 한 설계 제안이며, 출처가 이 제품의 개선 효과를 입증하는 것은 아니다.

저장소가 참조하는 `pro/ux-ui-expert.md`와 외부 개발 일지는 현재 checkout에 없어 사용하지 않았다. 계획을 처음 작성할 때는 앱 코드·배포를 변경하지 않았다. 이후 사용자의 구현 요청에 따라 아래 P1 작업을 진행했다.

## 10. P1 구현 기록

- 배정 2단계의 긴 통계·명단 반복을 없애고 기간 요약, 역할 목록, 학생 선택, 하단 미배정 인원 순으로 재배치했다.
- 모바일에서 역할 목록을 선택 대화상자로 옮겼다. 역할별 다중 선택, 정원 변경, 역할 이동 확인, 마지막 배정 확인은 유지했다.
- 공통 상세 화면 머리말과 홈 기능 타일의 중복 문구를 줄였다. 교사의 실제 데이터를 쓰거나 기능별 저장 규칙을 변경하지 않았다.
- 390×844와 1366×768에서 첫 학생 선택 항목의 초기 노출을 확인했다. 데모 E2E에서 키보드·axe 접근성, 저장·공용 제출·기록 흐름을 검증했다.
- P2 중 역할 목록의 단일 선택 편집 방식과 운영 설정·실천판 재배치는 별도 변경으로 남긴다. 실제 담임 사용성 평가는 아직 수행하지 않았다.
