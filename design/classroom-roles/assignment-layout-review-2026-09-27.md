# 학생 역할 배정 2단계 전체 레이아웃 검토 (codex)

2026-09-27. `pro/`의 웹·UX·UI 디자이너 프로파일에 따른 AI 내부 검토이며, 실제 디자이너나 교사 인터뷰가 아니다. 가상 명단만 사용한다.

## 구현 전

| 관점 | 판정과 근거 | 변경 방향 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자이너 | 수정 필요. 좌우 패널의 제목 시작 높이와 하단이 다르며, 340px 왼쪽 패널의 2열 역할 버튼은 화면 여유와 달리 좁다. 대부분의 정보가 14px로 보인다. | 같은 외곽 프레임과 헤더 정렬을 사용한다. 태블릿에서는 역할 목록을 위쪽 전체 폭에 놓고, 넓은 화면에서만 좌우 배치한다. 중요도에 맞게 글자 크기·굵기·여백을 구분한다. | 긴 역할명·적은 학생 수에서 한쪽에 빈 공간이 생길 수 있다. |
| UX 디자이너 | 수정 필요. `역할 설명`과 `추가 작업`의 뜻이 불분명하다. 정원 1~2명 역할에서 일괄 선택은 흔히 비활성이다. | 역할 설명은 선택한 역할 아래 직접 보여 주고, 자주 쓰지 않는 일괄 작업 메뉴를 주 흐름에서 제거한다. 여러 학생을 개별 체크하는 기존 흐름은 유지한다. | 일괄 선택을 사용하던 일부 사용자는 개별 체크가 필요하다. |
| UI 디자이너 | 수정 필요. 선택 역할은 색만 바뀌고, 모바일은 `정원 변경`이 오른쪽 패널 상단에 홀로 남는다. 패널·카드의 좁은 폭과 글자 확대를 다시 확인해야 한다. | 선택 카드의 테두리·배경·굵기를 강화하고, 모바일에도 선택 역할 제목을 표시한다. 카드 열 수는 화면·글자 폭에 따라 바뀌게 한다. | 실제 기기·고대비 모드·사용자 테스트는 별도 확인이 필요하다. |

## 구현 후

| 관점 | 판정과 근거 | 남은 위험 |
| --- | --- | --- |
| 웹디자이너 | 조건부 통과. 23명·18역할의 데스크톱 전체 화면에서 두 제목의 상단 좌표 차이 2px 이하, 두 패널 하단 차이 1px 이하를 검사했다. 역할 변경·정원 완료 상태에서도 한 외곽 프레임을 공유한다. 1024px에서는 역할 목록을 전체 폭 위쪽에, 390px에서는 역할 선택창을 사용한다. 3명·60명·60역할의 전체 화면도 확인했다. | 역할명과 설명이 매우 길면 화면 전체 높이는 늘어난다. 실제 교실 기기에서의 체감 밀도는 확인하지 못했다. |
| UX 디자이너 | 조건부 통과. 선택 역할은 파란 배경·두꺼운 테두리·굵은 글자로 구분한다. 역할 설명은 역할 제목 아래에 바로 보인다. 용도가 불분명했던 `역할 설명`·`추가 작업` 메뉴를 제거했고, 여러 학생 체크·해제·이동·정원 변경 흐름은 유지했다. | `추가 작업`의 일괄 선택·전체 해제를 쓰던 사용자는 이제 학생을 개별 체크해야 한다. 실제 교사의 수행 시간은 측정하지 않았다. |
| UI 디자이너 | 조건부 통과. 패널 제목은 18~20px, 카드 이름은 16px, 상태·정원은 14px로 계층을 분리했다. 모바일의 중복 역할명을 제거했고, 체크·검색·대화상자 포커스 및 대상 영역 axe 검사를 포함한 E2E를 확인했다. 320px와 글자 확대에서도 가로 넘침을 검사했다. | 고대비 모드와 실기기 확대·터치의 현장 검증은 남았다. |

가상 데이터 검증 대상: 학생 3·23·30·60명, 역할 0·18·60개, 긴 역할명과 학생명, 정원 0/2·2/2, 현재/다른 역할/미배정 상태. 화면에 맞지 않는 두 데이터 영역을 억지로 같은 높이로 늘리지 않도록, 데스크톱 좌우 배치는 예상 행 수가 비슷할 때만 사용하고 그 밖은 상하 배치한다. 전체 화면 캡처는 `tests/e2e/classroom-roles.spec.ts`의 Playwright 출력에 남긴다. 자동 검사와 AI 프로파일 검토는 실제 디자이너·교사 승인으로 간주하지 않는다.

검증: `npm run typecheck` 통과, `npm run lint` 통과(기존 경고 6건), `npm test -- tests/unit/roleAssignmentDraft.test.ts` 7건 통과, `npm run test:e2e -- tests/e2e/classroom-roles.spec.ts` 17건 통과, 1인 1역 관련 앱 스크롤 E2E 7건 통과, `npm run build` 통과(기존 번들 크기 경고). 원격 Supabase 연동 검사는 수행하지 않았으며, 해당 스모크 테스트의 레이아웃 기대값은 새 상하 배치에 맞게 갱신하고 `node --check`만 확인했다.
