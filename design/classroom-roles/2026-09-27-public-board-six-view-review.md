# 학생 실천판 1차→2차 모의 디자인 검토 (2026-09-27)

이 문서는 AI가 여섯 전문가 관점을 **모의** 적용한 기록이다. 실제 전문가 6명이나 학생·교사의 인터뷰, 승인, 사용성 시험을 받았다는 뜻이 아니다.

## 1차 구현과 증거

- 공용 화면을 PC 5열, 모바일 2열 타일로 확장하고 역할·번호·이름·공개 허용된 오늘 상태를 담았다.
- 역할 설명, 반복 안내, 긴 푸터를 제거했다. 비실천일에 기존 기록을 동시에 말하는 상세 문장은 숨겼다.
- 23명(완료·미실천·미기록 혼합, 긴 이름 포함)의 [PC 전체](public-board-review/first-desktop.png), [모바일 전체](public-board-review/first-mobile.png), [모바일 상세 전체](public-board-review/first-detail-mobile.png)를 실제 브라우저에서 캡처했다.
- 이 단계는 2차 설계의 평가 대상이며 최종안이 아니다.

## 여섯 관점의 1차 평가

| 모의 관점 | 판정 | 화면에서 확인한 근거 | 2차 수정 |
| --- | --- | --- | --- |
| 웹디자인 · 정보 위계 | 수정 필요 | PC 5열은 균형이 좋지만 역할명·상태가 전자칠판 거리에서 작다. | 역할과 오늘 상태의 크기·대비를 올린다. |
| 웹디자인 · 공간 밀도 | 수정 필요 | 학생 선택 시 23명 명단이 사라지고 한 카드 아래에 넓은 공백이 남는다. | 명단을 유지한 채 상세를 대화상자로 연다. |
| UX · 학생 기록 흐름 | 수정 필요 | 저장하면 명단으로 돌아가 기록을 바꾸려면 학생을 다시 찾아야 한다. | 저장 뒤 선택 학생을 유지하고 즉시 상태를 갱신한다. |
| UX · 전자칠판 흐름 | 수정 필요 | 학생 입력과 읽기 전용 전자칠판의 타일 밀도는 비슷해졌으나 상태·선택 동작이 서로 다르게 보인다. | 동일 타일 구조를 쓰고 읽기 전용에서만 선택을 막는다. |
| UI · 접근성 | 수정 필요 | 타일의 접근 가능한 이름은 번호·이름뿐이라 역할과 공개 상태가 읽히지 않고, 상세는 키보드 닫기·복귀가 불명확하다. | 타일 이름/설명, Esc, 초점 복귀를 명시한다. |
| UI · 반응형/상태 | 수정 필요 | 390px 2열과 긴 이름은 잘 버티지만, 비실천일에 과거 기록이 남은 경우 타일과 상세의 의미가 어긋날 수 있다. | 비실천일을 우선 표시하고 같은 상태 규칙을 양쪽에 쓴다. |

## 2차 구현과 재평가

- 학생용 타일은 역할을 첫 줄에, 번호·이름과 오늘 상태를 아래에 표시한다. 활동 설명과 반복 안내는 제거했다. 오늘 상태 공개 설정을 끄면 타일에서는 상태를 감춘다.
- 타일을 누르면 명단 위에 작은 상세창이 뜬다. 주간 O/X, 오늘 상태, 기록 버튼만 남기고, 저장 뒤에도 창을 유지해 수정할 수 있다. Esc나 닫기 후 원래 타일로 초점이 돌아간다.
- 전자칠판은 같은 타일 정보 구조를 읽기 전용으로 사용한다. 1920px에서는 화면 폭 전체와 더 큰 글자·타일을 사용한다. 이름 가림·상태 공개 설정은 그대로 따른다.
- 빈 명단, 미래 날짜, 비실천일에 기존 기록이 있는 경우를 각각 분명한 상태로 처리했다.

| 모의 관점 | 2차 판단과 근거 | 남은 위험 |
| --- | --- | --- |
| 웹디자인 · 정보 위계 | 역할→학생→상태 순서가 PC·모바일·전자칠판에서 같다. 완료/미완료/미기록의 색과 텍스트를 함께 쓴다. | 실제 교실 뒷자리의 가독성은 현장 검증이 필요하다. |
| 웹디자인 · 공간 밀도 | 1366px 23명은 5열, 390px은 2열, 1920px 전자칠판은 6열이다. 상세창은 명단을 가리지 않고 닫으면 제자리로 돌아간다. | 60명은 세로 스크롤이 남는다. |
| UX · 학생 기록 흐름 | 선택→주간 확인→했어요/못했어요→즉시 수정이 한 창 안에서 끝난다. | 공용 기기에서 실제 학생 오선택 빈도는 측정하지 못했다. |
| UX · 전자칠판 흐름 | 동일한 정보의 타일을 입력 모드와 읽기 전용 모드에 재사용한다. 전자칠판에는 기록 버튼이 없다. | 이름 가림과 상태 공개는 교사 설정에 따라 달라진다. |
| UI · 접근성 | 타일의 접근 가능한 설명에 역할·공개 상태를 포함했다. 상세창의 명암 대비, Esc, 초점 복귀를 브라우저와 axe로 확인했다. | 모든 보조기기 조합의 수동 시험은 하지 않았다. |
| UI · 반응형/상태 | 0/1/23/60명, 긴 이름, 200% CSS 확대, 비실천일에 기존 기록이 있는 경우를 확인했다. 가로 오버플로가 없다. | 200% 검사는 브라우저 자체 줌 대신 CSS 확대를 사용했다. |
