# 역할별 학생 다중 선택 전환 (codex)

## 범위와 흐름

학생 한 명마다 역할 드롭다운을 여는 방식을 없애고 `역할 카드 선택 → 담당 학생 여러 명 체크 → 배정 확정`으로 변경한다. 기존 메뉴 순서 수정은 보존한다.

- 1단계: 자동으로 불러온 명단을 총인원과 번호순 표로 확인한다. `명단 수정`을 누를 때만 편집하며 적용/취소를 구분한다. 명단 변경의 서버 저장 시점은 기존처럼 배정 확정 시점이다.
- 2단계: 역할별 배정 인원·정원·담당 학생을 카드에 표시한다. 선택한 역할의 학생들은 체크박스로 다중 선택한다. 이름/번호 검색과 미배정 학생 일괄 선택, 선택 해제를 제공한다.
- 다른 역할에 배정된 학생을 선택하면 기존 역할에서 이동한다는 설명을 먼저 제공한다. 한 학생에게 한 역할만 남으며 정원 초과는 일부 저장 없이 거부한다.
- 이미 선택한 인원 미만으로 정원을 낮추지 못하게 한다. 명단·정원·배정이 바뀌면 최종 확인을 해제한다. 이전 단계 왕복과 수정 취소는 현재 배정을 유지한다.
- 교체 화면에는 이전 역할을 표시한다. 확정된 과거 스냅샷과 기록은 바꾸지 않는다.
- 기존 학생 ID → 역할 ID 저장 형식과 서버 검증을 유지한다. DB, Edge Function, 공개 권한 정책을 바꾸지 않는다.

## 가상 담임 6명의 단계별 모의 검토

실제 인터뷰 또는 외부 코드 리뷰가 아닌 설계 가설 점검이다. 구현·검증은 개발 에이전트가 수행했다.

| 가상 담임 | 설계 의견 | 구현 검토·반영 | 인수 확인 |
| --- | --- | --- | --- |
| 김서연(5학년) | 역할 하나에 학생을 연속으로 선택할 수 있어야 한다 | 큰 체크 영역과 다중 선택, 학생 이름/번호 검색 | 여러 명 선택 및 모바일 키보드 조작 검사 |
| 박준호(5학년) | 다른 역할로 옮길 때 두 역할에 남으면 안 된다 | 기존 역할에서 이동한다는 안내, 단일 매핑 유지 | 이동 후 두 카드의 인원·최종 저장 내용 검사 |
| 이하은(5학년) | 역할 인원을 같은 자리에서 늘릴 수 있어야 한다 | 선택판 정원 조정, 정원 초과 및 부적절한 감소 차단 | 정원 증가·초과 선택 방지·감소 오류 검사 |
| 정민재(6학년) | 미배정 학생과 역할 교체 전 담당을 볼 수 있어야 한다 | 미배정 인원/이름 및 이전 역할 표시 | 누락 시 확정 차단·교체 화면·과거 기록 보존 회귀 검사 |
| 최지윤(6학년) | 가져온 명단을 실수로 바꾸거나 선택을 잃으면 안 된다 | 확인용 표와 명시적 편집/취소, 단계 왕복 시 초안 보존 | 수정 취소·학생 제외·단계 왕복·기존 식별자 유지 검사 |
| 한도현(6학년) | 화면을 계속 길게 내려가며 드롭다운을 열지 않아야 한다 | 역할/학생 선택판 분리, 넓은 화면 학생 3열·모바일 2열 | 30명 화면 캡처·가로 넘침·기능 이동·문서 스크롤 검사 |

## 코드 리뷰

React 검토 지침에 따라 배정 상태는 부모의 단일 매핑만 사용하고 인원·남은 자리·현재 역할은 그 값에서 계산한다. 다중 선택 변환은 순수 함수로 분리해 원본 변경, 정원 초과의 부분 적용, 다른 역할 선택 해제 등 회귀를 검사했다.

확인 표와 편집 화면 사이 포커스를 이동하고, 모바일에서 역할을 고르면 학생 선택판으로 이동할 수 있게 했다. 체크박스는 번호와 이름으로 구분한다. 새 역할 선택판에 대한 axe 검사 위반은 0건이다.

## 구현 완료 시점의 검증과 반영 범위

- `npm run typecheck`, `npm run lint` 통과. 기존 코드 린트 경고 6건 유지.
- 전체 단위 테스트 50파일/422개 통과(현재 작업 폴더의 기존 사용자 미커밋 검사 포함). 신규 다중 선택 순수 함수 검사 7개 포함.
- 관련 Chrome E2E 32개: 1인 1역 12개, 명단 가져오기 5개, 셸 스크롤 15개 통과. 데모 저장 경로이며 운영 Supabase 연동 검사로 간주하지 않는다.
- `npm run build` 통과. 기존 500 kB 초과 청크 경고 유지.
- 원격 스모크 스크립트의 선택자를 새 UI에 맞췄으나, 이번 작업에서 원격 계정 생성·서버 검사·운영 배포는 수행하지 않았다.
- 구현 완료 시점에는 이전 메뉴 순서 변경과 함께 로컬 `codex/classroom-roles-menu-order` 브랜치에서 검증했다. 무관한 README·영수증·가정통신문 변경은 보존했다. 이후 배포 요청의 커밋·병합·운영 검증 결과는 해당 GitHub PR에 기록한다.
- 외부 개발 일지와 UX 전문가 문서는 이 checkout에 없어 사용하지 않았다.
