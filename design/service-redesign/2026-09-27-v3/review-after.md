## 상호작용 설계 조건

이 조건은 그림의 행동을 구체화하기 위한 제안이며 구현 완료를 뜻하지 않는다.

- 후보 행 전체가 추가 조작의 대상이며 +도 같은 동작을 한다. 작은 +만 눌러야 하는 화면으로 구현하지 않는다.
- 담당자 제거는 기존 배정 해제와 같은 의미다. 후보와 필터를 바꾸어도 배정 상태는 유지한다.
- 기본 후보는 미배정 학생이다. 필터의 전체 학생을 선택하면 이미 다른 역할에 배정된 학생과 현재 역할도 확인할 수 있어야 한다. 다른 역할에서 이동할 때 기존 확인·취소 규칙을 유지한다.
- 정원 초과 방지와 최종 확인 조건을 유지한다. 이유는 필요한 조작·포커스·오류 시점에 제공하고, 기본 화면에 반복 안내로 두지 않는다.
- 역할을 완료했을 때 선택 중인 역할의 맥락이 갑자기 사라지면 안 된다. 담당자 변경 즉시 자동 이동하지 않고 현재 상세·선택을 유지한 채 다음 역할을 사용자가 고른다. 그룹 재배치는 선택 해제 또는 화면 재진입 시 정리하는 방안을 검증한다.
- 0명·미배정 후보 0명·정원 완료 상태는 별도 빈 상태가 필요하다. 모든 완료 역할을 같은 화면에서 편집할 수 있는 경로를 유지한다.
- 기본은 문서 하나의 세로 스크롤이다. 빈 공간을 줄인다는 이유로 역할·학생 각각에 세로 스크롤을 추가하지 않는다.

## 데이터 의미 확인

가상 학급은 기존과 같은 24명, 역할 정원 합계 24자리다. 완료 역할 8개는 각2명, 진행 중4개는 각1명이며 총20명이 배정돼 있다. 이 수치는 검토 기록에만 두고 화면의 중복 통계로 다시 노출하지 않았다.

선택 역할 도서 정리에는 17번 송도윤 한 명이 있다. 후보는 21 백지호, 22 남아린, 23 노하준, 24 전소윤이다. 후보를 추가하는 작업과 현재 담당자 제거가 시각적으로 분리된다.

## 실행한 검사와 한계

최종 전체 이미지에서 위 중복 문구의 부재, 네 정원 표기, 8개 완료 역할, 담당자·후보 이름과 번호를 확인했다. PNG 디코딩·파일 크기·문서 링크·홈 및 모바일 SHA-256 해시를 확인했다. 홈과 모바일 해시는 작업 전후 동일했다.

실제 앱 코드를 수정하지 않아 npm 타입 검사·단위 테스트·E2E·빌드·원격 연동 검사는 실행하지 않았다. 이전 시안과 사용자 코드 변경을 보존했다. 실제 교사 시험·아이트래킹·A/B 테스트도 수행하지 않았다.
