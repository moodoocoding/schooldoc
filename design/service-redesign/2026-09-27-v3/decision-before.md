# PC 역할 배정 3차 — 제작 전 설계

## 사용자 범위

홈의 현재 스타일과 승인된 모바일을 유지한다. 수정 대상은 PC 학생 역할 배정 시안이다. 실제 앱 구현·배포를 요청받은 것은 아니므로 이미지와 설계 근거만 새 폴더에 만든다.

## 이전 실패의 원인

진행률, 전체 배정 인원, 미배정 인원, 역할별 정원, 남은 자리, 하단 안내가 같은 상태를 여러 번 설명했다. 색과 테두리를 줄이는 것으로 이 정보 구조의 중복을 해결하지 못했다.

## 이번 화면의 질문

1. 지금 어느 역할을 배정하는가?
2. 이미 누가 맡고 있는가?
3. 누구를 추가할 수 있는가?

화면의 가장 강한 영역을 선택 역할·현재 담당자·추가 후보에 준다. 다른 역할은 작은 탐색 영역으로 둔다. 전역 업무 메뉴는 작업 화면에서 물리고 복귀 링크를 남긴다.

## 정보 배치 규칙

| 정보 | 처리 |
| --- | --- |
| 현재 역할 | 상세 영역 제목으로 강조. 왼쪽 선택 표시는 탐색 맥락이다. |
| 현재 담당자 | 역할 제목 바로 아래. 제거 행동을 가까이 둔다. |
| 추가할 학생 | 기본은 미배정 후보만 표시. 검색과 필터로 전체 학생에도 접근한다. |
| 역할별 빈자리 | 배정 중인 역할 행에 1/2만 표시. 추가 문장·숫자로 재서술하지 않는다. |
| 완료한 역할 | 별도 의미 그룹으로 낮은 위계에 배치. 매 행마다 완료·2/2를 되풀이하지 않는다. |
| 전체 배정 숫자·진행 막대 | 제거 |
| 미배정 인원·다음 단계 안내 | 제거 |
| 필터 카운터·반복 상태 배지 | 제거 |
| 도움말·예외 메시지 | 필요한 조작·실패 때만 노출. 기본 이미지에 상시 설명을 넣지 않는다. |

'정보는 무조건 한 번만'이라는 보편 법칙을 주장하지 않는다. 검색·확인을 돕는 역할명, 객체 이름, 그룹 라벨은 남기고, 같은 상태의 통계·설명 반복을 제거한다. 색+체크처럼 접근성을 돕는 다중 표현은 유지한다.

## 모의 전문가 사전 검토

- 웹디자인 — 수정 필요: 선택한 역할의 상세 영역을 주 시선으로 만들고, 탐색·본문·조작의 크기와 배경을 구별한다. 큰 글씨만으로 위계를 해결하지 않는다.
- UX — 수정 필요: 미배정 후보를 우선하되 전체 학생을 숨겨 재배정이 막히지 않도록 필터를 제공한다. 현재 담당자를 항상 가까이 표시한다. 필터와 검색을 바꿔도 기존 배정을 유지한다.
- UI — 수정 필요: 숫자 카운터를 없애도 실제 선택·제거·추가 조작이 보이게 한다. 기존 정원 제한·다른 역할 이동 확인·최종 확인 조건을 유지한다.

AI가 pro의 세 프로파일을 적용한 모의 검토다. 실제 교사 실험이나 전문가 승인으로 표현하지 않는다.
