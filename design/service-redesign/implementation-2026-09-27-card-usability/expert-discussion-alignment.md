# PC 역할 배정 화면 정렬·보조 동작 검토 (codex)

2026-09-27. [웹디자이너](../../../pro/web-designer.md), [UX 디자이너](../../../pro/ux-designer.md), [UI 디자이너](../../../pro/ui-designer.md) 프로파일을 적용한 **AI 모의 전문가 토의**다. 실제 전문가 인터뷰·회의나 교사 사용성 시험이 아니다.

## 구현 전 토의

| 관점 | 판단 | 근거 |
| --- | --- | --- |
| 웹디자인 | 수정 필요 | 왼쪽 `역할 선택`과 오른쪽 역할명의 크기·상단 위치가 다르고, 역할 설명 때문에 오른쪽 학생 선택 영역의 시작점이 내려간다. |
| UX | 수정 필요 | 배정 단계에서 역할 설명을 반복 확인할 필요는 낮다. 명단 오류를 뒤늦게 발견할 때 수정 경로는 필요하지만, 역할 목록 아래의 `명단 수정`은 역할 자체를 바꾸는 기능처럼 보인다. |
| UI | 수정 필요 | 두 열의 동등한 제목에 같은 글자 크기·행 높이·구분선을 적용해야 한다. 긴 역할명에서도 제목 시작점은 같고 줄바꿈만 자연스러워야 한다. |

**합의:** PC 배정 화면에서 역할 설명 펼침을 제거한다. 설명 데이터와 역할 목록 관리 화면은 유지한다. `명단 수정`은 PC 상단의 배정 전체 동작으로 이동하고, 명단 확인 단계로 돌아가는 기존 기능을 유지한다. 두 열에 동일한 제목 클래스와 패딩·헤더 높이·아래 구분선을 사용한다. 모바일 흐름은 변경하지 않는다.

## 구현 후 검토

| 관점 | 결과 | 확인 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 조건부 통과 | [1584px](role-assignment-desktop.png)·[1024px](role-assignment-1024.png) 전체 캡처에서 두 제목의 시작과 하단 선이 맞는다. 같은 글자 크기·굵기를 계산된 스타일과 두 헤더의 좌표로 검사했다. | 40자 역할명은 여러 줄로 늘어나므로 헤더의 끝선은 해당 행만 커진다. |
| UX | 조건부 통과 | 역할 설명을 배정 화면에서 제거해 학생 선택이 위로 올라왔다. 명단 수정은 상단에 남겨 명단 확인으로 돌아가고 초안 배정이 유지되는 브라우저 과제를 통과했다. | 실제 교사가 수정 경로를 얼마나 쉽게 찾는지는 확인하지 못했다. |
| UI | 조건부 통과 | 제목의 글자 크기·굵기 동일, 헤더 위·아래 좌표 차이 1px 이하, 키보드 포커스 복귀, axe 검사와 야간 테마·큰 글자를 확인했다. | 실제 스크린리더와 브라우저 200% 확대의 수동 검토는 남아 있다. |

`npm run typecheck`, `npm run lint`, `npm run build`, 관련 단위 테스트 28건, Chrome 데모 E2E 40건이 통과했다. 린트에는 이번 변경과 무관한 경고 6건, 빌드에는 기존 큰 번들 경고가 있다. 390px 모바일 전체 캡처의 SHA-256은 이전 구현 캡처와 동일하다. 운영 배포·실제 교사 시험 결과는 아직 아니다.
