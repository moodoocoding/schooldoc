# 모바일 역할 배정 UX 개선 (codex)

2026-09-27. [웹디자이너](../../../pro/web-designer.md), [UX 디자이너](../../../pro/ux-designer.md), [UI 디자이너](../../../pro/ui-designer.md) 프로파일을 적용한 **AI 모의 검토**다. 실제 전문가 회의나 교사 사용성 시험은 아니다.

## 구현 전 판단

| 관점 | 판단 | 근거 |
| --- | --- | --- |
| 웹디자인 | 수정 필요 | 30명 명단 확인 화면은 다음 버튼까지 약 30행을 스크롤해야 했다. 배정 화면도 학생마다 노란 카드와 `미배정` 문구가 반복되어 한 화면에서 비교할 수 있는 학생이 적었다. |
| UX | 수정 필요 | 역할을 바꾸려면 목록 대화상자를 매번 열었고, 정원을 채운 뒤에도 전체 30명 목록이 남았다. 최종 확인은 긴 목록 맨 아래에 있어 현재 역할과 다음 행동을 놓치기 쉬웠다. |
| UI | 수정 필요 | 역할 전환·배정 확인이 스크롤 위치에 따라 사라졌다. 선택·다른 역할 담당·미배정 상태는 구분하되 모든 학생에게 같은 상태 문구를 반복할 필요는 없었다. |

**결정:** 명단은 모바일에서 처음 다섯 명만 보여 주고 전체 보기로 확장한다. 다음 단계 버튼은 실제 동작에 맞게 `다음: 역할 배정`으로 부른다. 배정 단계는 현재 역할 선택과 다음 역할 이동을 상단에, 이전·남은 학생·배정 확인을 하단에 유지한다. 학생은 두 열에서 고르고 기본 범위에는 미배정 학생과 현재 역할 담당자만 남긴다. 검색과 `전체 학생`은 다른 역할 담당자를 찾아 확인 후 이동하는 경로로 둔다. 정원을 채우면 현재 담당자만 남기고, 남은 학생 동작으로 빈자리가 있는 역할과 첫 미배정 학생에 바로 간다. 저장 규칙·데스크톱 배치·홈은 바꾸지 않는다.

## 구현 후 검토

| 관점 | 결과 | 근거 | 남은 위험 |
| --- | --- | --- | --- |
| 웹디자인 | 조건부 통과 | [명단 확인](roster-mobile.png)은 다섯 명과 다음 버튼이 첫 화면에 보인다. [30명 배정 화면](assignment-mobile.png)은 학생을 두 열로 보여 주고, [완료 상태](assignment-complete-mobile.png)는 현재 담당자와 활성 확인 버튼을 구분한다. [긴 역할명](assignment-long-role-mobile.png)도 가로로 넘치지 않는다. | 60개 역할을 선택하는 대화상자는 여전히 길게 스크롤해야 한다. |
| UX | 조건부 통과 | 브라우저 과제에서 명단 확장·접기, 연속 선택, 정원 도달 후 다음 역할/미배정 학생 이동, 다른 역할 담당자의 이동 확인·취소, 빈 명단에서 역할 추가, 최종 확인·저장을 수행했다. | 실제 교사가 대량 배정을 얼마나 빨리 마치는지는 측정하지 못했다. |
| UI | 조건부 통과 | 역할 선택·하단 확인은 스크롤 중에도 접근 가능하다. 320px·390px·768px에서 가로 넘침이 없고, [CSS 200% 확대](zoom-200-mobile.png)에서는 동작 바를 두 줄·학생 카드를 한 열로 재배치했다. [야간 테마](assignment-midnight-mobile.png)의 선택 카드도 배경·체크로 구분된다. 자동 axe 검사와 키보드 포커스 복귀를 확인했다. | 실제 휴대전화 가상 키보드와 스크린리더 수동 검사는 남아 있다. |

검증은 로컬 데모 데이터로 했다. 원격 Supabase의 교사 계정·실제 학생 자료를 사용하지 않았다.
